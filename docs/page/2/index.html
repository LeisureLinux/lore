    译介 Phoronix 报道（Michael Larabel，2026-09-21）：GNU Wget2 2.3 是 2026 年首个新版本。用户可见变化：新增 --progress=dot（文本点状进度，替代默认温度计条）；改进构建系统与配置流程、打磨文档；增强 OS/2 支持（移植 ANSI 转义码、动态加载、类 DOS 路径、正确导出符号）；修复不同参数处理、文件名过长截断、iframe srcdoc 支持、几处内存泄漏。解读提醒：Wget2 是 GNU 现代重写（GitLab 托管），与 classic wget 1.x 两条线；多数发行版默认仍是 1.x、Wget2 以 wget2 命令/可选包独立存在；内存泄漏在批量递归抓取场景会缓慢涨内存，长文件名截断是跨文件系统（ext4 255B/eCryptfs/NTFS）老问题。

    CPO 的下一站，可能是一块玻璃：共封装光学走向「玻璃集成平台」
    译介 SemiWiki 报道（Moh Kolb，2026-09-21）：共封装光学（CPO）被视为「距离问题」——把光引擎挪近交换 ASIC/XPU 以缩短电通道、压低 SerDes 功耗、抬升带宽密度，但贴近不消灭物理瓶颈（只换坐标游移）。核心命题：封装不再只是支撑系统，而是定义能造出什么系统；CPO 把基板抬到战略地位。玻璃作为集成平台的优势：尺寸稳定性好、低损耗高频电布线、光滑表面承载细 RDL、CTE 可定制、可做大得多的集成尺寸（不受硅中介层晶圆尺寸/经济性约束）；光学对几何极敏感，尺寸稳定成为架构能力。更进一步：玻璃基板可能同时参与电集成与光集成（TGV 垂直互连+基板内光学结构），成为「集成平面」。关键闸门 TGV（玻璃通孔）制造难在孔形/损伤/金属化/铜填充/界面附着/残余应力/开裂/长期可靠性；玻璃不是散热材料（热路径须刻意设计）；生态（材料/设备/TGV/细 RDL/KGD/检测/多源供应）比首次演示更重要。关联长鑫 3D NAND、华为 122TB SSD 板级封装的「以封装破制程/基板逆向」叙事。

    Gzip 1.15 发布：修了几个「自诞生起就存在」的 bug，其中一个是文件删除竞态
    译介 Phoronix 报道（Michael Larabel，2026-09-20）：Gzip 1.15 接替 1.14（2025-04），含 100+ commit，重心是攒了一年半的 bug 修复，多个 bug 自诞生起存在。修复清单（引 GNU 通告）：另一进程同时重命名 gzip 目标祖先目录时会误删错文件（TOCTOU）、gzip -d 不再拒 PKZIP 签名/本地头/数据描述符、诊断给特殊字符文件名加引号、畸形输入用未初始化内存、解压 .lzh（在 .Z 后）时缓冲区溢出、.lzh 比特缓冲未清/译码表被上一文件污染致输出损坏、--synchronous 在 O_PATH/O_SEARCH 平台无法同步父目录（1.7 引入）、缺 mktemp 平台 gzexe/zdiff/znew 临时文件竞态。另：遵循环境变量 locale（不再默认 C）、终止对 FreeBSD 4.11/HP-UX 11.00/Minix 3.1.8/非 UCRT MinGW 的 Windows 8.1 支持。解读聚焦内存安全与数据损坏类问题、TOCTOU 对自动清理脚本的运维风险、祖传冷路径少人审计、低回归成本的「无脑更」建议。
