EDITOR\'S NOTE

2026 · 7 月刊 · 内部分发

距离上一版 2026.6.11 仅仅半个多月，OpenClaw 又放出了 2026.7.1 预发行版。表面上是一次小版本号迭代，底下却是        模型生态、Gateway、Crash-loop 恢复、移动端离线会话与 Doctor 自检        五个层面同时加固。

本文带你逐层拆解这版 release notes 的关键变更，        看懂为什么这可能是 OpenClaw 走出「玩具级 Agent 框架」、迈向「准生产级 AI 操作系统」的一道分水岭        。

01

PART

模型矩阵重构：GPT-5.6 默认、ClawRouter 路由

MODELS · PROVIDERS · ROUTING

模型层是这一版最显眼的部分。新装上阵的供应商阵容      首次包含 Featherless、Anthropic Claude Sonnet 5、Mythos 5、Meta Muse Spark 1.1，并新增 ClawRouter 这一内置路由插件      。对终端用户而言，最直接的变化是：新装默认模型切换为      GPT-5.6      。

ClawRouter 是这版引入最值得关注的概念之一。它在 OpenClaw 内部作为      bundled provider plugin      存在，支持 credential-scoped dynamic model discovery，同时维持 OpenAI-compatible 与原生 Anthropic/Gemini 传输------也就是说，你不再需要为每一个外部供应商写一份适配器，ClawRouter 会      按凭据动态发现可用模型、统一报价、统一预算上报      。

维度      2026.6.11      2026.7.1              默认模型      GPT-5.x 系列      GPT-5.6（含 /think ultra、max）              供应商路由      手动配置 per-provider      ClawRouter 动态发现 + 预算上报              上下文窗口      各模型默认      Nemotron Super 1M context 接入              凭据管理      明文存在 auth storage      SecretRef 进程本地 sentinel 注入

这张表最容易被忽视的一行其实是最后一项：      SecretRef model credentials      。在新版本中，已解析的 provider secrets 在 auth storage、流式 SDK 配置、本地 provider probing 阶段全部被      进程本地 sentinel 隔离      ，只在最终网络边界才以明文注入------同时保留 exact-value log redaction。换句话说：过去一旦 Gateway 进程被 dump，模型 API Key 会随堆栈一并泄露；现在它们只会出现在 TLS 握手那 1ms 之内。

02

PART

Gateway：Crash-loop 安全模式与容器迁移闭环

GATEWAY · STARTUP · RECOVERY

2026.6 系列最大的一类抱怨是「      升级到一半 Gateway 起不来      」------尤其是复用挂载状态做版本升级时，插件尚未收敛到目标版本，transport 已经对外开放，结果是一边重启一边雪崩。7.1 给这条链路上了一道安全闸：

  • 容器镜像升级：先跑版本化 state migrations 与 plugin convergence，在 Gateway 宣告 readiness 之前完成全部迁移；迁移失败则 fail-closed，附带 doctor --fix 恢复指引（PR #101881，修复 #98565）。
  • Crash-loop recovery：连续 unclean 启动后进入control-plane-safe mode，冻结 transport 与 provider 激活；遇到致命配置错误返回 EX_CONFIG，让 systemd / launchd 别再盲目拉起。
  • 插件更新可靠性：通过 ClawHub 切换成功的插件在 core 更新期间不再被二次处理导致意外禁用（PR #105405）。

真正关键的不是「修了一个 bug」，而是「承认升级本身就是一条独立的故障域」

03

PART

iOS / Android：离线预绘、Watch 语音回放

MOBILE · OFFLINE · VOICE

移动端这次重点在三件事：      iOS / Android 离线会话预绘、Apple Watch 完整语音轮次、Gateway TTS 通过 RPC 返回整段语音给远程客户端      。换句话说，OpenClaw 第一次让「手腕上、手机锁屏时」也能维持稳定对话。

iOS 离线预绘

iOS offline chat：从受保护的 per-gateway 缓存预绘最近会话与 canonical transcripts，离线时发送按钮禁用；配对重置时清空缓存对话文本。

Apple Watch 语音轮次

从 Watch 端发消息并直接听取 OpenClaw 回复；新增明确的「不发声消息」与「停止朗读」控件，避免手表被语音淹没。

Gateway TTS 整段回放

新增 tts.speak RPC，operator-scoped，直接返回配置 Provider 的整段语音作为 inline 音频，给远程客户端使用。

04

PART

Crestodian：对话式 Onboarding 与 Doctor 自检

ONBOARDING · DIAGNOSTICS

新装的「对话式 onboarding」是这版的隐藏主线。Crestodian 现在跑一个真正的 agent-loop，覆盖 CLI、Web install 与 macOS app。它能做到三件事：      AI 引导的 Provider 设置、模型评判的细粒度审批（绑定到确切操作）、凭据提示遮罩      ；当可用模型全空时，自动降级到 deterministic fallback。换句话说，第一次装 OpenClaw 的人不再需要在 6 个 Yaml 里手填凭据。

配套的 Doctor 自检面也加宽了不少：      auth-profile / workspace / device-pairing / channel-plugin / memory-provider / systemd exhaustion / Windows LAN firewall      七类诊断被一并暴露；doctor --fix 还会预先展示「review-required Gateway bind」与「denied node-command」类需要审批的改动，避免悄悄改了你的环境。

05

PART

Telegram / Codex：续传、Steer、配对

MESSAGING · STEERING

Telegram 通道做了三件与稳定性挂钩的事：      通过 private /login 配对 Codex、用 /steer 和 /tell 引导正在进行的 run、transcript acknowledgement 缺失时保留消息      。durable turn 的接管被小心翼翼地做成「只在 durable agent adoption 完成后才完成 spooled update」，避免一个会话被两条不同线程各回一半。

Codex 这边则是 0.143+ 的 app-server 协议、移除 0.142 之前的 wire-shape 兼容、retired on-failure approval 全部迁移到 on-request，以及      通过 tool_search 找回 deferred native spawn_agent      ，让 search-capable 模型也能跑 native subagent mirror。

CLOSING NOTE

2026.7.1 看似一次预发布，实则是把 OpenClaw 推向「可控、可恢复、可观测」的工程化轨道：模型路由不再写死、升级不再翻车、移动端不再断线、Doctor 不再是事后诸葛亮。当一个 Agent 框架同时具备这四件事，才真正可以进入生产。Pre-release 标签下的版本号，从来不是试用品的借口。
