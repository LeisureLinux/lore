Herdr：一个终端统领所有 AI 编码 Agent

发布于 · 分类 AI/Agent

TL;DR： Herdr 是编码 AI 时代的 tmux------一个终端多路复用器（TUI multiplexer），但专为 AI 编码 Agent 优化。它让 Claude Code、Codex、OpenCode 等所有 Agent 运行在 真正的 PTY 终端 中，支持 SSH 远程附着、持久化会话、Agent 状态可视化和 JSON Socket API 控制。无 Electron、无账户、无遥测。

一、Herdr 是什么？

Herdr（herdr.dev）是一个终端级的多路复用器，但不是 tmux 的替代品------它是为 AI 编码 Agent 量身定制的\"终端指挥中心\"。

口号很简洁：

one terminal for the whole herd

（一个终端统领整个牛群）

这里的\"herd\"（牛群）指的是你运行的所有 AI 编码 Agent------Claude Code、OpenCode、Codex、Grok CLI、Cursor 等等。

二、核心设计哲学

Herdr 的定位可以从官网上的一句话读懂：

「Most agent managers are apps. Herdr is a multiplexer.」

大多数 Agent 管理器是应用。Herdr 是一个多路复用器。

它特意不做三件事：

  1. ❌ 不是终端模拟器------你的 Ghostty、Kitty、iTerm 保持不变
  2. ❌ 不是浏览器面板------没有 Web 视图、没有账户、没有托管控制平面
  3. ❌ 不是 tmux 的简单包装------它理解了 Agent 的语义

三、Herdr 解决了什么问题？

在使用多个 AI 编码 Agent 时，你一定会遇到这些问题：

  • 同时跑 Claude Code 和 Codex，能不能在一个终端里看到所有状态？
  • Agent 正在编译大项目，我关了笔记本，它会不会中断？
  • 在外面用手机 SSH，能不能附着回去看看进度？

tmux 能解决持久化，但它不理解 Agent------它不知道哪个面板里的进程是\"working\"还是\"blocked\"。桌面 Agent 应用能理解 Agent，但离开那台机器就废了。

Herdr 填补了这个空白。

四、核心特性真正的 PTY 面板

不是重新实现了一个聊天视图。每个 Agent 运行在真实的 PTY 进程中，保留你完整的 shell 环境、字体和快捷键。

Agent 状态语义

Herdr 能识别 Agent 的状态：Blocked（阻塞）、Working（工作中）、Done（完成）、Idle（空闲），一目了然看到所有 Agent 的全局快照。

持久化会话

终端关掉？断开 SSH？Agent 继续运行。重新附着回来，一切还在。

三层访问模式

模式 使用方式 适用场景

本地 herdr 本地开发机，持久化 Agent SSH ssh you@server; herdr 远程服务器，类似 tmux 瘦客户端 herdr --remote workbox 本地客户端连接远，传输剪贴板

手机 SSH 客户端也完全可用------窄屏幕有专门的移动切换器，一个横条显示所有 Agent，点选即可附着。

控制 API 和 CLI

Herdr 暴露了一个 JSON Socket API，让 Agent 自身也能驱动它：

# 创建工作区结构
herdr workspace create --cwd ~/project --label api
herdr tab create --label logs

# 分割面板并运行任务
herdr pane split 1-1 --direction right
herdr pane run 1-2 "just test"

# 等待、检查、继续
herdr wait agent-status 1-1 --status done
herdr pane read 1-2 --source recent-unwrapped

这意味着你可以在一个 Agent 里启动另一个 Agent，然后等待它完成。Agent 可以编排 Agent。

五、对比：Herdr vs 其他方案

能力维度 tmux / Zellij 桌面 Agent 应用 Herdr

在终端内运行 ✅ ❌ ✅ 持久化 PTY 会话 ✅ 有限 ✅ 远程 SSH 附着 ✅ 有限 ✅ Agent 语义状态 ❌ 部分支持 ✅ Agent 直连附着 ❌ ❌ ✅ Agent 可编排 可脚本化 有限 ✅

右下角是让 Herdr 真正不同的地方：它不是 tmux 的替代品，而是 tmux 的 Agent 理解版。

六、集成生态

Herdr 支持市面上几乎所有主流 AI 编码 Agent：

Claude Code、Codex、Droid、Amp、OpenCode、Grok CLI、Hermes、Cursor、Antigravity、Kimi、Kiro、Copilot、Qoder CLI------引一个就行。

官网上还有市场（Marketplace），社区可以分享插件：通知器、布局预设、链接处理器、发布检查。

安装方式一如既往地简单：

# Linux / macOS
curl -fsSL https://herdr.dev/install.sh | sh

# Windows PowerShell
irm https://herdr.dev/install.ps1 | iex

没有 Electron、没有账户注册、没有遥测------一个 Rust 编译的二进制文件。

七、适用范围与场景谁在用？

官网页面上展示的工程团队包括：JetBrains、Docker、Vercel、Kimi、Sentry、Google、NVIDIA、AWS、字节跳动、腾讯、阿里巴巴等。

分布超有意思------既有纯海外公司（Sentry、Atlassian），也有中国一线互联网大厂（字节、腾讯、阿里）。说明跨 ssh 多 Agent 编排这个需求，在两边都很强烈。

最佳场景

  1. 你同时跑 3-4 个 Agent------每个负责不同模块，在 Herdr 的\"牛群\"中一眼看到各自状态
  2. 远程开发------在云服务器上跑 Agent，本地终端关掉后 Agent 不中断
  3. 手机排障------用手机 SSH 附着，检查卡住的 Agent，重新指令
  4. CI/自动测试------Agent 通过 Herdr API 编排其他 Agent，形成自动化流水线

不太适合的场景

  • 你只用一个 Agent，不介意它占一个普通终端窗口
  • 你完全在本地桌面开发，从不关盖子
  • 你需要图形化的 Agent 聊天界面

八、一个类比

tmux 是 Vim------全力键盘，保留了什么终端会话应该有的样子。

Herdr 是 VS Code for tmux------保留了终端的最核心理念（PTY、持久化、可脚本化），但加上了 Agent 时代的语义理解。

如果你已经入了多 Agent 协作的坑，Herdr 是那个\"我不知道我需要它直到我用上了\"的东西。

后记： Herdr 是完全开源的吗？官网没有明确标注协议。但它强调\"无 Electron、无账户、无遥测\"、安装方式是一个（显然 Rust 编译的）二进制文件，同时提供 CLI、API 和社区 Marketplace。如果你是多 Agent 工作流的重度用户，值得试一次。它的价值在你第一次关掉笔记本去吃饭、回来发现 Agent 还在运行时体现得最明显。
