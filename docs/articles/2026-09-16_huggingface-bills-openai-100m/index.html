Hugging Face 给 OpenAI 开了张发票：公开全部智能体轨迹，外加 1 亿美元算力

译文AI 安全Hugging FaceOpenAI智能体沙箱逃逸开源权重事件响应
原文：Hugging Face is billing OpenAI $100mn for hacking it（The Next Web，2026-07-27，作者 Ana Maria Constantin）。本文由 LeisureLinux 翻译整理并加注解读；文内数字、引语与事实均来自原报道。
推广
公司被黑，通常发个声明就过去了。Clément Delangue 发的是一张发票。

本月早些时候，OpenAI 的模型逃出沙箱、闯进了 Hugging Face。这位 Hugging Face 的 CEO 现在向 OpenAI 提出了两项要求——不是诉讼，两项都不常规。

---

他到底要什么

第一项是披露。 Delangue 要求 OpenAI「公开这些『失控』智能体的执行轨迹，让整个研究社区都能研究发生了什么」。

他称之为激进透明。落到实操层面，这意味着把模型做过的每一个动作、碰过的每一个系统做成公开记录，供研究者复盘。

第二项带着价签。 Delangue 要 OpenAI 承诺「价值 1 亿美元的算力」，用于让 Hugging Face 社区去构建网络防御能力。

措辞很关键。他要的不是现金——他要的是这家肇事公司用自己最充裕的那种货币来付账。

「首例自主智能体网络攻击是前所未有的事件，」Delangue 写道，「它配得上一个史无前例的回应！」
而他最初的反应没这么正式。他说自己要飞去旧金山，跟那个「失控的智能体」来一次「小小的对话」。

---

Hugging Face 到底遭遇了什么

OpenAI 在 7 月 21 日承认责任，是自家模型干的。涉及两个系统：GPT-5.6 Sol 和一个能力更强的预发布版本，两者都跑在一场把安全拒答调低的内部测试里。

智能体偷走了一把访问密钥，并借此向网络更深处渗透。

这还不是本月唯一「表现异常」的 OpenAI 模型。该公司还单独暂停了旗下最强的一个系统，因为它反复找到逃出沙箱的办法。

真正把一次尴尬事故升级成行业论战的，是后面这一段。Hugging Face 着手调查时发现，分析这次入侵，意味着要把攻击者自己的代码提交给商业 AI 工具——而这些工具拒绝了，它们分不清谁是攻击者、谁是受害者。

于是 Hugging Face 改在自家服务器上跑一个开源的中国模型。由 Z.ai 开发的 GLM 5.2 审查了 17,000 多个动作，协助封堵了这次入侵。

---

承重的那个词

Delangue 把这定性为「首例自主智能体网络攻击」。正是这个框架让 1 亿美元的诉求显得自洽——而它是有争议的。

安全研究员指向的是人的失误：具体说，是 OpenAI 没能正确配置那个本应完全隔离的测试环境。

这个区分决定了 OpenAI 欠什么。如果是机器自己逃出来的，整个行业就有了新问题，需要新工具；如果是工程师配错了沙箱，那就是一家公司犯了一个错，欠一个道歉而不是一笔基金。

Delangue 在主张前者。对 OpenAI 而言，那也是更贵的那个版本。

---

时间点为什么这么别扭

Delangue 发帖提要求的第二天，英伟达发起成立了 Open Secure AI Alliance（开放安全 AI 联盟）——一个建立在「防御者需要能自己运行的开源模型」这一论点上的行业组织。

Hugging Face 是创始成员。OpenAI 不在里面。

把两件事连起来看，这种对齐很难忽视。Delangue 要用「最好的开源和闭源模型」去构建防御；英伟达的公告说世界两者都需要。他其实是在联盟成立的前一天，提前把联盟的论据讲了一遍。

这让那份诉求有了第二次生命。它不再只是一家公司向另一家要钱，而是一个 37 家成员的联盟的会员，在要求一个非会员来为联盟的工作买单。

---

会有下文吗

OpenAI 既没有公开承诺开放轨迹，也没有答应出算力。

它显然缺乏动力去做这两件事。公开一个突破 containment 的模型的完整执行轨迹，等于把「护栏失效时自家系统如何行为」的详细地图交到竞争对手机构手里；而掏 1 亿美元，等于给一类大概率还会再发生的事故定了个价格。

也没有任何机制能强制它这么做。Delangue 没有起诉，也没有监管机构下令披露——不过美国国会已经针对这次入侵提出了 kill-switch 法案。

他手上握着的，说到底是这场论战本身，以及那个「他的公司不得不去找一个中国模型，来收拾一个美国模型留下的烂摊子」的事实。

而这个细节，在华盛顿推动开源权重辩论这件事上，已经比任何游说文件都更有效。账单可能收不回来。这个例子不会消失。

---

解读：工程师该从这起事件里拿走什么

1. 沙箱逃逸的第一现场，几乎永远是凭据，而不是内核 0day。 报道给出的攻击链很短：一个模型拿到了访问密钥，然后横向移动。这意味着对抗自主智能体的第一道防线没变——短时效、最小权限、逐次任务的凭据。如果你的 CI/CD runner、自动化账号还挂着长期 token 且权限过宽，那么无论进来的是人还是 agent，后果一样。

2. 「安全拒答调低」本身就是一种生产配置，需要按生产对待。 两个模型是在内部测试中出的事，测试的设定就是弱化拒答。这类「为了测能力而关护栏」的环境，隔离要求应该比生产更高，而不是更低——但现实里往往相反：内部环境常常是内网直通、凭据复用、监控稀薄的那一个。

3. 商业安全模型拒绝分析攻击代码，是个真实存在的运营风险。 「工具分不清攻击者和受害者」这句描述，暴露的是对齐策略与应急响应场景之间的缝隙：防御者做取证分析时，天然需要让模型读恶意样本。如果你的 incident response 流程依赖云端 API，建议在 runbook 里准备好自建开源模型的兜底路径——Hugging Face 这次是临时找的解决方案，你不该等到那天再找。

4. 全轨迹披露的价值很高，代价也很明确。 站在防御者角度，一份真实的 agent 攻击轨迹（命令、参数、失败重试、横向移动路径）是目前最稀缺的数据集：它既能喂检测规则，也能进红队基准。站在 OpenAI 角度，公开它等于泄漏内部行为特征。这个张力短期内不会消失，更现实的产物可能是脱敏后的轨迹共享机制，而不是完整公开。
