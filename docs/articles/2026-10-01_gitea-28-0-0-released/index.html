原文：Gitea 28.0.0 is released（Gitea Blog，2026-09-30，作者 bircni、TheFox0x7，Gitea 技术监督委员会）。本文为译文 + 解读。
推广

一句话结论

Gitea 28.0.0 发布，最大标志是去掉了历史性的 1. 前缀（所以是 28.0.0 而不是 1.28.0）。但这个版本真正需要你升级前仔细读的，是一批安全默认值收紧的破坏性变更：Git 网络操作改走内部代理、出网策略必须显式声明、自注册默认关闭、Actions 运行历史默认 400 天过期。默认更安全了，但很多人的现有配置会在升级后失效或行为改变。

一、版本号：去掉 1. 前缀

Gitea 去掉了版本号里历史性的 1. 前缀，所以这次发布是 28.0.0，而不是 1.28.0。
这对运维的实际影响：所有写死版本号的脚本、镜像标签、健康检查、升级文档都要跟着改。官方也提醒，发布二进制不再包含 32 位 x86 与 gogit 构建，Snap 不再为 armhf 构建，并且下载文件名不再带 OS 版本后缀（例如现在是 gitea-28.0.0-windows-amd64.exe）——如果你的下载脚本依赖旧命名规则，需要更新。

二、破坏性变更（升级前必读）

⚠️ 1. Git 网络操作走内部代理，出网规则重写（#39426）

这是本次最需要关注的变更。 迁移（migrations）、镜像（mirrors）以及其他 Git 网络操作，现在统一走一个内部代理，该代理对直连也应用出网设置。

具体变化：

  • external 预设被移除。 想要默认拒绝的策略，需要设 EGRESS_MODE = strict 并显式列出允许的主机。
- [migrations] EGRESS_MODE 管迁移与镜像； - [security] EGRESS_MODE 管 webhook 与 OAuth2。
  • strict 模式下，不带端口的条目只允许 80 和 443 端口。
  • 默认的 lax 模式下，[security] ALLOWED_HOST_LIST 不再限制公开主机。 想让它继续当排他性白名单，必须设 [security] EGRESS_MODE = strict。如果设置了白名单却没有显式声明 EGRESS_MODE，Gitea 会在启动时打警告。
  • IP 地址条目不再支持通配符，且 * 不再是合法条目。
  • 域名条目遵循 curl 语法：
- example.com —— 匹配该域名及其所有子域； - *.example.com —— 只匹配子域； - example.* —— 无效。
  • 非法的 [migrations] BLOCKED_HOST_LIST 条目现在会阻止 Gitea 启动。
  • [migrations] ALLOWED_DOMAINS、BLOCKED_DOMAINS、ALLOW_LOCALNETWORKS 已废弃，改用 [migrations] ALLOWED_HOST_LIST 与 BLOCKED_HOST_LIST。
解读：这是把「默认宽松」翻成「默认收紧」。过去你的 ALLOWED_HOST_LIST 在 lax 模式下其实拦不住公开主机——很容易给人「我已经限制出网了」的错觉。新版本要求你明确表态：到底是要白名单，还是要宽松。代价是升级后镜像、webhook、OAuth2 可能集体失灵——因为它现在真的按你写的规则执行了。

⚠️ 2. Actions 运行历史会过期了（#38855）

已完成的 Actions 运行，默认在 400 天后被删除，连同它们的 jobs、日志和 artifacts。执行删除的是新的 cleanup_action_runs 定时任务，默认在午夜运行。

想保留全部运行记录，升级前设置：

[actions]
RUN_RETENTION_DAYS = 0

注意语义变了：0 现在表示「永久保留」，适用于 RUN_RETENTION_DAYS、LOG_RETENTION_DAYS、ARTIFACT_RETENTION_DAYS。日志和 artifacts 始终随其运行一起删除。

解读：如果你的合规、审计或排障流程依赖一年以上的 Actions 历史，这次升级会静默删掉它们。这是本次最容易被忽略、损失又最不可逆的一项——删掉的 artifacts 是要不回来的。

⚠️ 3. 要求 Git 2.25 或更新（#39131）

Gitea 现在拒绝在低于 2.25.0 的 Git 版本上启动。 自行安装 Git 的，升级前先跑 git --version 确认。

⚠️ 4. 自注册默认关闭，[server] DOMAIN 被忽略（#39400）

  • 除非显式设置 [service] DISABLE_REGISTRATION = false，否则自注册现在是禁用的。
  • Gitea 不再读取 [server] DOMAIN。 实例域名（含默认 SSH 域名）现在来自 ROOT_URL——如果你以前依赖 DOMAIN，请改设 ROOT_URL。
解读：自注册默认关闭是正确的安全默认（公开实例最容易因此被塞满垃圾账号），但如果你的部署依赖开放注册（如内部试用环境），升级后会突然没人能注册。域名来源改成 ROOT_URL 是更合理的收敛——单一真相来源，但迁移时容易漏，需检查 SSH 克隆地址是否仍正确。

⚠️ 5. Actions 工作流求值更严格（#39358）

  • Job 级 if: 现在在矩阵展开之前求值，且只能使用 github、gitea、needs、vars、inputs 这几个上下文。依赖 matrix 的条件要挪到 strategy.matrix.include/exclude，或挪到 step 级 if:。
  • 矩阵的 fail-fast 现在真正生效了，失败 job 可以取消剩余组合。想让全部跑完，设 strategy.fail-fast: false。
  • 公开仓库里的工作流不能再调用私有仓库的可复用工作流；嵌套工作流的权限也不能超过调用方。
解读：fail-fast 从「写了不生效」变成「真生效」，是静默的行为变更——原本指望矩阵全绿的流水线，可能会提前中断。而公开仓库不能调私有仓库的可复用工作流，会直接打断那些用「公开仓库 + 私有 actions 仓」模式的组织。

三、主要亮点（管理）

🚀 以特定用户身份查看实例（#38614 / #38924）

管理员现在可以「模拟（impersonate）」某个用户，以该用户的视角查看 Gitea，便于在不让用户交出密码的前提下复现权限问题。会话有横幅标记并能链回管理员账号；会话中的一切操作都以被模拟用户身份执行，开启审计日志后，事件会同时记录两个账号。

这是很实用的运维能力——「用户说看不到某个仓库」这类问题的定位时间可以从小时级降到分钟级。同时审计双记录的设计也很必要，避免模拟成为审计盲区。

🚀 审计日志（#38189）

Gitea 现在能记录安全相关事件，并在管理员、组织、仓库、用户的设置界面中展示。事件可按 actor、action、origin 过滤，管理员可导出为 JSONL。

默认关闭，启用方式：

[audit]
RECORD_OUTPUT = database

默认保留 30 天，通过 [audit] RETENTION_DAYS 调整，0 表示永久保留。

🚀 共享 Redis 配置（#38550）

新的 [redis] 段设置一个 CONN_STR，作为 cache、session、queue、global lock、WebSocket pub/sub 的默认值。适用于那些已经配置使用 Redis、但没有各自设置连接串的子系统。

[redis]
CONN_STR = redis://127.0.0.1:6379/0

🚀 专用机器人账号（#38966）

机器人账号是给自动化用的：用访问令牌认证、不能交互式登录、不接收通知和邮件。管理员可以创建机器人、管理其令牌，并可从管理界面、API 或 CLI 在普通用户与机器人之间转换符合条件的本地账号。

这是个迟到的功能。过去自动化账号只能伪装成普通用户，既混在人员列表里，又可能收到通知邮件——职责边界模糊。机器人作为一等公民，对合规审计也更友好。

🚀 实时通知改用 WebSocket（#36965）

通知计数、秒表更新、登出事件现在使用 /-/ws 的 WebSocket，取代 /user/events 的 SSE。

升级注意：

  • 反向代理必须转发 WebSocket 升级头，否则通知计数和秒表会退化为轮询；
  • 多进程部署需要 [websocket] PUBSUB_TYPE = redis 和 Redis 连接；
  • [ui.notification] EVENT_SOURCE_UPDATE_TIME 设置被移除。
这一条是「不明显的升级陷阱」：功能看起来还在（退化成了轮询），但你的反代配置如果没改，性能和行为都会悄悄变化。多实例部署的还需要补 Redis 配置。

四、主要亮点（代码与协作）

  • 🚀 仓库级 HTTPS 部署令牌（#37306）：部署令牌是 SSH 部署密钥的 HTTPS 对应物。每个令牌限定单个仓库，有只读或读写权限，作为Git 与 LFS over HTTPS 的密码。部署令牌和个人访问令牌（#38907）都支持原地重新生成。
  • 🚀 在 PR diff 里搜索与过滤文件（#37068）：diff 文件树新增搜索框与文件扩展名过滤器。两者同时收窄文件树和 diff，且扩展名过滤保存在 URL 里，所以过滤后的视图可以分享。
  • 🚀 合并前要求代码所有者审批（#34995）：新的分支保护选项，在每条匹配的 CODEOWNERS 规则都被其代码所有者或所列团队之一的成员批准前，阻止合并。
  • 🚀 选择接收哪些仓库通知（#37571）：关注按钮变成菜单，含 Participating and mentions（仅参与与提及）、All activity（全部活动）、Ignore（忽略）、Custom（自定义）。自定义可为 issues、pull requests、releases 任一开通知。UI 与邮件通知都适用。
  • 🚀 从仓库头部切换仓库（#38188）：仓库名旁边的下拉框，可搜索并在同一所有者的仓库间切换。
  • 🚀 从生成仓库中排除文件（#38064）：模板仓库可在 .gitea/template 的 [exclude] 段列出文件和目录，使它们不出现在生成的仓库中。
  • 🚀 通过关闭引用关闭 PR（#39393）：Fixes: #123 这类关闭引用现在也能关闭 pull request，而不只是 issue。
  • 🚀 内外部 issue 追踪器并用（#39354）：仓库现在可以同时使用 Gitea 内置 issue 和一个外部追踪器（其引用使用字母数字或正则格式，如 JIRA-123）。要把外部追踪器 URL 留空，否则 Issues 标签页仍会重定向到外部追踪器。
  • 🚀 REUSE 许可证检测与多许可证展示（#38720）：Gitea 现在能检测按 SPDX 标识符命名的 REUSE 风格许可证文件，并展示所有检测到的许可证及其文件链接。

五、主要亮点（Actions）

  • 🚀 查看构建队列（#38585）：新的队列视图先列运行中的 job，再按 runner 领取顺序列等待中的 job。管理员有带所有者、仓库、状态过滤的实例级视图；每个仓库在 Actions 标签页有自己的队列。两个视图都原地刷新。
  • 🚀 工作流运行列表自动刷新（#38329）：Actions 运行列表现在自动刷新，浏览器标签页在后台时除外。
  • 🚀 在浏览器里预览构建产物（#36754）：Actions 运行视图现在可以浏览 artifacts 并预览文本、图片、PDF，以及生成的 HTML（如测试报告）。预览需要登录且有该运行的读权限；HTML 预览在沙箱 iframe 中运行。ZIP 下载仍然可用。[actions] ARTIFACT_PREVIEW_MAX_SIZE 默认把预览限制在 10 MiB；0 禁用预览，-1 移除限制。单个文件还受 [ui] MAX_DISPLAY_FILE_SIZE 约束。
  • 🚀 动态矩阵、max-parallel 与更多工作流语法（#36564 / #36357 / #39358）：job 矩阵现在可以由前序 job 的输出构建；strategy.max-parallel 限制同时运行的矩阵 job 数；runs-on 等属性可以依赖 needs，并在那些 job 完成后解析；uses: 接受 self: 以引用同一实例上的 actions 与 workflows，可复用工作流调用接受 $/ 表示同一仓库（#38822）；推送非法的工作流文件现在会创建一次失败的运行并显示错误。
  • 🚀 项目看板 API（#38691）：新的 REST 端点，在仓库、组织、用户三个层级管理项目看板。
  • 🚀 更多工作流运行管理 API（#35382 / #38756）：新的 Actions 端点管理工作流运行、获取日志、强制取消。
  • 🚀 包注册表改进（#37890 / #39267 / #36695 / #38968）：npm 注册表支持 npm deprecate、更丰富的版本元数据和单版本 API；Helm chart 可带 provenance 文件上传；站点管理员可通过新 API 列出所有包。

六、安全修复

官方明确说明：本版本包含安全修复。为了给所有人留出升级时间，细节将在大约一周后补充到公告中。

已列出的安全条目：

  • Fix(git)：拒绝推送中非法与重复的 Git 对象（#39472）
  • Fix(git)!：Git 网络操作走内部代理并更新出网设置（#39426）
  • Fix(ssh)：通过指纹识别所呈现的公钥（#39423）
  • Fix(actions)：让已取消和未批准的 fork PR 运行保持在审批门之后（#39399）
  • Fix(deps)：更新 golang.org/x/crypto SSH 以应对拒绝服务（#39219）
  • Fix(repo)：对团队访问、删除和包解链强制执行仓库级授权（#39063）
这是本次发布一个需要留意的节奏问题：公告发布时安全细节尚未公开。对自托管运维而言，「含安全修复但细节待公布」意味着你不能靠影响面判断优先级——建议按「立即升级」处理，而不是等细节。

七、升级建议：动手前的检查清单

官方步骤：从下载页取包 → 读 breaking changes → 备份数据 → 替换二进制或 Docker 容器 → 重启。

本文补充的检查清单：

  1. 1. 备份：数据库 + 仓库数据 + custom/ 与配置文件。Actions 历史一旦被清理任务删除无法恢复，如果它在保留范围内，先确认 RUN_RETENTION_DAYS 设置。
  2. 2. 版本号：更新所有写死 1.x 的脚本、镜像标签、文档；注意下载文件名不再带 OS 版本后缀、32 位 x86 / gogit / armhf Snap 已取消。
  3. 3. Git 版本：git --version 必须 ≥ 2.25。
  4. 4. 出网规则：这是最容易出问题的一项。审阅 [migrations] 与 [security] 的 ALLOWED_HOST_LIST / BLOCKED_HOST_LIST；
- 想收紧 → 设 EGRESS_MODE = strict 并列出允许主机； - 检查 IP 条目里的通配符（已不支持）和 * 条目（已非法，会阻止启动）； - 检查域名条目是否符合 curl 语法（example.* 无效）； - 迁移废弃项：ALLOWED_DOMAINS / BLOCKED_DOMAINS / ALLOW_LOCALNETWORKS。
  1. 5. 域名：[server] DOMAIN 已不生效 → 确认 ROOT_URL 正确，并检查 SSH 克隆地址。
  2. 6. 注册：如果依赖开放注册，显式设置 [service] DISABLE_REGISTRATION = false。
  3. 7. 反向代理：确认转发 WebSocket 升级头（否则通知与秒表退化为轮询）；多进程部署配置 [websocket] PUBSUB_TYPE = redis 及 Redis 连接。
  4. 8. Actions：检查矩阵 fail-fast 的预期（现在真生效了）；确认没有依赖 job 级 if: 里的 matrix 上下文；确认没有「公开仓库调用私有仓库可复用工作流」的用法。
  5. 9. 审计与机器人：考虑启用 [audit]（默认关闭）；如需自动化账号，改用机器人账号而非伪装普通用户。
  6. 10. 升级后验证：迁移/镜像功能（出网规则最容易踩）、webhook 与 OAuth2、SSH 克隆、登录、Actions 跑一次、通知计数是否实时。

八、解读：这次释放的两个信号

1. 自托管软件正在把「安全默认」调紧，而这必然是一次阵痛。

这个版本的核心主题是把默认值从宽松改成收紧：自注册默认关闭、出网默认受限、非法配置阻止启动。方向完全正确——自托管产品的历史包袱就是「默认配置不安全，而使用者以为它安全」。但代价也很直接：升级后一堆东西会突然不工作，而其中一些（出网规则、fail-fast）是静默的行为变更，不会给你明显报错。

这说明一件事：Gitea 判断自己的用户群已经足够成熟、值得用「明确的配置」换取「真正的安全边界」。 对运维而言，升级前读 breaking changes 从「好习惯」变成了「必需动作」。

2. 「Actions 历史 400 天过期」是需要单独记住的一项。

其余变更的后果大多是「不工作」——你能立刻发现并修。而 Actions 历史到 400 天被删是静默、累积、不可逆的。如果你的团队把 Actions 日志/artifacts 当作审计证据或长期排障依据，请在升级前就把 RUN_RETENTION_DAYS = 0 加上。

顺带一提语义变化：0 从「立刻删除」变成了「永久保留」——这本身就是个容易理解反的改动，值得在升级时特别向团队说明。
