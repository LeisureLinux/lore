Linux 7.4 内核构建或快 36%，增量构建快 70%：AI 找出瓶颈，人写的补丁

Linux7.4内核构建性能优化AIkbuildRust前端译文独立科技媒体内核开发
原文：Linux 7.4 Could End Up Seeing Kernel Builds ~36% Faster, Incremental Builds ~70% Faster（Phoronix，作者 Michael Larabel，2026-09-14 06:31 EDT 发布）。本文由 LeisureLinux 翻译整理并加注解读；数字与署名均来自原报道，补丁链接已核对。
推广
本月早些时候，Michael 报道过一组发往 Linux 内核邮件列表的补丁——它收拾了一批"hideous code（丑陋代码）"，让 Linux 内核构建更快。借助 AI 的协助，内核里一批单线程瓶颈被定位并修复。今天早上这组补丁出了第二版（v2），有望在 Linux 7.4 合入主干。

这组补丁对加速内核构建收益很大：包含全部模块的 allmodconfig 完整构建快了 36%，而增量构建快了约 70%。

这项工作由 ARM 的 Lorenzo Stoakes 牵头，今天提交了补丁 v2。原先 7 个补丁里有 2 个已经被接走并合入；其余补丁做了一些修复、针对最新上游 Git 代码 rebase、让 Rust 编译器并行前端（parallel front-end） 更顺，以及其他多为小改。Stoakes 在评论里说，由于改动大体没有争议，他乐观认为能在下一个内核周期（Linux 7.4）合入。这是个相当令人兴奋的成果——构建时间拿到了两位数的百分比提升。

对想跟进的人，v2 补丁可在内核邮件列表找到（lore.kernel.org，主题 build-speedup-v2）。

---

解读：三个值得内核/构建工程师关注的点

1. "AI 找瓶颈，人写补丁"是一个可复制的工作流。 报道标题里写的是"AI made a lot of hideous code but found major bottlenecks"——意思是 AI 未必写出能直接合入的漂亮代码，但在扫描、定位单线程热点这件事上帮了大忙。对动辄几小时的全内核构建来说，瓶颈往往藏在某条被忽视的串行步骤里；让 AI 在海量 Makefile/kbuild 逻辑里圈出热点，再由人做工程化修复，比纯人工 grep 高效。这是 2026 年相当务实的"人机组队"范式。

2. 增量构建 70% 比全量 36% 更关键。 每天改几行、重编内核的开发者，吃的是增量构建的红利；全量 36% 利好 CI 与发布构建。两者都两位数提升，意味着开发者反馈循环和 CI 排队时间同步缩短。如果你在日常用 make -j 跑内核，等 7.4 合入后这波收益会直接落到你头上。

3. Rust 前端并行化被点名。 补丁里特意提到"让 Rust 编译器并行前端更顺"——Rust 正在大举进入内核（从上面几篇能看到 coreutils 也在被 Rust 重写），而 Rust 编译前端长期是构建吞吐的短板。把这部分也并行化，是"内核里 Rust 代码越来越多"背景下的必然优化。值得做内核 Rust 开发的关注。
