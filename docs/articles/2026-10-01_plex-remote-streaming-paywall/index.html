原文：Plex just closed the last free loophole for streaming your own movies remotely（MakeUseOf，2026-09-30）；Plex just blocked one of the last free ways to stream your own movies remotely（XDA Developers，2026-09-30）。本文为译文 + 解读。
推广

一句话结论

Plex 把远程串流的付费门槛扩展到了第三方客户端。据 Infuse 开发团队 Firecore 公告，他们收到 Plex 通知：「从本周晚些时候开始，所有 Plex 用户都需要 Remote Watch Pass 或 Plex Pass，才能从远程个人媒体服务器播放——包括使用 Infuse 这类第三方应用的用户。」 至此，「自己的服务器、自己的电影」在家庭网络之外播放，已无免费路径。本地网络内播放仍完全免费，音乐和照片也不受影响。

一、这不是突然袭击，而是三年收网的最后一环

很多报道把这条新闻写成「Plex 又涨价了」，但准确地说，这是一条持续了 18 个月的收紧路线的终点。

时间动作
2025-03-19Plex 宣布 Plex Pass 从 4.99 涨到 6.99 美元/月；同时宣布远程播放不再免费，并推出新的 Remote Watch Pass
2025-04-29新规生效：移动端 App 首先需要订阅才能远程播放
2025-11推进到 Roku 平台
2026-03-23推进到 智能电视与游戏主机（三星、LG、Vizio、PlayStation、Xbox 等）
2026-09 下旬推进到第三方客户端（Infuse 等使用 Plex API 的应用）
2026 年底（预期）覆盖所有电视平台

Plex 员工在 2025 年 11 月的论坛帖中就已经预告了这个方向：

「这项远程串流的规则变更，将扩展到所有其他 Plex TV 应用（Fire TV、Apple TV、Android TV 等），以及任何使用 API 提供远程串流的第三方客户端。」
所以 2026 年 9 月这一步，不是新政策，而是既有政策的补漏。

二、新规之下，满足条件的三选一

Plex 官方支持文档写得很清楚。要从 Plex Media Server 远程播放视频（即不在与服务器同一局域网时），以下任一条成立即可：

  1. 1. 服务器管理员的账号有活跃的 Plex Pass —— 此时该服务器上的所有用户都能免费远程串流（这是「一次付费、全家受益」的路径）；
  2. 2. 你自己的账号有活跃的 Plex Pass；
  3. 3. 你自己的账号有活跃的 Remote Watch Pass。
⚠️ 注意「活跃」二字：不需要同时买两个，三选一即可。
价格对照：
订阅价格包含什么
Plex Pass6.99 美元/月；69.99 美元/年；249.99 美元终身远程串流 + 硬件转码、跳过片头/片尾、离线下载、家长控制等全套
Remote Watch Pass1.99 美元/月；19.99 美元/年（无终身选项）只有远程串流，不含其他 Plex Pass 权益

不受影响的部分：

  • 本地网络内播放：完全免费，不需要任何订阅。事实上 Plex 还取消了移动端的一次性激活费，所以「只在家里看」的用户比以前更省。
  • 音乐与照片：远程播放限制只针对电影/电视/视频。Plexamp（音乐）与 Plex Photos（照片）的串流不受限制。
这里有个值得注意的反差：同一个远程访问动作，串流音乐免费、串流视频要钱。Plex 的理由是视频的带宽与转码开销远大于音频。这个解释在技术上站得住，但用户是否买账是另一回事。

三、第三方客户端为什么被拉进来了

这是本次事件里最值得拆的一层。

在此之前，付费校验是构建在官方 Plex App 里的。第三方播放器（如 Apple 生态里口碑很好的 Infuse）走的是 Plex 的公开 API，自己实现了播放逻辑——它们绕过了官方 App 里的那道校验。

Firecore 团队在 Reddit 上确认收到 Plex 的通知后表示失望——因为远程访问一直是 Infuse 的热门功能。他们也说明：本地播放不受影响，用 Infuse 在家里看自己的库照旧免费。

关键在于补漏的方式：Plex 没有封杀第三方客户端，而是把校验从客户端挪到了服务端——由 Plex 的中心服务器在会话握手时判断「这个请求是不是来自家庭网络外」，并据此要求订阅。这使得绕过变得困难得多，因为校验点不再在你可控的应用里，而在你必须连的 Plex 云服务上。

「Plex 依然会知道你在放什么，因为服务器软件会上报」——一位长期用户的总结。这正是中心化鉴权的代价：你可以不装官方 App，但你绕不开 Plex 的服务器。

四、不想付费的话，三条现实路径

社区给出的方案按技术门槛从低到高排列：

路径 1：Mesh VPN（Tailscale）—— 最省事

思路是让手机以为自己在家里。用 Tailscale 这类 mesh VPN，在服务器和你的设备上都安装、登录同一账号，两者就被放进同一个私有虚拟网络（设备会拿到 100.x.x.x 的固定地址）。此后 Plex 看到的连接被判定为本地，限制自然不适用。

  • 优点：安装即用，官方包覆盖 Windows / macOS / Linux / Synology / TrueNAS；地址固定，适合做媒体服务器；流量走你自己的加密隧道，ISP 和公共 Wi-Fi 看不到你在看什么。
  • 代价：每个要看的人都得装。给远方的父母或朋友分享库的场景，这条路很难走通。
  • 额外好处：可以继续用官方 Plex App（保住 Discover、Watchlist 等功能），只是把网络层修好。

路径 2：Docker + 反向代理（Caddy）—— 门槛最高、体验最好

在 Docker 里跑 Plex，让流量经过 Caddy 这类反向代理。Caddy 会自动处理 TLS 证书，亲友访问时不需要装任何 VPN App。

  • 优点：对最终用户零感知，体验和以前一样。
  • 代价：配置复杂；可能把服务器意外暴露到公网，需要你真正理解自己开的端口意味着什么；后续每次网络变化或组件更新都要维护。

路径 3：换客户端或换平台

  • 换客户端：Remote Watch Pass 是构建在 Plex 软件里的限制，不是协议层面的限制。因此不使用官方 App、改用一个不强制付费校验的开源客户端（社区常提到 Plezy），可以直接连库播放，顺带还能免费拿到离线下载、跳过片头片尾等 Plex Pass 功能。这在技术上等于再次利用同一个 API 缺口——而 Plex 已经证明它有能力在服务端补齐，所以这条路的长期稳定性存疑。
  • 换平台：Jellyfin 是最常被提起的去向——免费、开源、无订阅，硬件转码等 Plex 要收费的功能也包含在内。代价是远程访问要自己搭：没有 Plex 那套「帮你搞定网络」的中心服务，需要用反向代理或 Tailscale 自行配置。

五、解读：这件事真正的看点

1. 这不是「涨价」，是「商业模式的补漏」。 Plex 的远程访问过去依赖它的中继（relay）基础设施——直连失败时用 Plex 自己的服务器中转流量，这确实有带宽成本。问题在于：即使你配好了端口转发、走的是纯 P2P 直连，2026 年依然要付费。这说明收费的依据已经与成本脱钩，转向了「这个功能对用户值多少钱」——也就是典型的订阅化定价。

2. 真正的转折点是「校验位置」。 从客户端挪到服务端，意味着Plex 对「谁能远程播放」拥有了单方面、可远程更改的决定权。过去你买的是软件，现在你租的是准入资格。这是自托管社区对 Plex 不满的深层原因——硬件是你的、文件是你的、网络是你的，但鉴权在他那里。

3. 对自托管用户的启示：把「中心化鉴权」当作单点风险来设计。 Plex 事件给出的通用教训是——当你的服务可用性依赖第三方的鉴权服务器时，你就把一部分控制权交给了对方。Jellyfin 之所以在这轮事件里被反复提及，不只是因为它免费，而是因为它的鉴权在你自己的服务器上。如果你正在自建媒体库，值得在设计阶段就问一句：断掉厂商的云，我的东西还能用吗？

4. 现实建议。

  • 只在家里看：不用做任何事，Plex 对你是变便宜了（激活费取消）。
  • 偶尔在外看：Remote Watch Pass（1.99 美元/月）是成本最低的合规路径；如果你已经在用 Plex Pass 的其他功能，那本来就覆盖了。
  • 有多个用户要远程看：服务器管理员买 Plex Pass 最划算——一次订阅，服务器上所有用户都免费用。
  • 不想付、且愿意动手：Tailscale 是性价比最高的方案（但要每个人都装）；Jellyfin 是彻底摆脱的路（但要自己维护远程访问）。
