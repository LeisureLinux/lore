GNU Wget2 2.3 发布：多了 --progress=dot，修了几个内存泄漏

译文GNUWget2下载工具HTTP/2内存泄漏OS/2独立科技媒体
原文：GNU Wget 2.3 Released With --progress=dot, OS/2 Improvements（Phoronix，Michael Larabel，2026-09-21）。本文由 LeisureLinux 翻译整理并加注解读；文内事实来自原文。
推广
GNU Wget2 今天到了 2.3，是这款流行的非交互式命令行下载工具在 2026 年的第一个新版本。

译文：2.3 有什么

对用户最可见的变化，是新增了 --progress=dot——给那些更喜欢「文本点状（dot）」显示、而不是默认温度计进度条的人一个替代选项。

此外，Wget 2.3 改进了构建系统与配置流程，并打磨了项目文档。

OS/2 操作系统的支持也得到增强：移植了 ANSI 转义码、支持动态加载、使用类 DOS 的路径风格、正确导出符号，并接通了该系统的其他功能。

另外，Wget2 还修了不同参数的处理、文件名过长时的截断、对 iframe 的 srcdoc 的支持，以及几处内存泄漏。

Wget 2.3 可从项目的 GitLab 下载。

解读：这是个「小版本」，但有两个点值得记

1. 先分清：这是 Wget2，不是你几十年用的那个 wget。

很多人机器上的 wget 是经典的 GNU Wget 1.x（C 写、开发放缓）。Wget2 是另一回事——它是 GNU 主导的现代重写，设计目标就是多线程、HTTP/2、更好的性能与可维护性，项目托管在 GitLab（不是 classic wget 的老家）。所以「Wget 2.3」和「wget 1.25」是两条线：发型相同，内核不同。对工程实践的含义是：别看到 Wget 2.3 就以为你的发行版 wget 升了级——多数发行版默认仍是 1.x，Wget2 通常以 wget2 命令或可选包独立存在。关注它是因为，它代表了「下载器」这个最基础工具的现代演进方向。

2. 修复清单里藏着一个老生常谈：内存泄漏 + 长文件名截断。

这次修的「几处内存泄漏」和「文件名过长截断」听起来琐碎，却是 CLI 下载工具最典型的隐患：内存泄漏在长时间、批量、递归抓取（-r -l 整站镜像）场景下会缓慢涨内存，跑大任务时尤其明显；文件名截断则是老问题——不同文件系统对文件名长度上限不同（ext4 255 字节、eCryptfs 更短、Windows 的 NTFS 又有自己的限制），稍长的 URL 映射成文件名就可能被砍坏，导致文件静默覆盖或写入失败。Wget2 把这些边界条件持续收口，正是「现代重写相对老 wget 更稳」的具体体现。

一句话收尾：Wget 2.3 没有惊天动地的新功能，--progress=dot 只是个显示偏好，但它持续把「内存泄漏、长文件名、iframe srcdoc」这类基础工具的暗角补上——对一个你天天 wget 一下、却从不在意的工具来说，这种静默维护性，本身就是价值。
