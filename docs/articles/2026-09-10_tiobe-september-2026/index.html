TIOBE 2026 年 9 月榜：Python 跌破 18%，Julia 逼近前 20

译文编程语言TIOBEPythonJulia
本文译自 TechRepublic 文章《TIOBE Index for September 2026: Python Drops Below 18% as Julia Nears Top 20》，作者 Liz Ticong，2026 年 9 月 7 日发布。原文链接：https://www.techrepublic.com/article/news-tiobe-september-2026-julia-nears-top-20/
9 月的 TIOBE 榜单前 10 名几乎没有变化，但水面之下仍有几场胜负未定的竞赛。

Python 保持领先，C++ 扩大了对 Java 的优势，末尾名次依然胶着。而在别处，随着 MATLAB 再度下滑，Julia 逼近重返前 20——为上月开启的故事又添了一回转折。

TIOBE 编程社区指数通过追踪与熟练工程师、课程和第三方供应商相关的搜索活动，来衡量编程语言的流行度。

Python 跌破 18%，C 也在走弱

Python 9 月为 17.76%，延续了 2026 年大部分时间里评分的逐步下滑。C 同样失守，降至 10.28%。尽管前两名都在走低，Python 仍握有可观的领先优势，短期内第一的位置无人能撼动。

C++ 拉开了与 Java 的差距

第三名之争这个月看起来没那么胶着了。C++ 小幅升至 8.67%，而 Java 降至 7.54%，两者差距扩大到 1.13 个百分点。8 月时两者仅差 0.37 个百分点，让排名互换看起来越来越可能。

C# 以 4.22% 位居第五，其后是 JavaScript 的 2.76% 和 Visual Basic 的 2.55%。三者本月评分份额均上升，其中 Visual Basic 增幅最大。

Rust 守住第 10，门槛依然很紧

SQL 以 2.16% 守住第八，R 以 1.69% 位列第九，两者评分都上升但位置未变。

Rust 以 1.34% 稳居第 10，将其首次进入前十的纪录延长到第三个月。Fortran 紧随其后，以 1.24% 排在第 11，两者之间只差 0.1 个百分点，让最后一个席位对相对微小的变化都保持开放。

Julia 逼近前 20，MATLAB 再度下滑

Julia 以 0.74% 升至第 21，刚好排在第 20 的 COBOL 之后。MATLAB 再跌两位至第 27，延续了上月引发关注的下滑。

TIOBE CEO Paul Jansen 表示，Julia 在数值与科学计算、建模和数据处理领域夺取了 MATLAB 的部分地盘。他也指出，Julia 仍集中在专业领域，尚未作为通用语言获得广泛使用。

重返前 20 或许能说明：即使没有更广泛的突破，Julia 在这些技术领域的实力也足以支撑它在指数中占据更强位置。守住这个位置可能是更严峻的考验，而更大幅度的攀升，则取决于 Julia 能否触达 Jansen 所说的它最强领域之外的开发者。

---

我们的解读：榜单看的是「搜索热度」，不是「生产使用」

1. Python 跌破 18% 值得关注，但别误读成「Python 在衰落」。 TIOBE 衡量的是搜索活动，不是代码量或生产使用。在 AI 时代，Python 的实际使用几乎可以肯定是在增长的——但它的「搜索热度占比」会随着越来越多的人把 AI 生成代码当作默认工作方式而下降：你不再需要搜索「Python 怎么读 CSV」，因为你直接问模型了。这是 TIOBE 这类基于搜索的指标在 LLM 时代面临的结构性失真，也是解读本榜单时最重要的一条免责声明。

2. C++ 拉开对 Java 的 1.13 个百分点，是「性能回潮」的又一个信号。 从 8 月的 0.37pp 到 9 月的 1.13pp，差距在一个月内翻了三倍。结合今年 CISA/FBI 反复强调内存安全的背景，这个走势有点反直觉——但逻辑是通的：内存安全倡议推动的是「新代码用 Rust」，而不是「存量高性能代码改用 Java」。在游戏、HPC、AI 推理引擎、嵌入式这些领域，C++ 依然是默认选项，而 Java 的增量更多在云原生后端——那块恰恰被 Go、Rust、TypeScript 一起分食。

3. Rust 守住第 10 的真正含义：前十的门槛正在降低。 原文点得很清楚——Rust 1.34%，Fortran 1.24%，只差 0.1 个百分点。Rust 首次进入前十已经三个月了，但它的绝对评分只有 1.34%——对比 Python 的 17.76%，差了 13 倍。这说明「进前十」在今天的 TIOBE 里已经不是「主流语言」的同义词，而是「长尾头部」的位置。把 TIOBE 排名当作语言重要性的排名，会严重高估尾部语言的普及度。

4. Julia 逼近前 20 是个漂亮的「专业化胜利」，但天花板也写在了同一段话里。 Jansen 的评述其实一针见血：Julia 夺走了 MATLAB 的地盘，但仍集中在专业领域，尚未成为通用语言。这既解释了它的上升（科学计算、建模、数据处理这三块的替代需求真实存在），也预示了它的瓶颈（无法触达领域外开发者）。Julia 的机会在于「MATLAB 替代 + 开源授权」的组合拳，风险在于生态规模——对需要长期维护的项目，选择 Julia 意味着接受一个更小的人才池和更少的第三方库。

5. 最实用的一条建议：不要用 TIOBE 做技术选型。 它是热度指标，适合观察趋势，不适合决定「用什么写下一个项目」。真正该看的是三件事：你的团队会什么、你要解决的问题需要什么、目标领域的生态成熟度如何。一个更稳妥的做法是把 TIOBE 与 Stack Overflow 开发者调查、GitHub Octoverse、以及本地招聘市场数据交叉验证——尤其是本地招聘数据，因为它直接决定你招不招得到人。

6. 对信创与国产开发生态的参照。 三个观察：一是Python 在 AI 领域的默认地位短期不会被撼动，国产 AI 工具链的 Python 绑定是安全的长期选择；二是Fortran 以 1.24% 稳居第 11 说明科学计算老代码的生命力极强——国产科学计算与工业软件的兼容性工作中，Fortran 编译器的维护不能忽视；三是Julia 这类「专业领域强、通用生态弱」的语言，在信创场景中应作为技术储备而非主力选型，除非有明确的 MATLAB 替代诉求。
