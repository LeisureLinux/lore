Mir 2.30 发布：Rust 从可选变硬性依赖，Canonical 首次公开 Mir 路线图

MirCanonicalWayland合成器RustUbuntu 26.04wl_fixes路线图桌面译文
原文线索：Mir 2.30 Released Now With Rust Required, Mir Roadmap Published（Phoronix，Michael Larabel，2026-09-24）。本文由 LeisureLinux 编译整理并加注解读。
推广
Canonical 今天（2026-09-24）发布 Mir 2.30——这是那个用来自建各种 Wayland shell 的合成器库的最新版本，应用范围从智能镜子一路铺到各类消费设备。这一版最显眼的变化是：构建 Mir 现在明确要求 Rust 编译器，而此前它只是可选项。

译文：2.30 改了什么

  • Rust 成为硬性依赖：Mir 2.30 的 evdev 输入平台代码已改用 Rust。构建选项 MIR_ENABLE_RUST 被移除，构建 Mir 必须始终具备 Rust。
  • 动机是 OS 目标收窄：Mir 现在严格锁定 Ubuntu 26.04 LTS 及更新版本，而该平台上 Rust 是被强制要求的——所以 Rust 可以被安全、无条件地假定存在。
  • 新增 Wayland wl_fixes 协议支持。
  • 修复若干 bug，并带来一批文档改进。
  • 首次随 2.30 文档发布公开路线图。路线图包含：为视频播放使用（显示）硬件 plane、支持完全用 Rust 构建一个基于 Mir 的合成器、稳定 mir-shell Wayland 扩展、设计长期的 Mir 渲染管线、Mir shell 的 systemd 集成，以及安全方面的改进。
  • 版本可从 GitHub 下载：github.com/canonical/mir/releases/tag/v2.30.0。

解读：一次「收窄边界」的版本

1. Mir 早已不是「Ubuntu 的下一代替换」，而是一块合成器库。

Mir 最初的野心是给 Ubuntu 一套自己的显示服务器/合成器栈，去和 X、Wayland 正面对撞。多年演化后，它的真实落点是一个可复用的 Wayland 合成器库——给想要自建 shell 的人（嵌入式、消费电子、数字标牌、智能镜子）提供底座。这一定位决定了它不会去和 GNOME 的 Mutter、KDE 的 KWin 抢桌面默认，而是比它们「更底层、更可裁剪」。

2. Rust 从可选变必需，本质是「把 OS 目标收窄」的连带结果。

看 Phoronix 给的因果链很清楚：Mir 把支持面主动收窄到 Ubuntu 26.04 LTS+，而这个平台上 Rust 本就必备，于是 Rust 从「最好有」变成「一定有」。MIR_ENABLE_RUST 被删，意味着不再为没有 Rust 的环境保留退路。

这是 Ubuntu 生态「Rust 化」浪潮里的一朵浪花。同一批 Phoronix 新闻里：Ubuntu 26.10 把 cp/mv/rm 全线切到 Rust coreutils 完成 100% 迁移；Google 那个「难维护」的 Binder C 驱动也被 Rust 取代。趋势是——在 Ubuntu 的地盘上，Rust 正从「加分项」变成「入场券」。

代价也要说清楚：构建门槛提高了。任何想把 Mir 移植到无 Rust 工具链平台的人，从 2.30 起要么补上 Rust，要么留在旧版。不过对 Mir 而言，这本就「不是目标场景」，所以代价可控。

3. 新增 wl_fixes 是「跟着 Wayland 上游走」的成熟信号。

wl_fixes 是 Wayland 协议体系里用于修补核心协议若干历史设计遗留的一套协议。Mir 跟进它，说明项目在主动对齐 Wayland 上游协议演进，而不是自成一套。对一个「合成器库」来说，协议兼容性就是它的可用度。

4. 首次公开路线图，才是这一版最有信息量的事。

一个项目愿意把「接下来要做什么」摊开写进文档，通常意味着它进入了产品化/长期维护的节奏。看点逐条拆：

  • 用硬件 plane 做视频播放：把视频帧直接送进显示控制器的 overlay plane、绕开合成器全屏重绘——这是嵌入式/媒体设备的省电省 CPU 关键手法，说明 Mir 在认真做「设备上的媒体输出」。
  • 全 Rust 的 Mir 合成器：不只是输入平台用 Rust，而是把整个合成器搬进 Rust。这和「Rust 硬依赖」是一套组合拳。
  • 稳定 mir-shell 扩展：从「能跑」到「第三方可依赖」——只有接口冻结，别人敢把产品压在它上面。
  • 长期渲染管线设计：架构层面的债要提前还，避免渲染路径反复推倒重来。
  • Mir shell 的 systemd 集成：与 Ubuntu 的引导/服务模型对齐，是「和平台长在一起」的做法。
  • 安全改进：对任何要跑在政企/消费终端上的显示栈，这几乎是必选项。
5. 对开发者的现实含义。

如果你在嵌入式或消费设备上自建 Wayland shell，Mir 提供的不是「一套桌面」，而是一块合成器底座 + 一套正在被冻结的 shell 扩展。2.30 之后，用 Mir 意味着接受「Rust 工具链是前提」这一条，换来的是更明确的长期路线与更稳定的扩展面。

一句话收尾：Mir 2.30 不是一次功能大爆炸，而是一次边界收窄——把支持面押在 Ubuntu 26.04+、把构建押在 Rust、把未来押进一份公开路线图。对一个已经「退到幕后当库」的项目来说，这种收窄恰恰是它走向长期主义的信号：先想清楚自己不做谁，再决定自己能做多久。
