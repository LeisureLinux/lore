    DMS 换 Noctalia：niri 桌面壳迁移实录，以及两者的真实差别
    把 Debian 13 + niri 26.04 的桌面壳从 DankMaterialShell 1.6 迁到 Noctalia 5.1 的完整实录。先讲清两者真实差别：DMS 是 Go 主程序（静态编译 71 MB）+ Quickshell(Qt6/QML) 渲染，Noctalia v5 是纯 C++ 直接跑 Wayland + OpenGL ES、零 Qt 零 GTK 依赖（7.7 MB deb）。v4 时代的 Noctalia 曾基于 Quickshell，已废弃。迁移实测踩到三个反直觉的坑：①mako 由 D-Bus 激活而非 systemd unit，pkill 无效，须用用户级 dbus-1/services 覆盖；②真正持有 org.freedesktop.Notifications 的是 DMS 自身而非 mako；③官方 niri.kdl 模板含 mustache 占位符，直接 include 会让 niri 校验失败。附 niri 源码级结论：config 热重载不重跑 spawn-at-startup。最终验证通知接管 / Intel Iris Xe OpenGL ES / 双屏 bar / 中文 / logind 锁屏全部正常，全程未丢窗口。
