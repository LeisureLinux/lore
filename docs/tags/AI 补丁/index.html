    Kernel Report 回归：Jonathan Corbet 在 Kernel Recipes 2026 谈内核社区的「加速变化」
    新闻+背景梳理（非演讲全文翻译，详细内容仅 YouTube 视频）。新闻事实：LWN《The Kernel Report 2026 edition》(2026-09-24)——停办两年后 Corbet 在 Kernel Recipes 2026 讲了更新版 Kernel Report，审视内核社区正发生什么、如何应对一段加速变化期、未来走向，视频在 YouTube。Kernel Recipes 2026(第13届,巴黎,9/21-23,推 corbet 任 patron/教父)；主办方称距 Corbet 上次在 KR 讲 Kernel Report 已十年、距该演讲上次出现在议程已两年。Corbet 是内核文档 maintainer、LWN.net 联合创始人兼执行主编、《Linux Device Drivers 3e》第一作者。演讲摘要原文仅三句：『停办两年后 Kernel Report 回来了。内核开发正经历一段加速变化(a period of accelerated change)的时期。本演讲将审视内核社区正在发生什么、可能走向何方，并着眼于将于 10 月举行的 Maintainers Summit。』背景(均标注公开来源、不归于演讲)：①AI 生成补丁压倒 maintainer——网络子系统 Jakub Kicinski 在 Linux 7.3 pull request 称『我们完全被淹没了』，net/net-next 各合并 632/648 补丁，net-next 三分之一到一半似 AI 驱动的低优先级修复/清理/澄清(Dataconomy/Hardware Busters 2026-08)；②Torvalds 称『新常态』——7.2-rc7 是多年最大 rc6、『我不太高兴这个规模』但『这就是现实：新常态，大量修复，很多是各种 AI 工具审查出来的』，AI 用于审查而非写码、补丁仍由人撰写(The Register/TechRadar 2026-08)；③社区把 AI 规则写进文档——2026-04 落地 coding-assistants.rst，AI 参与需 Assisted-by 标签，AI 不能用 Signed-off-by，提交者承担全部责任(byteiota 2026-08)；④Sashiko AI 审查系统——Google Roman Gushchin 打造、2026-03 发布、用 Gemini 3.1 Pro 审 LKML 补丁，Greg KH 背书，亦在本届 KR 议程(Gushchin 主讲)；⑤Maintainers Summit(10月)是摘要点名落点，呼应内核文档《Linux kernel project continuity》(极端情况如何召集最近一届 Summit 受邀者与 LF TAB 讨论顶层仓库持续管理)；⑥同场议程(《Futex》Rostedt、《DAMOS》Park、《Security in the LLM age》Greg KH、《Rust for Linux》Ojeda、《Swap and Memory Reclaim》Song、《Large scale kernel build testing》Bergmann)本身就是加速变化清单。解读：①该报告价值在 maintainer 视角的年度纵览而非新消息，回归说明社区到了需重新纵览的节点；②2026 最尖锐矛盾是『AI 让产出变快』与『维护带宽固定』的错配——生成补丁成本趋零、审查成本未降；③治理被拉回视野：coding-assistants.rst(责任归属)、Assisted-by/Signed-off-by 区分(法律边界)、项目连续性文档(延续机制)，为『人的责任』建制度；④对工程实践者，上游节奏与规则正在变(AI 署名/审查流程/维护者过载)会向下游传导，跟随 maintainer 关切比追单个 CVE 更能预判摩擦点。
