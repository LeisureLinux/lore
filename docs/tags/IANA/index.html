    内网域名没有一个是安全的：.lan / .local / .home / .corp 的真实状态，以及 ICANN 给出的 .internal
    家用路由器默认给 .lan，mDNS 用 .local，老企业内网挂着 .corp / .home —— 这些名字都没有官方保障。本文用 IANA 特殊用途域名登记表与根服务器实测，厘清六个域名的真实状态：① .local 有 RFC 6762 但只能用于 mDNS，用普通 DNS 配它会让 mDNS 和 DNS 抢答同一名字；② home.arpa 是唯一有 RFC 的普通 DNS 家庭域名，RFC 8375 明确说明放弃 .home 的原因——IETF 管不了根区，无法阻止 .home 被委派；③ .corp / .home / .mail 已被 ICANN 冻结委派（使用量太大），但那是政策决定不是技术保证；④ .lan 最没有保障——既无 IANA 登记，也不在冻结名单，只是恰好还没轮到；⑤ .internal 是 ICANN 2024 年 7 月正式保留的私有用途 TLD，草案承诺 MUST NOT appear in the root zone；⑥ 企业内网最安全的做法是用自己拥有域名的子域（如 ad.example.com），因为委派链在自己手里。附三种真实风险场景（查询泄漏 / 名字碰撞 MitM / 证书冲突）与各场景迁移建议。核心判断：最重要的不是换域名，而是把内网域设为本地权威（unbound static），一步切断泄漏与劫持两条路径。
