    一个布尔值把内网服务变成了公网服务：把通配监听收回内网（socat 桥模式）
    很多服务只给两个选项：只听 127.0.0.1，或听所有网卡（0.0.0.0 / *）。当你想要中间那一档「只听内网」时，它们帮不上忙。本文记录一个通用解法：让服务退回只听 127.0.0.1，再用 socat 在指定的内网地址上补一个口。实测确认三个关键事实：① 写代码里的 httpProxyListenLAN: true 会绑定 *:8888（同时含 IPv4 0.0.0.0 与 IPv6 [::]），在有公网 IPv6 的机器上等于把内网服务直接暴露给整个互联网；② 从二进制提取 JSON tag 确认该服务只有布尔开关，没有「绑定指定地址」选项，且日志字符串里只有 0.0.0.0 和 127.0.0.1 两个硬编码地址；③ bind=<具体内网 IP> 不会产生任何 [::] 监听（对照实验：IPv6 监听数为 0），而 bind=0.0.0.0 会重新暴露，同一端口在不同地址上可共存（方案可行性前提）。改造后：本机与内网均可用，公网 IPv6 不可达。附通配监听审计命令。

    国庆回老家，万物皆隧道：把家里所有服务收敛到只剩一个 SSH 端口
    一次假期前的网络架构改造：把本地 DNS、HTTP 代理、远程桌面、RustDesk、模型网关全部收敛到 127.0.0.1，由一条 SSH 隧道按需拉取。家里那台香橙派对公网只留 22 端口，其余服务一律只听回环。核心洞察：一旦服务只绑 127.0.0.1，就不再需要信任网络——不需要 VLAN、不需要内网 ACL、不需要 VPN，暴露面从一个网段收敛到一个端口。文中记录了 ssh -L 在 Debian 13 / OpenSSH 10.3 上绑不了 IPv4 字面量（需 socat 桥）、启动门禁不能探目标端口（IPv4-only 服务 + IPv6-only 域名会误判）、DNS 自举循环（隧道自己的解析依赖隧道）、UDP 不能直接走 ssh -L（需两端 socat 转换）、以及「一个 DNS 答案服务不了两种网络位置」这个必须在本机 /etc/hosts 解决的位置相关问题。

    systemd 262 正式发布：内嵌兜底 unit、LUO 热更新会话，还带一只「AI 提交金丝雀」
    译介 Phoronix 报道（Michael Larabel，2026-09-22）：systemd 262 正式发布。亮点：①管理器内嵌基础 unit 文件作内存兜底（reboot/shutdown target、systemd-poweroff.service、multi-user.target）；②可编成单文件静态链接 PID1/executor 二进制给极小容器；③NUMAPolicy= 新增 preferred-map / weighted-interleave；④service 新增 LUOSession= 创建 Live Update Orchestrator 会话；⑤systemd-firstboot 支持 headless 无人值守配置；⑥systemd-coredump 支持 Linux 6.17 kernel coredump socket 协议；⑦systemd-homed 新 FSCRYPT 家目录默认 FSCRYPT v2；⑧systemd-cryptenroll 加首次启动注册向导；⑨systemd-vmspawn --coco= 在 SEV-SNP 外新增 Intel TDX；⑩dm-clone boot 集成；⑪AI canary 检测未审查的 AI/LLM 代码贡献。解读：相对 08-26 已发的 rc1 深度解读，正式版真正新增的是 AI canary 与 LUO 收口；AI canary 让「AI 生成+无人审」这一危险组合在贡献门禁显形（类 AI 红队/护栏逻辑）；内嵌兜底 unit+静态 PID1 是最小容器/微 VM/机密计算场景的攻击面收敛，与 Ubuntu 26.10 迁 Rust coreutils 同属「小、静态、自包含」重组潮流；升级动 PID1 须逐条核对 rc1→262 的 breaking changes（TPM 凭据/Type=notify-reload/journalctl -F 等）。

    systemd 262-rc1 发布：嵌入兜底 unit、PID 1 静态容器、TPM/SEV-SNP/TDX 全栈机密计算加码
    systemd 262-rc1 进入测试周期。三类硬改动：(1) 启动 / 容器路径——manager 内嵌 basic.target / multi-user.target 等兜底 unit，PID 1 可构建为单文件静态多调用二进制、专为微型容器而生；(2) 调度 / NUMA——NUMAPolicy= 新增 preferred-many 与 weighted-interleave，service 新增 RestartRandomizedDelaySec= 把同步故障重启风暴抹平，slice 加 ActivatingConcurrencyMax=；(3) 安全 / 机密计算栈——TPM 凭证强制绑 SRK 防 MITM 偷取、cryptenroll 新增 first-boot wizard、cryptsetup 启用 Argon2id 强化 PIN、vmspawn 把 Intel TDX 纳入 --coco=、SEV-SNP 走 initrd /.extra/system_credentials/ 让凭证纳入启动度量。文档侧 ukify --sign-initrd-pcrs、NvPCR 重写为基于 PCR policy、pcrextend 不再依赖 anchor secret、cryptenroll / cryptsetup 走 Varlink API。
