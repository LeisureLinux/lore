AI 程序员独立开发 160 万行代码？Cursor 官方揭秘：多 Agent 协同的数周“长跑”实验

未知日期 AI/Agent 阅读原文（微信）↗

前言\

未来的编程，是否只需要人类下达一个"构建浏览器"的指令，剩下的就交给成百上千个 AI Agent 自动运行数周？

近期，Cursor 团队负责人 Wilson Lin 发布了关于"扩展长时间运行自主编码能力"的研究报告。他们不再满足于 AI 写个简单的脚本，而是让数百个 Agent 并行，处理原本需要人类团队耗时数月的超大规模项目。

今天，我们通过对 Cursor 官方博客的深度拆解，看看 AI 编码已经进化到了什么程度。

一、 核心挑战：为什么 1+1 并不总是大于 2？

目前的 AI Agent 在处理小型任务（如修复 Bug、写单元测试）时表现惊人，但一旦面对数十万行、跨度数周的大型项目，就会陷入瓶颈：

* 视野狭窄： 单个 Agent 很难在脑中构建起整个超大代码库的地图。

* 协作僵局： 多个 Agent 共同协作时，往往会发生"推诿"或"碰撞"。

Cursor 团队在早期尝试了**"平等地位 + 锁机制"，结果发现 Agent 会长时间占用文件锁不释放，导致 20 个 Agent 的效率甚至不如 2 个。而"乐观并发控制"**虽然解决了锁问题，却让 Agent 变得胆小，只敢改动边缘代码，没人敢碰核心逻辑。

二、 突破口：规划者（Planners）与执行者（Workers）的解耦

最终，Cursor 发现了一套高效的协同公式："动态规划 + 专属角色"。

1. 角色分工

* 规划者 (Planners)： 战略家。负责持续探索代码库，拆解任务。它们可以递归地派生出"子规划者"，实现无限深度的任务树。

* 执行者 (Workers)： 战术家。不看全局，只专注完成手头被分配的那个具体函数或文件。完成后提交，由评审 Agent 决定是否通过。

2. 系统重启机制

为了防止 Agent 在长时间运行中产生"思维漂移"，系统会定期进入干净状态重启，从最新的代码库重新扫描。这种**"减法"优于"加法"**的设计策略，让系统异常健壮。

四、 关键实战经验：模型与提示词

Cursor 在实验中总结了几个极其重要的技术细节，值得开发者关注：

* 模型阶梯： GPT-5.2 系列在长时间任务中展现了绝对统治力。它比 Opus 4.5 更专注，更少"走捷径"。

* 术业有专攻： 并不是所有任务都用最贵的模型。规划者需要更强的推理能力（用 GPT-5.2），而一些简单的 Worker 任务可以由更轻量的模型完成。

* Prompt 为王： 协作是否流畅、Agent 是否会陷入死循环，80% 取决于精心设计的提示词工程。

五、 未来展望：Agent 时代已来

虽然目前还存在 Planner 唤醒、运行成本等难题，但 Cursor 的实验证明了：通过堆叠 Agent 确实可以线性扩展自主编码能力。

这些实验中的技术，正在逐步合入我们每天使用的 Cursor 产品中。也许不久后，你在侧边栏输入的不再是一个指令，而是一个"产品路线图"。
