Agmente：自托管玩家的“最后一块拼图

未知日期 Linux/运维 阅读原文（微信）↗

在自托管的数字世界里，我们部署了 Proxmox VE、Docker、Uptime Kuma 等一系列服务。但痛点在于：我们缺乏一个原生、轻量且具备高度审美聚合能力的移动端入口。

rebornix/agmente 的出现，本质上是为散落在内网的各项服务提供了一个 Unified Dashboard（统一仪表盘）。

{#section path-to-node="5"}

一、 项目的核心意义：为什么要用它？

  1. 消除"Web UI 疲劳"：无需频繁在手机浏览器中缩放 PVE 或 Home Assistant 臃肿的网页版。

  2. 极简主义运维：通过 API 驱动，只抓取核心指标（CPU、内存、服务状态），实现"一眼即知"。

  3. 开发者基因：作为 VS Code 团队成员的作品，它在交互逻辑上追求极速响应，拒绝多余的动画与冗余数据。

{#section-1 path-to-node="8"}

二、 系统架构：它是如何工作的？

理解 Agmente 的工作原理是部署的第一步。它并非传统的 Client-Server 架构，而是一个 API Aggregator（API 聚合器）。

  • 数据源层：你的 Linux 服务器、PVE 宿主机或 Uptime Kuma 实例。

  • 传输层：通过 HTTPS/REST API 进行通信。

  • 展示层：Agmente 移动端通过读取配置文件，动态渲染 UI 组件。

{#section-2 path-to-node="12"}

三、 针对 Self-host 读者的部署全流程

对于习惯了 Linux 环境的读者，部署 Agmente 并不意味着要改写代码，而是要完成**"数据供给"与"端点连接"**。

1. 环境准备：数据源的暴露

Agmente 需要"喂"数据。你需要在服务器端准备好以下接口之一：

  • Uptime Kuma API：用于获取服务的 Up/Down 状态。

  • Prometheus / Netdata：如果你需要更深层的系统负载（Load Average）数据。

  • Custom JSON Endpoint：如果你是硬核玩家，可以写一个简单的 Python 脚本，将 df -h 或 free -m 的结果封装成 JSON。

2. 通讯隧道（Security First）

由于自托管设备通常在内网，严禁直接将 API 暴露在公网。建议方案：

  • WireGuard / Tailscale：手机端开启 VPN，直接通过内网 IP 与 Agmente 通信。

  • Cloudflare Tunnel：配合 Access 鉴权，实现安全的公网安全访问。

3. 客户端配置逻辑

目前该项目主要通过配置文件驱动。你需要：

  • 定义 Endpoint：指向你服务器的 API 地址。

  • 配置 Token：在 Header 中加入校验字段，确保数据传输的 Privacy & Security。

{#section-3 path-to-node="24"}

四、 技术进阶：定制你的 Dashboard

Agmente 的强大之处在于其 JSON-driven UI。你可以像配置 settings.json 一样定义你的手机监控界面：

{
"widgets": [
{
"type": "status_card",
"title": "Home Lab Node 1",
"endpoint": "https://pve.local/api2/json/..."
},
{
"type": "uptime_chart",
"target": "Personal Blog"
}
]
}
