Redox OS 2026 年中盘点：用 Rust 写的微内核操作系统走到哪了

用 Rust 写的微内核 OS ，从调度器到桌面到 RISC-V 同时向前冲——2026 是它认真的一年 。——Redox OS / Phoronix, 2026.06

7 月初，Phoronix 把 Redox OS 2026 年 6 月的开发进展做了一次集中盘点。这不是版本号式的"做了什么什么功能"，而是 一个用 Rust 写的、从零搭建的 Unix-like 微内核操作系统 ，在桌面、调度器、驱动策略、RISC-V 几个方向同时往前冲的真实进展。

01

TRANSLATION

翻译要点：Phoronix 这一篇盘了什么

Redox OS 的 6 月份动态被 Phoronix 浓缩在下面几件事上：

内核层面

新调度器 EEVDF

替代了传统的 Round Robin。Linux 主线在内核 6.6 时代也合并了 EEVDF（由 Peter Zijlstra 推动），Redox 是把这一调度算法论移植到了自己的微内核上。

RedoxFS 性能优化

I/O 事件等待延迟大幅下降，加入了 inode caching（灵感来自 ZFS），整体应用运行效率提高。

死锁检测 + 多线程可靠性

同步增强。

用户态 / 桌面环境

Xfce 移植（未达可用）

Xfce 移植成功，但还未达到可用级别——只是个底子。

COSMIC Monitor

移植成功（System76 的 COSMIC 桌面系列组件），Redox 上首个图形化系统监视器。

Orbital 桌面

新增 GTK3 后端，开始支持分数缩放（fractional scaling）和 USB 手柄。

图形栈

通过 Mesa3D 的 Lavapipe 软光栅，Redox 上 首次跑通了 Vulkan 软件路径 。硬件 GPU 加速还没到位，但 API 层面 已经能"运转" 了。

RISC-V 进展

  • 真机启动持续改进。
  • 上线了软件包浏览 Web UI，覆盖 x86-64、i586、ARM64 (aarch64)、RISC-V (riscv64gc) 四种架构。

驱动策略：Linux-in-QEMU

新策略公布：不再无脑给每个硬件写原生驱动，而是在 QEMU 里跑一个精简版 Linux，由它驱动稀有/老硬件。

用户态生态

  • rustc + Cargo 可在 Redox 上原生编译 Rust CLI/TUI 程序（2026·01 里程碑）。
  • 移植：tmux、NodeJS、Tcl、Flycast（SEGA Dreamcast 模拟器）。
  • bootloader 增加文本编辑器（修改启动参数）。
  • 登录管理器支持电源管理菜单与键盘布局切换。
  • 首次"在 Redox 里提交 Redox 代码"——开发者已经能自举式开发。

02

EEVDF SCHEDULER

内核解读：EEVDF 调度器换上了"最公平优先"

2.1 Redox 之前用什么

Redox 一直用教科书级别的 Round Robin ：每个就绪线程按固定时间片轮转，简单但 不区分任务紧迫度——交互响应、长计算任务、I/O 等待都被一视同仁地"轮流上场"。对桌面 OS 来说，这意味着 鼠标点击的响应被一个疯狂的压缩任务阻塞 的可能性是有的。

2.2 EEVDF 是什么

EEVDF（Earliest Eligible Virtual Deadline First） 是一种 基于"最早到期虚拟截止时间"优先 的调度算法——- 每个任务被分配一个虚拟截止时间（virtual deadline） - 调度器总是优先让虚拟截止时间最早的就绪任务先跑 - 同时保证不公平时间（lag）补偿：被调度器忽视了一段时间的任务，能抢回运行权 - 本质上是把"哪个任务最紧迫"变成"哪个任务最该先跑"

这个机制在 Linux 6.6（2023）合并后已经用一年多了，Redox 在 2026 年把它引入自己的微内核——等于在调度理论上向主流接轨 。

2.3 为什么这件事重要

微内核的任务调度难度比宏内核大。微内核把大部分服务搬到了用户态进程里， 调度决策影响整个系统的"对话质量" 。换上一个理论上更公平、响应特性更可预测的调度器，等于让 Redox 的"操作系统底层对话"更顺畅。

对于桌面使用场景，鼠标点击后到出现反应的时间分布会更窄；对于服务端场景，长尾请求的延迟也会变短。

03

DESKTOP STRATEGY

桌面环境：两条腿走路的"Orbital + COSMIC"

Redox 的桌面路线不是单一路径，而是 两条互补路线 ：

3.1 Orbital：自研组件的根

Orbital 是 Redox 的官方桌面外壳，同时承担 显示服务器 / 窗口管理器 / 合成器 三重身份。它不是 Wayland 的复刻，也不是 X11 的复刻——是一个 专为 Redox 设计的全新 GUI 栈 。

6 月 Orbital 的进展：

  • GTK3 后端：让 GTK3 应用能在 Orbital 下运行——意味着 GIMP、Inkscape、GNOME 系编辑器这一大坨 Linux 桌面主力应用都有机会直接运行
  • 分数缩放支持：高 DPI 屏的痛点开始被解决
  • 部分窗口像素更新优化：UI 性能提升

3.2 COSMIC：借 System76 的肩膀

COSMIC 是 System76（Pop!_OS 母公司）主导开发的下一代 Linux 桌面环境， 同样用 Rust 写 。Redox 与 COSMIC 是 天然盟友——同样的编程语言、类似的安全模型、类似的下一代桌面形态。

6 月的进展： COSMIC Monitor （系统监视器应用）成功移植到 Redox。这是 Redox 上 第一个图形化系统监视器 ，让用户在桌面上看见 CPU/内存/IO 占用——以前只能命令行跑 top。

在 COSMIC compositor 已经在 Redox 上作为 Winit 窗口跑通（2026·03 PoC）的前提下，COSMIC Settings 也在迁移中。Redox 用户未来能拿到"借来的下一代桌面"。

3.3 Xfce 为什么也被移植

Xfce 是成熟的 X11 桌面环境。Redox 上跑 Xfce 不是为了"主要桌面"，而是为了 成熟 X11 体验 和 兼容老应用 。它现在还 未达到可用 等级——是个起点。

04

VULKAN / GRAPHICS

图形栈：通过 Lavapipe"先跑起来再说"

4.1 Vulkan 首次跑通

Redox 在 3 月份通过 Mesa3D 的 Lavapipe 软光栅（CPU 跑 Vulkan 指令的 reference 实现）跑通了 Vulkan 软件路径——第一个 确定性的"能用 Vulkan API" 里程碑。

别小看这一步——Vulkan 是 现代显式 API ，应用层和驱动层的契约复杂。Lavapipe 让 Redox 上能验证：

  • Vulkan loader → driver 的调用链
  • Mesa 编译能 cross-compile 到 Redox
  • Redox 内核态/用户态 IPC 能满足 Vulkan 的高频内存映射需求

这是"硬件 GPU 加速"的前置条件：先把协议跑通，硬件驱动接入是后一步。

4.2 距离真正 GPU 加速还有多远

硬件 GPU 驱动仍然在排队。当前可见的进展：

  • Intel 图形驱动已经做了 page flipping 与 plane 支持，这是基础显示输出的最低要求
  • USB 手柄等 HID 类驱动在进步

总的原则：先把"显示输出"做对，再考虑"3D 性能"。Redox 当前桌面体验距离"流畅跑 Blender"还远，但显示服务器层面的里程碑已经踩到。

05

LINUX-IN-QEMU

驱动策略：Linux-in-QEMU 的智慧

5.1 核心困境

微内核 OS 最大的痛点是 驱动覆盖 。Linux 在二十多年里积累了 上万种硬件驱动 ，任何想取代 Linux 的系统都要么花二十年重写一遍，要么找出别的办法。

Redox 选了第三条路：承认现实，借助 Linux。

5.2 Linux-in-QEMU 方案

这个策略的核心：

  1. QEMU（本身正被移植到 Redox）虚拟化出一个精简版 Linux实例
  2. Linux 实例负责驱动稀有/老硬件
  3. Redox 与 Linux 之间的 IPC 接口被设计成严格隔离的沙箱
  4. Linux 内核的崩溃不会拖垮 Redox 本体——因为微内核设计下驱动失败是可恢复的

这不是"装个虚拟机"，而是 把 Linux 当一层"驱动运行时" 嵌进 Redox。它的精妙之处是 承认生态边界——搞硬件支持就让 Linux 搞，Redox 专心做自己独特的事。

5.3 这条路的安全约束

要注意这不是"放弃安全"：

  • 红线：Redox 的 capability-based 安全模型不变
  • Linux-in-QEMU 实例只能访问 Redox 严格授权的硬件资源
  • 任何驱动崩溃只影响 QEMU 实例，Redox 主内核与用户进程不受牵连

这是一个务实的妥协：在不丢掉核心价值（安全、能力隔离）的前提下，覆盖了它自己写不完的硬件广度。

06

ROADMAP

路线图：2026 年的三条路径

Redox 在 2025——2026 路线图里把发展分成 三条并行的轨道 ：

轨道 目标用户 当前进展
Hosted Web Services Runtime Web 服务部署 rustc/Cargo 已可用
Bare-Metal Server 服务器直接运行 EEVDF 调度器 + 性能优化已上
Desktop Environment 桌面用户 Orbital + COSMIC + Xfce 三轨并行

这种 多线并进 避免了"做一个方向就要推迟其他方向"的陷阱——每条线都可以独立里程碑、独立演示。

RISC-V 这一条独立加成

RISC-V 是 2026 年应用处理器硅的一个重要发力点。Redox 通过 riscv64gc 已经能启动真机，加上软件包浏览 Web UI 覆盖四种架构， 让任何 RISC-V 板子都可能直接跑 Redox——这是一个显著的开源操作系统红利。

07

SELF-HOSTING

自举开发：Rust 在 Rust 上写 Rust

6 月份最容易被忽视、但意义最深远的一点是：

 「Redox 开发者现在可以在 Redox 内提交 Redox 代码。」

听起来像套娃，但对一个从零起步的 OS 而言，这是 开发流水线"自举" 的标志——意味着：

  • Redox 的工具链在 Redox 上已经够用（rustc 在 Redox 跑通，Git 工具链也在）
  • Redox 已经不再是"在 Linux 上开发 Redox"的状态
  • 长期看，Redox 团队不再被 Linux 的发行节奏绑定

这有点像 Linux 早期（1990 年代初）Linus 第一次"在 Linux 编译 Linux 内核"的瞬间——是操作系统独立性的关键里程碑。

THE END

风险与限制：红字写下来的现实

把 Redox 当 Linux 替代还差得远。6 月份的状态对应以下几点：

  1. 桌面环境未达可用：Xfce 还在端口阶段，Orbital + COSMIC 有 PoC 但非"日常使用"水平
  2. Vulkan 是软件路径：没有 GPU 硬件加速，3D 性能 = 没有性能
  3. Linux-in-QEMU 启动开销：每多一层虚拟化都增加资源消耗，要权衡\"覆盖广度 vs 性能\"
  4. 包生态还在追赶：Rust TUI 工具能编、能跑，但 Web 浏览器、专业 IDE、视频编辑这些"Linux 桌面主力"还在路上
  5. RISC-V 板子启动不等于"日常使用"：能否在 VisionFive 2、StarFive 等真实开发板上完成日常工作流，是另一个问题

💡 结论：Redox 是"2026 年最值得严肃对待的微内核 OS"，但它仍然是实验性的，不要当作日常生产 OS。

这像极了 1992 年的 Linux：认真，但别拿它上线生产。

📖 名词解释

Redox OS：一套 Rust 写的、Unix-like、微内核架构的操作系统，从引导到用户态全面自研。

Microkernel（微内核）：操作系统架构的一种，只在内核态保留最小化功能（IPC、调度、中断），把驱动、文件系统、网络协议栈等挪到用户态进程。

Unix-like：在设计哲学上遵循 Unix 传统——单一职责的小工具、可组合的管道、文件系统作为一等公民。

Orbital：Redox 自研的桌面环境，同时承担显示服务器、窗口管理器、合成器三重职责。

COSMIC：System76 主导用 Rust 写的下一代 Linux 桌面环境，Redox 借鉴其组件。

Xfce：成熟的 X11 桌面环境，Redox 已移植但未达可用级别。

EEVDF（Earliest Eligible Virtual Deadline First）：基于"最早到期虚拟截止时间"优先的调度算法。

Round Robin：经典时间片轮转调度算法，所有任务按固定窗口轮流上场，不区分任务紧迫度。

RedoxFS：Redox 自研的文件系统，受 ZFS 启发。

inode caching：将节点元信息放在内存缓存中以加速文件系统访问。

Capability-based Security：把权限封装成不可伪造 token 的安全模型。

Linux-in-QEMU：把精简版 Linux 跑在 QEMU 内，由 Linux 驱动稀有硬件，Redox 通过沙箱接口调用。

QEMU：开源硬件虚拟化 / 模拟器。

Winit：Rust 生态的窗口创建抽象层，被 COSMIC compositor 用来在 Redox 上 PoC。

Lavapipe：Mesa3D 内的 Vulkan 软光栅（CPU 实现）。

Mesa3D：开源图形驱动框架集合，包含多个开源 GPU 驱动、Vulkan 实现、OpenGL 实现。

Vulkan：新一代显式、低开销图形 / 计算 API。

GTK3：跨平台 GUI 工具包。

page flipping / plane support：显示控制器里"交换前后缓冲区"与"多图层合成"的能力。

fractional scaling：非整数倍的 DPI 缩放（如 125%、150%）。

riscv64gc：RISC-V 64 位 General Compute 配置文件。

Self-hosting（自举）：操作系统能编译自身的能力——Linux 在 1991——1992 完成，Redox 在 2026 完成。

Sandbox capability：把外部不可信代码放在严格隔离环境中运行。

Flycast：开源的 Sega Dreamcast 模拟器。

**rustc / Cargo**：Rust 编译器与包管理器。
