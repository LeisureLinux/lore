—— Phoronix 对 Samba 4.25 的报道（2026-09-26）

Samba 4.25（连接 Linux/Windows 的文件与打印共享服务最新稳定版）带来实验性 SMB3 持久句柄：客户端在服务器重启后能保留有效文件句柄，实现「不间断文件访问」。代价是每次操作双份存储，性能开销显著。另有新 Ceph RGW VFS 模块、JSON 审计改进与默认 AES 域加密。

01

PERSISTENT

核心：实验性 SMB3 Persistent Handles

这是面向透明故障转移（transparent failover）的关键能力。有了持久句柄，SMB 客户端能在服务器重启或宕机后重新连接，并保留此前持有的有效文件句柄——即不间断的文件访问。

代价很直接：每个 open/update/lease/close 操作都要做双份存储（double storage），因此带来「significant」性能成本。Phoronix 定性为实验性——默认未必开启，生产需评估。

02

OTHER

其他主要变更

1. 新的 Ceph RGW VFS 模块

4.25 新增 Ceph Object Gateway（RGW）VFS 模块，可把 Ceph 对象网关的 bucket 直接以 SMB 共享形式导出——把对象存储挂进 SMB 世界。

2. JSON 审计日志改进

审计日志（audit logging）的 JSON 输出增强，便于日志采集与 SIEM 接入。

3. 域加密类型默认改为 AES

域相关加密类型默认改为 AES，跟上现代 Kerberos 加密套件基线。

4. 其他

随发布说明一并带来若干常规更新，完整清单见 Samba.org 的 v4.25 release notes。

03

WHY

解读：为什么值得记

1. 持久句柄是「高可用 SMB」拼图的一块

真正的透明故障转移需要服务端支持持久句柄 + 底层共享存储 + 集群故障切换协同。Samba 补上了「句柄在故障后仍有效」这个前提，但双份存储的开销提示：它解决的是可用性，不是零成本。

2. Ceph RGW 模块把对象与文件打通

对已经跑 Ceph 的团队，能直接用 SMB 把对象 bucket 暴露给 Windows 客户端，省掉一层网关节点。

3. 默认 AES 是安全基线收敛

与业界把 Kerberos 加密往 AES 收的节奏一致，减少弱加密类型暴露面。

Samba 常被忽略，却是「Linux 服务器 ↔ Windows 客户端」文件共享事实上的桥梁；持久句柄 + Ceph 模块显示它在往高可用 + 对象存储融合方向演进。
