「文件名 + 时序」本身就构成足够强的信号——足以从键盘一路还原到你访问的网站。

—— 释读 Graz 理工大学《文件通知攻击》（CCS 2026）

现代操作系统都内置了监控文件系统事件的子系统：Linux inotify、Windows ReadDirectoryChangesW、macOS FSEvents。任意有读权限的进程都能订阅这些事件。而这篇论文证明：它们正在泄漏你的一举一动——首个针对三大系统的通用「文件通知模板攻击」。

01

HOW

译文：攻击怎么做的

攻击分两阶段。模板化（templating）：攻击者控制的离线阶段，半自动扫描「用户活动 ↔ 文件操作事件」之间的因果泄漏——覆盖终端命令、键盘鼠标输入、浏览网页、Web 服务器、打印、跑 VM/容器、改蓝牙/网络/VPN 设置、USB 交互。

效率是关键：单次活动过程中，监控整个系统文件系统上的所有文件事件——耗时由活动本身决定，而非搜索空间，因为攻击者直接把操作系统当预言机（oracle）。攻击阶段再用模板窥探，CPU 开销最高仅 0.21%，时间分辨率 0.2–11.5 ms。

·

Linux：仅用 /dev 中 2 个文件就能做本地/远程击键时序；用 /usr 中 1448 个文件就能做网站指纹

02

RESULTS

译文：各平台上的攻击结果

·

Linux：本地与远程 SSH 击键时序 F1 93.1%–100%（7 用户，66% 按键在 1ms 内）；KDE Plasma 6（Wayland）认证 UI 覆写攻击；前 100 网站指纹 F1 87.9%

·

Android（基于 Linux）：发现新非特权原语，能揭示应用无法访问的、受权限保护的文件是否存在（如 WhatsApp 使用）

·

Windows（最严重）：任意非特权用户即使对目录无读权限，也能泄漏所有文件的完整路径（如用户主目录），仅一次扫描对前 1000 网站指纹 F1 97.8%

·

macOS：泄漏最少，但仍足以监控特定应用启动与交互

披露：2025-10 负责任披露给 Linux/Windows/macOS/KDE，均承认，Linux 已部署部分补丁；微软称该「损害隐私的、未文档化的行为」是 by-design，辩解只暴露文件名与路径、不暴露内容。

03

WHY

解读：为什么这篇论文重要

1.「文件名 + 时序」作为侧信道，最反直觉也最致命

传统侧信道（缓存、功耗、时序）大多要特殊硬件或微架构知识。这篇攻击完全不需要特殊硬件，只用操作系统公开提供的文件监控 API——任何普通进程都有权调用。它利用的是两类「看似无害」的元数据：哪些文件被访问了、什么时候被访问。而正是这两样，让攻击者能重建你按了键、你在打字、你打开了哪个网站、你在跑什么容器。

2. Linux 的泄漏点，暴露「公开可读目录」这个被忽视的设计面

论文最有工程含义的细节是 `/dev`：一台测试机上 /dev 有 278 个不可读文件，却都能触发通知。因为父目录公开可读，非特权用户即使读不了 syslog 本身，也能监控 /var/log 目录、收到目录内所有文件的通知——即「不可读文件绕过」。

·

/dev/input：键盘/鼠标触发通知 → 击键时序（每次按键两个通知 key down/up），访问模式还能区分触摸板（密集突发）与键盘（零星访问）

·

/dev/snd、/dev/bus/usb、/dev/tun：分别泄漏音频设置、USB 插拔、VPN 激活

·

/usr/share：KDE 搜索每次按键都触发事件；Firefox 浏览不同网站访问不同字体文件 → 网站指纹

「目录可读」不等于「目录内容安全」——尤其当目录里混有敏感文件时。这是系统/发行版设计者该记住的一条。

3. Windows 的 by-design 回应，是「结构性风险」而非「补丁遗漏」

Windows 上「非特权用户可泄漏所有文件完整路径、即使无读权限」，微软回应是 by-design、辩解「只暴露文件名路径、不暴露内容」。但文件名与路径本身就是敏感信息——它足以让攻击者对前 1000 网站做 97.8% F1 的指纹识别。当厂商把元数据泄漏定性为「设计如此」，就意味着不会有 CVE、不会有补丁、不会有升级提醒——它从「可修复的 bug」变成「必须靠架构缓解的既成事实」。这正是安全工程最棘手的一类问题：它不是错误，而是特性。

4. 对普通用户的现实意义

在多用户 Linux/Windows 主机上（共享服务器、多用户工作站），一个低权限账户可能正在被动窥探你的键盘时序、网站访问、容器活动。单用户桌面受影响较小（攻击需要「第二个本地用户代码执行」），但一旦有低权限服务被攻陷（systemd 下服务常以非特权用户运行，如 XZ Utils 事件），这条通道就成了后门式情报来源。Linux 已有部分补丁，Windows 的 by-design 行为短期不会变。

这篇论文的价值，不是发现了一个「可被修掉的 bug」，而是揭示了一类结构性侧信道——操作系统把「文件事件」开放给任意非特权进程，而文件名、路径与时序本身就构成足够强的信号。当厂商把这类元数据泄漏称为「设计如此」时，能缓解它的就不是补丁，而是权限模型和 API 设计——问题被从「运维层」提升到了「操作系统架构层」。
