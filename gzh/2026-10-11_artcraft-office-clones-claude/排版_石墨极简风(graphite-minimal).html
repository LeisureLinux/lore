这是我认为最该被引用的部分，因为它和「AI 奇迹」的叙事完全相反。以下全部来自 `gridcraft/ROADMAP.md` 的原文（最后审阅 2026-10-10）。

GridCraft 的官方自评

功能区目录：258 / 290（89.0%）（实测）

·

工作表函数：501 / 523（95.8%），其中 492 个可用（94.1%）

·

功能广度（加权）：约 75%

·

·

主流从业者 / 基础用户：约 50% / 约 63%

注意最后一行的工作量单位：「Opus 5.5 agent-hours」。这是一个很有意思的信号：这个项目把「Claude 代理的运行时间」当作工程量的计量单位写进了正式路线图。

为什么它自评还是 alpha（原文列出的具体阻断项）

**为什么是 alpha**：六个核心工作流在 macOS 上端到端通过（**打开 XLSX、输入公式与数据、格式化、排序与筛选、图表、数据透视、打印到 PDF、另存为 XLSX**），**但用户在实际文件上仍会撞到阻断性的缺口**：**100 MB 的工作簿打不开**（issue #175）；**没有 `.xls` 支持**（#121）；**阿拉伯文和天城文没有做字形整形**（中文文本在 #142 中仍被报告）；**图表在往返保存后丢失类型和选项**；**而且「还没有人确认过 Excel 能无修复提示地打开我们的输出」，跨越一个真实的测试语料库。**

最后那一条最值得停一下：它把「兼容性」的标准定在了「对方能不能无提示地打开」这个可证伪的判据上，并且诚实地承认这个验证还没做。对比一下多数 AI 项目的宣传口径（「支持 DOCX/XLSX/PPTX」），这个项目的口径是「核心工作流能跑通，但实际文件会撞到这几个具体问题，而且往返兼容性尚未验证」。

按维度的分解：缺口分布得极不均匀

·

功能约 59%（广度约 75%）· UI/UX 保真度约 55% · 文件格式约 50%

·

性能约 35% · 稳定性约 60% · 本地化约 10%（功能区 5 种语言，但要花 100–165 小时，是除功能外最大单项）

·

硬件约 40% · 平台约 80%（无 iOS/Android；在 Linux、BSD、RISC-V 上领先）

·

生态约 10%（VBA 明确不在范围内）· AI 功能约 15%（「代理控制很强；没有应用内助手」）

三个有信息量的项：① 本地化只有 10% 但要花 100–165 小时，符合直觉但常被忽略；② 生态只有 10%，VBA 明确不在范围内，这是对 Excel 替代品最致命的定位问题；③ 「AI 功能 15%」这行的备注最耐读：「代理控制很强；没有应用内助手」，也就是说它把 AI 放在「外部代理可以控制应用」这个位置，而不是「应用内置一个聊天框」。

WordCraft 的自评与一次估算修正

功能区/菜单目录 402 / 434（92.6%）（实测）、功能广度约 80%、「可用于实际工作」约 60%、到 beta 还需约 150–230 个代理小时。

而它的 ROADMAP 里还记录了上一轮估算被修正的过程：2026-10-07 的数字（目录 89%、功能深度约 65%、到完全对等约 215 小时）被重新测量了。目录和函数计数保持或上升；深度和小时数变动是因为新证据：仓库头五天里用户和贡献者提了 82 个 issue，以及旧估算漏掉的范围（本地化、遗留的 .xls、Power Query 与数据模型、协作、移动端、AI）。连这个项目的成本估算，都是一边做一边修正的。

03

CLAUDE

真正值钱的东西：CLAUDE.md

这是我读这批仓库最大的收获。 GridCraft、WordCraft、DeckCraft 每个仓库里都有 `CLAUDE.md` 和 `AGENTS.md`。它们不是使用说明，而是一份给 AI 代理的施工规程。

① clean-room 边界：写得像法律条款

**Clean-room。** 开发机上装了 Microsoft Excel，可以**黑盒观察**它：运行它、用合成工作簿操作它的 UI、**按窗口 id 截图**。**绝不读取、反汇编或复制 Office 包里的任何内容，绝不提交由 Excel 产生的文件，绝不复制 GPL/AGPL/LGPL 代码（LibreOffice、Gnumeric……）。函数行为来自公开文档和观察。**

而 WordCraft 那版把资产规则写得更细：「绝不复制、描摹、截图裁剪或重新创作来自 Microsoft Word/Office 或任何 Microsoft、Adobe、Avid 或 Autodesk 产品的图标、图像、模板、主题、剪贴画、字体、光标、音效或任何其他资产。哪怕『临时』也不行。」 而且每个资产必须在 `ATTRIBUTION.md` 里有一行，CI 检查不通过就失败；优先在代码里画出来；专有字体（Calibri、Aptos、Cambria）用系统字体或度量兼容的开源替代渲染，绝不打包。

这几条的工程价值很高，理由有三：① 它把「clean-room」从一句口号变成了可执行的检查（CI 强制 ATTRIBUTION.md 有对应行）；② 它明确了「可以做什么」（黑盒观察、按窗口 id 截图、公开规范），而不只是「不许做什么」，这很重要，因为没有正面清单的禁令会让代理过度保守或偷偷绕过；③ 它点名了具体项目（LibreOffice、Gnumeric、AbiWord、pandoc），明确划出了与 GPL 系的法律距离。

② 「Never crash」：把代码质量写成硬规则

「人们把他们的数字托付给 GridCraft；一次崩溃就丢了他们的工作。这一点优先于功能开发。」 然后是可执行的规则：非测试代码中不许 panic（不许 unwrap()、expect()、panic!、todo!()、unimplemented!()）；不许 `unsafe`；错误是 `Result`；「来自输入的数字是敌意的」（用 get() 而不是索引，限制由输入决定大小的分配，点名 REPT、SEQUENCE、整列引用）；限制递归；每个崩溃修复都带回归测试；用 `#![deny(clippy::unwrap_used, ...)]` 编译期强制。

**最后一道防线**：`Session::execute` 捕获逃逸的 panic 并恢复工作簿。**这是安全网，不是许可。**

这一段是整份文档里技术上最扎实的部分：它区分了「安全网」和「许可」；它把「输入是敌意的」写成了规则并点名具体的攻击面（表格炸弹）；它用 Rust 的 lint 把它变成编译期强制，而不是靠人记住。顺带一个观察：当人是主要开发者时，这种规则通常写在团队 wiki 里然后没人看；当代理是主要开发者时，规则必须写成机器可检查的形式，否则每次会话都要重新教。AI 参与开发这件事，反而逼出了更严格、更可执行的工程规范。

③ 「一切皆命令」：一个决定解决三个问题

**一切皆命令。** 用户可见的行为 = 一个命令（id、label、功能区路径、快捷键、参数文档、`enabled`、`run`）+ 测试。**id 跟随 Excel 的功能区**（`home.bold`、`insert.chart`、`data.sortAscending`）加上原语（`cell.set`、`selection.set`、`range.setValues`）。**控制通道、CLI 和 MCP 都能触达所有命令。** **程序化调用绝不打开对话框**：空参数的命令按默认值运行或返回错误；只有菜单式调用才打开对话框。

这个决定我认为是整批设计里最聪明的一处，因为它一举解决三个问题：① 可测试性（每个 UI 动作都是可单独调用的命令，能脚本化测试、能模糊测试）；② 可被代理控制（MCP / CLI / 控制通道共享同一套命令，代理不需要模拟点击）；③ 权限与安全的可审计性（命令是有限的、有名字的、有参数文档的集合，比「任意 UI 操作」更容易施加策略）。

这也解释了我前面看到的那奇怪一行：「AI 功能 15%（代理控制很强；没有应用内助手）」。它没有跟风做一个内置聊天框，而是把整个应用做成「可被外部代理精确驱动」的形式。 文档里还给了具体的驱动方式（向控制端口发 JSON 行执行命令、然后截图），以及一个特别值得学的做法：「做 UI 工作时要看结果（快照 PNG），并与观察记录对比」，这是把「视觉验证」也纳入了自动化循环。

④ 给并行代理准备的工程细节

文档里还有几条只会在「多个代理并行工作」时才有意义的规则：每个代理用独立的 `CARGO_TARGET_DIR`；只编辑你拥有的 crate；用完删掉你的 target 目录；一次提交一个任务 id（例如 M2.1: borders gallery）。而 `plan/` 目录是 gitignored 的（含任务、状态、observed-ui.md 的实测观察），这意味着「给代理的上下文」和「公开的代码」是分离的。

04

LEGAL

那个法律选择，以及我的判断

为什么偏偏禁 GPL

这三个应用用 MIT/Apache-2.0 发布，而 `CLAUDE.md` 明确禁止复制 GPL/AGPL/LGPL 代码，并点名了 LibreOffice 与 Gnumeric。这个组合不是偶然的。 现有的开源 Office 替代品（LibreOffice）是 MPL/LGPL 系的，如果这个项目的代码里混入了 LibreOffice 的实现，它就不能用 MIT/Apache-2.0 发布，整个「随便用、随便商用」的卖点就没了。所以它选择了更难的路：从公开规范（ECMA-376 / ISO 29500、RTF 规范、ODF 1.3）重建实现，再加上对竞品软件的黑盒观察。

这条路的价值在于：它产出的东西在法律上是可以被商业采用的。 企业法务对 GPL 系代码有天然的顾虑，而 MIT/Apache-2.0 几乎没有这个摩擦。但代价也是真实的：如果复用 LibreOffice 的代码，你有 20 多年的格式兼容积累；如果 clean-room 重建，格式兼容性的长尾只能自己踩，而这条长尾极长。所以那个「没人确认过 Excel 能无修复提示打开我们的输出」的缺口，不是懒惰，而是这条路的固有代价。我认为这是理解整个项目最重要的一把钥匙：它的 50% 不是「AI 做得不够好」，而是「选了最难的法律路线后，长尾成本的真实呈现」。

一个我无法解释的空白

`CLAUDE.md` 反复引用一个叫 `craftrules` 的仓库作为共享标准的权威来源（standards/never-crash.md、standards/fonts.md、standards/test-corpora.md 等）。但我实测：`storytold/craftrules` 返回 404，它的 README 也是 404。也就是说这个仓库没有公开。

这个空白和我昨天写的那篇形成了一个呼应：Veda 完全没有 AI 使用声明，但它的代码来源是个空白；ArtCraft 极其详细地写了 AI 规程，但共享标准的仓库不公开。 我不做过度解读（可能私有、可能还没建、可能准备后续公开），但它带来的实际影响是明确的：`CLAUDE.md` 里最关键的几条规范的权威文本，在一个我看不到的地方。 而对读者来说，实际可用的仍然是每个仓库里那份 `CLAUDE.md`，它已经把核心边界写清楚了。

给它现在的实用定位

·

个人，想找不订阅的表格/文档工具：值得装来试（功能广度 75%、函数 95.8%，日常够用，界面接近 Excel）

·

Linux 桌面用户：值得关注（原生 Rust + 原生 XLSX 格式，不是 Wine 也不是网页套壳）

·

想用代理自动化文档处理：这是它最强的卖点（MCP + CLI + 「一切皆命令」）

·

企业，有 VBA 宏和复杂模板：不要替换（VBA 不在范围、往返兼容未验证、本地化 10%、成熟度 alpha）

·

需要审计供应链与许可：MIT/Apache-2.0 + clean-room 规则是加分项，但要知道它建仓 5 天、alpha 阶段

一条通用建议：如果你要试，别拿唯一的一份重要文件试。 拿副本，并且存成新文件而不是覆盖原文件（因为往返兼容性尚未验证）。这不是对它能力的怀疑，而是对任何 alpha 阶段软件的合理操作。 而对 VBA 那一条我想单独说：对绝大多数企业来说，Excel 的护城河不是界面，而是那张巨大的 VBA 宏表和在它上面长出来的业务逻辑。 一个替代品如果不支持 VBA，它能替代的是「个人做表格」，不是「跑着业务的公司」。项目的选择是清楚的：用自有脚本 + MCP + CLI 替代 VBA，押注「新写的自动化用代理来做」，而不是「把旧的宏搬过来」。这在技术上说得通，但迁移成本落在用户身上。

最后是我的四点判断。第一，新闻稿和仓库讲的不是同一个故事，而仓库更值得读。 媒体标题是「AI 造出 Office 替代品」，而仓库的 ROADMAP 自己写着「可用于实际工作约 50%」。第二，`CLAUDE.md` 才是这个项目真正的新东西：它不是给人看的文档，而是给「会自己动手改代码的执行者」看的规程，其四个特征（正面+负面清单、规则机器可检查、区分安全网与许可、为并行执行写规则）值得任何做 AI 辅助开发的人参考。第三，它的 50% 主要是「法律路线选择」的成本，而不是 AI 能力的上限。 第四，它把 AI 放在了「外部代理精确控制应用」这个位置，而不是「应用内置聊天框」：从「一切皆命令」出发，可测试性、可代理控制、可审计性三件事一起被解决了。

代理工作流 **看快照 PNG 并与 `observed-ui.md` 对比**；**并行代理各自独立 `CARGO_TARGET_DIR`**；**一提交一个任务 id**；`plan/` 为 gitignored
⚠️ 空白 上述规则引用的共享标准仓库 **`storytold/craftrules` 实测 404（未公开）**

这个项目最值得学的不是它能生成多少代码，而是它把规则写成了什么样子。CLAUDE.md 不是给人看的文档，而是给「会自己动手改代码的执行者」看的规程：正面清单与负面包清单并列、规则做成机器可检查的、区分安全网与许可（「这是安全网，不是许可」）、以及为并行执行写规则。而它的 50% 我认为主要是法律路线选择的成本，而不是 AI 能力的上限：clean-room 重建买来了 MIT/Apache-2.0 的商用自由，代价是格式兼容的长尾必须自己走一遍，而长尾只能靠真实文件磨。最后一点值得记住：它把 AI 放在了「外部代理精确控制应用」这个位置，而不是「应用内置聊天框」，而它靠「一切皆命令」这个架构决定变成可能——从这一个决定出发，可测试性、可代理控制、可审计性三件事一起被解决了。
