QUOTE

家用路由器默认给你一个连冻结名单都没进的域名，而 mDNS 用了十几年的那个标准域名，其实只能用于组播。

—— 关于内网命名的一次核验

家用路由器默认给你 .lan，mDNS 用 .local，老企业内网挂着 .corp / .home。这些名字有一个共同点：都没有任何官方保障。其中 .local 有标准，但只能用于 mDNS；home.arpa 是唯一有 RFC 的普通 DNS 家庭域名；.corp / .home / .mail 已被 ICANN 冻结委派，原因很简单——用的人太多，一旦委派就是全球性事故。而 .lan 连冻结都没有，它只是恰好还没轮到被委派。2024 年 7 月，ICANN 董事会正式保留了一个新的私有用途顶级域 .internal，目标正是让所有人从这批未保留的名字上迁移走。

01

IANA REGISTRY

先看权威数据：IANA 登记表里到底有谁

判断一个域名「用在哪儿是否安全」，唯一权威来源是 IANA 的特殊用途域名登记表（Special-Use Domain Names，依据 RFC 6761）。我把完整列表拉了下来，结果很清楚：只有两个「内网用途」的域名被正式登记。

域名引用状态
home.arpa.RFC 8375Standards Track（2018）
local.RFC 6762Standards Track（mDNS）

而下面这些，全部未登记：

域名IANA 登记引用
.lan无—
.corp无—
.home无—
.internal暂未登记ICANN 已保留（2024-07）
.private无—

根区实测：「未登记」到底意味着什么

我直接问了根服务器（198.41.0.4），.lan / .corp / .home / .internal 全部返回 NXDOMAIN：

...bash

$　dig　lan　　　　　　　NS　@198.41.0.4　　　#　NXDOMAIN
$　dig　corp　　　　　　NS　@198.41.0.4　　　#　NXDOMAIN
$　dig　home　　　　　　NS　@198.41.0.4　　　#　NXDOMAIN
$　dig　internal　　NS　@198.41.0.4　　　#　NXDOMAIN
$　dig　arpa　　　　　　NS　@198.41.0.4　　　#　a.ns.arpa.　　←　唯一例外

注意 NXDOMAIN 前面还有一个 aa 标志（Authoritative Answer）：

...bash

$　dig　lan　NS　@198.41.0.4　|　grep　flags
;;　flags:　qr　aa　rd;　QUERY:　1,　ANSWER:　0
　　　　　　　　　　　　　　^^

根区是「权威地」告诉你 .lan 不存在 —— 这是确定性否定，不是「我懒得理你」。正因为如此，客户端拿到 NXDOMAIN 后还会继续叠加后缀往上问，一路问到根。

02

BREAKDOWN

六个域名的真实状态

.local —— 有标准，但只能用于 mDNS

RFC 6762（Multicast DNS）的规定很明确：

This document specifies that the DNS top-level domain ".local." is a ==special domain with special semantics==, namely that any fully qualified name ending in ".local." is ==link-local==, and names within this domain are ==meaningful only on the link where they originate==.

—— RFC 6762

机制是这样的：任何 .local 查询都不走普通 DNS 单播，而是发到 mDNS 组播地址 224.0.0.251 / FF02::FB。但很多家用路由器把它配成了普通 DNS 域，这违背了 RFC 6762。

正确用法错误用法
.local + Avahi / mDNS.local + 普通 DNS 记录
客户端发组播查询客户端发单播查询，或被 mDNS 抢答

如果你同时跑着 Avahi 和一条 DNS A 记录，会遇到「有时能解析、有时不能」的诡异现象 —— 因为 mDNS 和传统 DNS 在抢答同一个名字。

home.arpa —— 唯一有 RFC 的普通 DNS 家庭域名

RFC 8375（Standards Track，2018 年）把 home.arpa 指定给住宅家庭网络做非唯一用途。为什么是 .arpa 而不是大家更喜欢的 .home？RFC 里说得很直白：

This document corrects an error in RFC 7788 by replacing '.home' with 'home.arpa.' as the default domain name for homenets. =='.home' was selected as the most user-friendly option; however, there are existing uses of '.home' that may be in conflict with this use.==

—— RFC 8375

No such process is available for requesting a similar delegation in the root at the request of the IETF, ==which does not administer that zone==.

—— RFC 8375

这段话的分量在于：IETF 管不了根区，所以无法阻止 .home 将来被委派给某个商业注册局。为了安全，只能退到 .arpa —— 因为 .arpa 由 IETF 自己管理，永远不会被商业化委派。这也是为什么它是唯一一个根区里有 NS 记录的特殊用途 TLD。

.lan —— 最流行，但零保障

它流行的原因很实在：三个字母，语义直观，路由器固件默认就用它。ICANN 公开征询时甚至有人力挺：

I suggest to use ==.lan instead of .internal or .private==. .lan is much faster and easier to type, especially on mobile devices. .lan is the abbreviation of "Local Area Network" so it would make perfect sense.

—— ICANN 公开征询中的一条意见

但最终 ICANN 选了 .internal。风险在于：没有任何机构承诺不委派 .lan。它和 .corp / .home 不同 —— 那两个至少被冻结了，而 .lan 连冻结都没有，只是「恰好还没轮到」。

.corp / .home / .mail —— 已被明确冻结委派

首轮新 gTLD 计划期间，企业内网对这三个名字的使用量太大，导致大量内部查询泄漏到根服务器。如果 ICANN 把它们委派出去，全球企业会在同一天集体撞车。结果就是 ICANN 停止了这些字符串的委派。

但「冻结」不等于「永久保留」—— 这是 ICANN 的 政策决定，不是技术保证。理论上未来可能解冻。所以 .corp / .home 现在「能用」，但这是借来的时间。

.internal —— ICANN 给出的官方答案

时间事件
2020-09SSAC-113 建议保留一个私有用途 TLD
2024-01ICANN 公开征询候选字符串
2024-07ICANN 董事会决议保留 .internal
2025–2026IETF 起草 draft-davies-internal-tld（最新 -06）

草案的作者阵容很说明问题：K. Davies 来自 IANA，A. McConachie 来自 ICANN，W. Kumari 来自 Google。这不是社区提案，是官方意志。而它的核心承诺很硬：

the "internal" top-level domain is reserved from being used in the global DNS it ==MUST NOT appear in the DNS root zone== except to the minimum extent necessary.

—— draft-davies-internal-tld

目标是明确的：把运维者从 .corp / .home / .lan 这类未委派的命名上引导开。目前草案还没成为 RFC（最新 -06，2026 年 11 月过期），所以 .internal 还没进入 IANA 登记表，但 ICANN 董事会已经批准保留，方向是确定的。

03

RISKS

风险到底有多大：三种真实场景

风险 1：查询泄漏到公网（最常见）

内网用 .lan，笔记本带出公司连上咖啡厅 WiFi，解析 printer.lan 这类名字时公司 DNS 不可达，查询就泄漏到公网根服务器，攻击者由此看到你的内网命名。

这不是假设。内网 DNS 服务器的查询日志里就能看到这类泄漏（*.lan 的 NXDOMAIN），而且都是打到根服务器才回来。

风险 2：名字碰撞导致中间人攻击（最严重）

某天 .lan 被委派给某注册局，攻击者注册 printer.lan，你的员工在外网时就会解析到攻击者的 IP，流量被劫持。这是 US-CERT 专门发过警报的场景（TA16-144A）：

Web Proxy Auto-Discovery (WPAD) DNS queries that are intended for resolution on ==private or enterprise DNS servers have been observed reaching public DNS servers==.

—— US-CERT TA16-144A

==Opportunistic domain registrants could abuse these collisions== by configuring external proxies for network traffic and enabling ==man-in-the-middle (MitM) attacks== across the Internet.

—— US-CERT TA16-144A

Verisign 的实测数据是：约 2000 万条/天的脆弱查询在公网上出现。

风险 3：证书体系冲突

内网用 .lan 并自签证书，某天它成为公共 TLD 后，内网 CA 和公网 CA 体系冲突，浏览器报警、TLS 失败、内部服务集体不可用。

04

HOME VS ENTERPRISE

家庭网络 vs 企业内部

场景.lan 安全性说明
纯家庭网络尚可接受设备少，但仍建议换
企业内网不推荐设备多、笔记本会带出、合规要求高

企业内部还有一条：Active Directory 的域该叫什么

不要用 .corp、.local、.lan 这类未保留的名字做 AD 域，原因有三条：ad.local 类域名会和 mDNS 打架；.corp / .home 有委派风险，一旦委派，企业所有机器的 Kerberos / LDAP 都会冲突；内部 CA 签的证书未来可能与公网冲突。

正确的做法是 用你真正拥有的域名下的子域，例如把 AD 域设成 ad.example.com。因为 example.com 在你手里，它的任何子域都不会被别人注册——不存在「未来被委派」的问题。

代价是需要一点额外配置：让内网 DNS 对 ad.example.com 做本地权威，不要泄漏到公网。但这比「某天域名被抢注」便宜得多。

05

RECOMMENDATIONS

给不同场景的建议

家庭网络

推荐 home.arpa —— 唯一「现在就有 RFC 保障」的选项。次选 .internal，这是 ICANN 官方方向，但客户端支持度还不明确。

...dnsmasq

#　dnsmasq　示例
local=/home.arpa/
address=/router.home.arpa/192.168.1.1
address=/nas.home.arpa/192.168.1.10

企业内部

优先用你自己拥有的公网域名的子域：AD 域用 ad.example.com，内部服务用 internal.example.com。这是唯一不会有名字碰撞风险的方案，因为根区里那条委派链在你自己手里。

如果已经在用 .lan / .corp / .home

迁移成本很高（改 DNS、DHCP、证书、所有客户端配置），所以第一步不是迁移，而是隔离。关键动作是让本地 DNS 成为这些名字的权威，不再向上游查询。以 unbound 为例：

...unbound.conf

local-zone:　"lan."　static
local-data:　"lan.　3600　IN　SOA　ns.lan.　hostmaster.lan.　..."
local-data:　"lan.　3600　IN　NS　ns.lan."
local-data:　"ns.lan.　3600　IN　A　192.168.1.1"

这里 static 和 transparent 的区别是关键：

类型未定义的名字是否向上游查询
transparent有记录就答，没有就转发上游会泄漏
static全部本地权威，未定义即 NXDOMAIN永不外泄

验证生效的方法是看 aa 标志是否出现 —— 有 aa 就说明是本地权威回答，没碰上游。

...bash

$　dig　nosuch.lan　@192.168.1.1　|　grep　flags
;;　flags:　qr　aa　rd　ra　　　　　←　有　aa　=　本地权威

这一个改动的价值，比换域名大得多 —— 它直接切断了「查询泄漏」和「名字碰撞劫持」两条攻击路径。

KEY FACTS

关键事实速查

KEY FACTS

项目 内容
IANA 登记的内网域名 仅 home.arpa（RFC 8375）与 local（RFC 6762）
根区查询结果 .lan / .corp / .home / .internal 全部 NXDOMAIN（带 aa 标志）
唯一有根区 NS 的特殊 TLD .arpa
.lan 的保护状况 无登记、无冻结，仅「恰好还没轮到」
.corp / .home / .mail 已冻结委派（政策决定，非技术保证）
.internal 状态 ICANN 2024-07 保留；草案要求永不进入根区
企业推荐做法 用自己拥有域名的子域，如 ad.example.com

这批域名的区别不在「能不能用」，而在「谁在背后兜底」。.local 有 RFC 6762 兜底，但只能用于组播；home.arpa 有 RFC 8375 兜底，因为它退到了 IETF 自己管的 .arpa；.internal 有 ICANN 董事会决议兜底，草案甚至写明它永不进入根区。而 .corp / .home 的「冻结」是政策决定——今天的决定明天可以改；.lan 更彻底，连冻结都没有，它只是恰好还没轮到。但对已经在用 .lan 的网络来说，迁移的成本远高于隔离的成本：把内网域设为本地权威（unbound 的 static），一步就切断了「查询泄漏到公网」和「名字碰撞劫持」两条路径。域名是你借来的，隔离才是你自己的。
