01

WHAT

译文：改了什么

Google 工程师 Ian Rogers 主导对 perf script 的 overhaul，目标是解决它高开销、构建依赖复杂、及其它设计难题——做法是给 Python 造一个正经的 perf 模块（C 写的扩展）。有了它，性能提升明显：一个原本 3.7 秒的 Python 脚本，改用独立脚本 + 新模块后只要 0.1 秒。

周六发出的 49 个 patch 把 Python perf 代码迁到新模块，同时丢掉旧的 libpython 代码和 legacy 脚本。整套约 2.1 万行，用于改进 perf 脚本流程。Rogers 这次有 Gemini 3.1 Pro 协助。

改动在 lore.kernel.org 审查中，未合入主线。

02

WHY

解读：不是又优化了一下，是架构清洗

1. 数字背后，是「内嵌解释器」被证伪

旧做法把 Python/Perl 解释器嵌进 perf 二进制，脚本在 perf 进程内跑——构建要拉 libpython、二进制变重、每次启动都初始化解释器运行时。改成「独立 Python 进程 + C 扩展模块」后，perf 只管高效吐数据，Python 侧用 C 扩展直接消费。3.7s→0.1s 主要是去掉每趟都付的启动/嵌入税，不是算法优化。

2. 通则：脚本慢，先查宿主进程初始化成本

当你发现「调个脚本要 3.7 秒」，别先怪 Python 慢——先看看是不是被宿主进程初始化拖死。这条对写任何「宿主内嵌脚本」的人都成立。

3. AI 辅助工程，攻与维护的两面

Rogers 明说有 Gemini 3.1 Pro 协助。这跟 Hacktron「AI 写利用」、DeepSeek「AI 黑客模型」形成对照：同一能力，一边用来攻，一边用来维护基础设施（重写 2.1 万行内核工具）。工具无善恶，看谁在补哪面墙。
