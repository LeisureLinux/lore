Sarah Jamie Lewis 被 Firefox 里又一处 AI 集成气到，索性写了个 patch：从代码库里删掉所有 AI 集成代码。结果改 1605 文件、删 852,297 行、37MB，再压到不到 1MB。这催生了 Base Browser 项目——一场「fork 一个成熟内核、把不想要的方向剔掉」的硬分叉运动。

01

WHAT SHE DID

译文：删掉 85 万行

受一条 Mastodon 线程鼓舞（呼吁各 Firefox fork 联手维护脱离 Mozilla 的硬分叉），她动手删掉 Firefox 全部 AI 集成代码。最初 patch：1605 文件变更、852,297 行删除、37MB。

她和志愿者用 git 不可逆删除标志 + 自定义 Python 把 37MB 压到 <1MB，便于重新打补丁。特别感谢 cliffmccarthy、gellge 等。

当前状态：删，而非关

如今 Base Browser 基于 Firefox 153 ESR，提供一套补丁物理删除用户敌对功能——而不是常见的「软 fork 仅禁用」。她认为删才对，原因正在于它麻烦：这些功能大、与核心耦合紧、占代码比重越来越高。「我根本不认为这些功能该出现在浏览器核心基底里。」

她也准备好输：无足够资金/人力长期维护，除非众人 pooling 努力；自承「不是对的人」，但至少先做点什么。哪怕只教会几个人从源码构建 Firefox，都算赢。

02

RETREAT

译文：退路，与更远的愿景

·

尽量离线：OpenZIM 阅读器把基础浏览搬离核心浏览器，已转一批站点到 Kiwix 图书馆离线读

·

尽量用独立应用：比起 web app 更爱桌面独立应用，给 Mastodon 等试独立客户端

·

尽量用 feed 阅读器：不打开整个浏览器也能与在线系统交互

但她不想把一生耗在「为原地不动而战斗」。她回望 2000s Firefox 复兴、Amaya/Flock「浏览器应可创造」的愿景，试建支持 gemini 协议与 RSS 的小浏览器。借一句老口号：we need new noise（我们需要新的噪音）。

03

MY READ

解读：一场关于「浏览器该是什么」的立场

1. 「删」而非「关」，技术上更诚实

软禁用=代码还在，升级/改默认就可能重新打开，维护方永远在和上游增量搏斗；物理删除则砍掉攻击面与审计面，代价是每次 rebase 新 ESR 要处理冲突。她那句「删才对，正因它麻烦」点破：一个功能越大越耦合核心，越不该在核心里——这跟「攻击面即风险」是同一直觉：少一行代码，少一份被利用/被悄悄改默认的可能。

2. 独立 web 的生存策略 + 一个实用 git 技巧

Base Browser 与 Tor/Waterfox 一脉相承但更激进。冷知识：37MB 压到 ~1MB 靠 git 不可逆删除 + 脚本重打补丁——原始 diff 含被删行全文才巨大，不可逆删除让 git 不再保留，重打时由脚本恢复上下文。任何「从上游大块剔功能」的人都用得上。

3. 她自承会输，恰恰说明值得被看见

对抗主流叙事的不一定是赢家，而是愿意先动手、把可复用补丁和讨论场(放在 Codeberg 而非 GitHub)留下来的人。「先做点什么」本身就有价值。
