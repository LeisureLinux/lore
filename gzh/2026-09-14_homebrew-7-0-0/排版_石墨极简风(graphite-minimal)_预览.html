如果 Apple 和 GitHub 都撑不住 Intel Mac， 志愿者项目也撑不住 ——Homebrew 7.0.0 的告别倒计时，从今天开始。

—— LeisureLinux 荐读

9 月 13 日，Homebrew 发布 7.0.0 大版本。官方对 6.0.0 以来最重要变化的概括只有一句话：更快的安装与升级、更强的沙箱、原生 macOS 应用、内置漏洞检查与公告数据库、macOS 10.15 支持终结、Intel Mac 降至 Tier 3。

这一年一个大版本的节奏很稳，但 7.0.0 的「破坏面」比以往更宽。对一句话里没展开的部分——尤其是 Intel Mac 用户该怎么办、Linux 沙箱为什么换了实现、 post_install 为什么被弃用 ——本文在译文之外给出解读。

01

INTEL MACS

Intel Mac：不是「减少支持」，是倒计时

这是本次发布最重磅的消息。Apple 已在 macOS 27 Golden Gate 中放弃 Intel x86_64，GitHub Actions 将于 2027 年秋退役 Intel macOS runner。官方原话很直白：

「如果 Apple 和 Microsoft 的 GitHub——世界上最大的两家科技公司——都无法继续支持 macOS Intel x86_64，很遗憾 Homebrew 也做不到。」

时间表分两段：7.0.0 起 Intel 就是 Tier 3——现有 bottles 保留，但 更新过的 formula 可能要源码编译 ，且会越来越频繁；2027 年 9 月 1 日起，Homebrew 彻底停止在 Intel 上运行。注意措辞：不是「停止支持」，是「停止运行」。

macOS 侧的门槛也在整体抬高：10.15 Catalina 及更早版本支持直接移除，Sonoma 14 降至 Tier 3，官方 .pkg 安装器现在仅支持 Apple Silicon 且要求 Sequoia 15 以上。与此同时，macOS Golden Gate 27 在 Apple Silicon 上是 Tier 1 全支持、预构建 bottles 齐备。官方还罕见地指了条后路：Intel 用户可以考虑 MacPorts。


02

SECURITY

安全：公告数据库、内置扫描与一批 GHSA 修复

这是 7.0.0 里最值得安全团队关注的部分，三个动作：

1

新开的advisory-database 漏洞公告数据库：针对 Homebrew 实际打包的 formula 版本与 revision 记录漏洞，含 backport 的安全修复，OSV 格式、CC0 许可，可自由复用。

2

内置命令 brew vulns：基于 OSV.dev 扫描已安装 formula 的已知漏洞，无需额外 tap 或 gem，支持按严重度、依赖、Brewfile 过滤，还能区分「有修复可用」与「暂无修复」。

3

公告数据进 formula API 并提供可下载索引，第三方工具可以区分「未修复」与「已随包发布修复」，SBOM 里也加上了上游包标识（PyPI、npm、Cargo 等）。

本次还修复了一批安全公告，其中两条值得记一下：一条是 6.0.12 修复的 高危漏洞 ——未签名的 cask 卸载元数据可以带着 sudo 执行命令，相关脆弱代码已全部删除；另一条是 7.0.0 修复的中危——恶意 cask 可经 LaunchServices 在 macOS 安装沙箱之外执行代码，现已限制应用启动、Mach 服务与 Unix socket 连接。

沙箱本身也在收紧：formula 与 cask 操作进入沙箱、依赖下载迁往独立的 fetch 阶段——下载时有网络和可写缓存，进入 install 阶段就断网且缓存只读——并且默认阻止沙箱内读取用户 home 目录。


03

LINUX SANDBOX

Linux：Bubblewrap 换成内核原生 Landlock

6.0.0 引入的 Bubblewrap 沙箱在 7.0.0 被替换为 内核原生的 Landlock （Linux 6.1 以上，ABI 2）。原因很实际：Bubblewrap 需要额外依赖和提升的 Docker 权限，落地时问题不少；Landlock 零依赖、无提权。

降级策略也做得干净：内核不支持 Landlock 的机器仍可运行，只是退回 6.0.0 之前「无沙箱」的旧配置， brew doctor 会给出 advisory 提示 ，而不是直接报错。配套变量变化：旧的沙箱开关已禁用（Landlock 可用时自动启用），关闭沙箱的变量与架构覆盖变量将于 2027 年 12 月弃用。


04

GUI & PERFORMANCE

BrewUI 与安装链路全面并发

Homebrew 第一次有了官方原生 macOS 应用：BrewUI。一条命令 brew install homebrew-app 即可装上（要求 macOS Tahoe 26 以上）：包浏览、搜索、已装版本信息一个窗口搞定。有意思的细节是，每个操作都会显示底层的 brew 命令—— 不是把终端藏起来，而是把 GUI 和命令对应起来 。

性能侧，并发贯穿了整条安装链路：安装、重装、升级的包准备与下载重叠执行，Brewfile 批量安装同样受益；系统信息与 tap 元数据并发收集；缓存清理避免重复扫描；fetch 直接从 API 元数据取下载信息；启动子进程更少，热运行复用已解析的 API 数据——签名每次加载都会验。

05

TAP MAINTAINERS

post_install 时代落幕，与四条解读

formula 的 post_install 与 cask 的各类 flight Ruby 块被弃用，改为声明式 steps。动机是安全：显式的操作与路径可以被验证、沙箱化、经签名 API 下发，而不是「装包时执行任意 Ruby」。官方 tap 已直接拒绝旧钩子，第三方 tap 宽限到 2027 年 12 月，自动转换工具可以处理常见情况。

「『包定义等于可执行代码』的表面积，正在被一块一块地拆掉。」

解读一：去 Ruby 化是主线

从弃用 post_install、把下载信息挪进 API、到 cask 语言变体不再逐个执行 Ruby 定义——Homebrew 在持续收缩包定义的执行面。这不是审美洁癖：恶意 cask 恰恰是借「安装时执行代码」得手的。声明式 steps、签名数据、沙箱，是 供应链防护的三件套 。

解读二：brew vulns 补上包管理器级漏洞可见性

Linux 发行版有发行版安全公告已久，Homebrew 此前一直是空白——装了什么、哪些版本带 CVE，全靠自觉。现在有了 CC0 的 OSV 数据库加内置扫描命令，CI 里跑一次针对 Brewfile 的漏洞检查，就能给开发环境做漏洞门禁。对用 Homebrew 管理 macOS 开发机的团队，这是 7.0.0 里 投入产出比最高的一个功能 。

解读三：Intel 的退场值得现在就行动

Tier 3 意味着从今天起就可能碰到「formula 更新了但没有新 bottle，只能源码编译」的情况，且会越来越频繁。还在用 Intel Mac 做开发机的，现在迁移 Apple Silicon 或转 MacPorts 的成本，远低于一年后被动迁移。

解读四：选 Landlock 是务实的取舍

Bubblewrap 需要引入依赖和 Docker 权限，对一个装在用户目录、不以 root 运行的工具来说部署摩擦太大。Landlock 的代价是依赖内核版本，但 2026 年的主流发行版都已覆盖；无 Landlock 时优雅降级而非报错，这个取舍做得干净。

THE END

结语：一个「基础设施型」大版本

用户可见的新东西不多，但底层从安全模型、沙箱实现到安装链路并发都在换梁换柱。顺带一提，6.0.0 到 7.0.0 之间官方仓库长期保持 0 个开放 issue——这个志愿者项目的工程纪律可见一斑。

升级建议：一条更新命令即可完成。Intel Mac 用户、CI 里引用 Ubuntu 22.04 镜像或 master 分支 action 的、以及维护第三方 tap 的，按时间线尽早迁移。
