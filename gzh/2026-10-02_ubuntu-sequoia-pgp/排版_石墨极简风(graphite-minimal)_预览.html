—— Ubuntu 的 Rust 化是防守型安全的复利

Canonical 工程师 Richard Scott McNew 发布 Ubuntu 26.10 Rust 进展：Sequoia PGP（Rust 实现的现代、内存安全 OpenPGP）已进入 26.10「Stonking Stingray」，提供 `sq`/`sqv` 对应 GnuPG 的 `gpg`/`gpgv`。26.10 默认仍是 GnuPG，但官方明确：未来版本中它「可能」成为默认 OpenPGP 工具链。同期 Rust Coreutils 过渡达成 100%，cp/mv/rm 也切到了 Rust 版。

FACTS

这条更新里说了什么

Ubuntu Discourse 原文（据 Phoronix 转述）：

**Ubuntu 26.10「Stonking Stingray」的另一项新内容是 Sequoia PGP**——一个用 Rust 编写的现代、内存安全的 OpenPGP 实现。Sequoia PGP 提供 **`sq` 和 `sqv`** 命令，作为 GNU Privacy Guard 的 **`gpg` 和 `gpgv`** 的对应物。**未来，Sequoia PGP 可能成为 Ubuntu 的默认 OpenPGP 工具链**，在迁移到现代的内存安全实现的同时，保持 OpenPGP 互操作性。

当前状态一句话：26.10 里默认的还是 GnuPG，Sequoia 是并列提供；官方措辞是「可能」（may），没有时间表。

OMG! Ubuntu 补充的关键细节

·

不只是「进仓库」，而是「进了默认安装集」：Sequoia PGP 被纳入 26.10 的默认 seed（预装），且 `rust-sequoia-sq` 包已移入 `main` 仓库，由 Canonical 官方支持

·

但它现在还不是默认：`gpg` 仍然调用 GnuPG，`sq`（或配置为使用 Sequoia 库的应用）才走 Sequoia

·

官方动机：采用 Sequoia 能让 Ubuntu 在提供 OpenPGP 互操作性的同时，受益于 Rust「更可维护、内存安全的基础」

·

怎么试：直接跑 `sq sign` 或 `sq verify` 即可体验

·

这不是孤立的 Rust 变化：26.10 开箱即用整套 Rust 核心工具，GNU 版 `cp`、`mv`、`rm` 现在由 `uutils` 提供

「移入 main 仓库」的分量：Ubuntu 的仓库分 main（Canonical 官方支持）与 universe（社区维护）。移入 `main` 意味着这个包从「社区附带品」升格为「Canonical 承诺支持的组件」，这是判断发行版认真程度的最硬指标之一。

02

CONTEXT

为什么是「100% Rust Coreutils」之后轮到 PGP

把这条新闻放进 Ubuntu 两年的 Rust 路线里看才完整：

·

2025-10（25.10）：首次默认携带 Rust 核心工具集；Rust 版 sudo（sudo-rs）成为默认

·

2026-04（26.04 LTS）：cp/mv/rm 因 TOCTOU 问题被扣在 GNU 版，问题正是 Canonical 委托的 uutils 安全审计发现的

·

2026-09 上游：TOCTOU 修复；Rust Coreutils 0.12 发布

·

2026-09-16：26.10 草案 notes 更新为 过渡 100% 完成

·

2026-10-15：26.10 正式发布

·

2026-10：Sequoia PGP 进入默认安装、移入 `main`

几个值得记住的细节

·

`cp`/`mv`/`rm` 的「拖后腿」不是闲话：26.04 是 LTS，保守是应该的。审计发现问题 → 修上游 → LTS 保持 GNU → 非 LTS 的 26.10 先切，这个节奏本身是健康的工程流程

·

审计带来了正外部性：uutils 团队给 GNU coreutils 贡献了更多测试，「uutils 通过的 GNU 测试比一年前 GNU 自己的还多」。重写工作的副产品是整个生态的测试覆盖变厚，惠及 GNU、busybox、BSD 各家

·

资金与治理：Canonical 是 Trifecta Tech Foundation 金牌赞助商（每年 4 万欧元），还在 26.04 前出资对 uutils 做了安全审计

Sequoia PGP 是什么

Sequoia 是 OpenPGP 的另一个实现，不是新协议：同一套协议，两套实现：

·

语言：GnuPG 是 C，Sequoia 是 Rust

·

命令：GnuPG 用 `gpg`/`gpgv`，Sequoia 用 `sq`/`sqv`

·

架构：GnuPG 是多功能套件（加密/签名/密钥管理/agent），Sequoia 是模块化的库 + CLI（可嵌入其他程序）

·

内存安全：传统 C 历史漏洞面较大；Rust 所有权模型在编译期挡住 use-after-free、越界、数据竞争这一整类问题

·

互操作：同为 OpenPGP（RFC 4880/9580），互操作是设计目标

关键认知：`sq` 不是 `gpg` 的换皮，互操作靠的是协议而不是代码兼容。 OpenPGP 是开放标准，两者各自实现同一套协议，所以密钥、签名、加密消息可以互通。发行版换默认实现，理论上不需要用户换密钥。

为什么密码学组件对「内存安全」特别敏感：GnuPG 处理的是不可信输入（别人发来的密钥、签名、加密邮件），历史上一整类 CVE 都源于 C 的内存处理错误。对「处理敌意输入的守护组件」来说，Rust 的收益是结构性的。

解读与运维建议

1. Ubuntu 的 Rust 化是「按组件渐进替换」，不是「重写发行版」

把这两年的动作连起来看，模式非常清晰：sudo-rs（25.10 默认）→ coreutils 全套（26.10 完成）→ Sequoia PGP（26.10 进入、未来默认）。每一步都是选一个边界清晰、有成熟上游的项目，先并存、后切换。没有一次性大爆炸，且每个组件都选在「有独立上游、有测试基线、可回退」的位置。这是发行版做大规模语言迁移的教科书节奏。

2. 「互操作」是替换能成立的前提，也是最脆弱的环节

GnuPG 不只是命令行工具，它周边有庞大生态：gpg-agent、gpgme、邮件客户端集成、apt 签名链、keyserver、smartcard/HSM 等。Sequoia 替换的只是 `sq`/`sqv` 这层 CLI 入口；生态依赖的是 GnuPG 的库与 agent 体系。

现实的替换路径大概率是「按场景分批」：先覆盖「验证签名 / 校验 deb 包」这类简单场景（`sqv` 对应 `gpgv`，正是 `apt` 用的形态），再逐步处理 agent、密钥管理这类复杂场景。「未来成为默认」这句话里，默认的范围是什么（仅 CLI？含 agent？含 apt 链？）比时间点更值得关注。

3. 对运维：现在几乎没有影响，未来要盯三件事

·

现在：26.10 上 `gpg` 行为不变，sq 多了个可用替代；脚本、CI、apt 全不受影响

·

未来切换盯三处：① `gpgv` → `sqv`：若 sqv 成为 apt 验签路径，验证失败的报错形态与 exit code 是否与 GnuPG 完全一致（CI 和自动化对这两点最敏感）；② 密钥与 agent 迁移：gpg-agent 的 socket、缓存、passphrase 交互是否保持；③ LTS 与中间版的差异：LTS 大概率最后切，跨 LTS/非 LTS 的行为差异会持续几个周期

·

建议：现在就在 26.10 测试环境跑 `sq sign` / `sq verify` / `sqv` 与 `gpg` 交叉验证，把自己的密钥环互操作验证一遍。等它真成默认时，你就有了现成的兼容性清单

4. 更大的图景：Ubuntu 在赌「内存安全是可运营的工程目标」

从 sudo-rs 到 coreutils 再到 PGP，Ubuntu 选的都是安全审计已完成、上游测试体系成熟、且与 GNU 版可互换的项目。它不是在追「用 Rust」的时髦，而是在执行一个可验证的替换清单：每换一个组件，就少一类内存漏洞。对服务器装机量极大的发行版来说，这是防守型安全的复利。

测试的正外部性值得单独一提：uutils 给 GNU 补的测试最终惠及所有实现。这类迁移如果做对，产出物不只是 Rust 版本，还有更厚的协议级测试基线，这可能是这波 Rust 重写潮里最被低估的价值。
