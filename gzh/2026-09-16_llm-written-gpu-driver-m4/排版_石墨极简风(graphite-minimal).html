01

THE ABI

内核侧的真正敌人是固件 ABI

在 Apple Silicon 上，内核驱动不直接和硬件对话，而是和跑在一个叫 RTKit 的自定义 RTOS 上的 GPU 固件对话。所以写内核驱动的第一步不是搞硬件，而是搞清固件 ABI。

这也是整个项目最烦人的部分。Apple 没设计一套体面的接口，而是把一个普通内核驱动切成两半，一半塞进 AGX 叫「固件」，另一半用内存里的共享 struct 通信。这些 struct 里，固件持有的字段和主机控制的字段交错在一起。

作为复杂度参考：A18 Pro 的固件 ABI 比「已经非常复杂」的 M1 还要复杂得多——struct 数量 1.5 倍、指针数量 2 倍、提交工作的流程显著更复杂。当年 Asahi Lina 是在 12 小时连轴转的苦战里搞明白 M1/M2 这套东西的。

原文提到一个细节：作者宁可自己用 live probing 逆向 M4、A18 Pro 和（大部分）M5 的用户空间，结果还发现了 Apple 自家驱动都没发出的硬件特性与指令。

02

THE REPLAY

「重放」才是逆向的核心工作流

方法很直接：观察 macOS 的行为、重放它、再试着自己做——这一切能成立，靠的是作者此前自建的 hypervisor。

当他把这个思路描述给 LLM 时，模型对「重放」的理解极其字面：先等到第一个固件可见事件（他们叫 kick），把整个 GPU 内存状态存一份；重启后拷回主机内存、执行 kick，看到输出页果然变了。

然后它再试着用代码重建这些对象，沿着指针走、把内容搞明白。一轮轮实验下来，Codex 会不断减少它拷贝的页数，直到不再需要任何重放状态、所有东西都从源码构建出来。

三个卡点，全是「拿不到干净捕获」

·

固件启动后的 render：换更早的捕获点后几乎立刻定位，少了一个单字节 descriptor

·

compute：捕获到 336MB 且无法重放，改用单用户模式 + 最早 LaunchDaemon + 极小 Metal 程序

·

partial render：TVB 装不下几何体，本质上等于给驱动加 save/resume

「以单用户模式启动，禁用 GUI——这样不会有 render 工作；装一个 LaunchDaemon，在 Metal 可用的最早时刻跑一个极小程序；捕获并重放这个纯 compute trace。」

—— 原文所述解法

compute 跑通后，作者想知道原来那份代码为什么不行。Codex 自己也不知道——能跑的和坏掉的看起来几乎一样。

03

MESA FIRST

Mesa first 完胜硬件优先

用户空间逆向分两阶段。第一阶段让 Claude 把它能找到的所有 Metal 程序看一遍，构建反汇编器、汇编器，理解各种 descriptor 格式。这一步成功了。

但「能反汇编再汇编」不等于「知道怎么自己造一个」。当试图补齐这个差距——理解每条指令到能编译任意程序的程度——Claude 表现很糟，基本零进展。

于是两人分头走：作者走硬件优先（先搞清硬件、写 spec、让 LLM 实现），Niklas 走 Mesa first（先把 Mesa 搭起来，只在需要某功能时才去逆向）。

结果 Niklas 明显更快：他的 agent 被「真的要把 Mesa 建起来」这个目标锚定，资源用得高效得多；而作者的 agent 会为了「完整性」在无关紧要的小任务上耗时。 Niklas 快到作者干脆转为支援他。

作者对 Codex 的关键评价：pedantic

原文用的词是 「pedantic（迂腐）」：它极其彻底，这在某些场景是巨大优势，但另一些时候会卡在某个不相干的枝节上，损害整体目标。

顺带挖出的硬件能力

·

原生单指令 64 位加法

·

各向异性过滤到 128x（Metal 上限 16x）

·

矩阵单元的一个新模式

·

uniform_mov 的 7 位立即数支持

这些行为硬件支持、但 Metal 未暴露，和当年 Alyssa Rosenzweig 逆向 M1/M2 的做法一样：直接改指令的 bit 再外推。作者对这批人的评价是「简直是巫师」。

04

TESTING

测试这道题，已经有人替你写好了

用户空间图形开发有几件大好事。最关键的：Khronos 的兼容性测试套件（CTS）本身就是一份详尽的测试语料，是驱动必须通过的。

换句话说，「给 LLM 提供好测试来锚定它」——整个 LLM 工作流里最难、最敏感的一环——已经免费得到。

剩下的活是翻译：在 Gallium（Mesa 内部 API）和 AGX 硬件语义之间做转换，其中一大块是把 NIR（Mesa 的内部 IR，很像 LLVM IR）翻成 AGX 的私有 ISA。这个编译器将来做 Vulkan 驱动还能复用。

Niklas 就这样一边逆向一边迭代特性，最终达成完整 OpenGL ES 3.0 合规（未通过的都是可选扩展）。从 Python 原型走到功能完整的 Linux 驱动只花了 3 天，而这三天里还有一天几乎白费——因为 Codex 不知为何选择先啃最难的那块。

05

MY TAKE

解读：真正的信息量在哪

1. 这不是 LLM 单飞的胜利，是流程设计的胜利

把真正起作用的东西列出来：一个自建 hypervisor、净室隔离、最小可复现捕获（单用户模式 + 最早的 LaunchDaemon + 极小 Metal 程序）、以及现成的 CTS 语料。LLM 负责的是在这个约束里做枯燥而庞大的 bit 级推理。少任何一环，一个月都不可能。

2. 「重放」是逆向 agent 时代的核心工作流

先存整块内存状态、拷回去、kick、看输出页变没变，然后逐步减少拷贝页数直到完全从源码构建。这是一条可度量的收敛曲线：每一轮实验都是对理解程度的一次可验证检验。这篇文章最有价值的方法论就在这里。

3. 卡点几乎总是「拿不到干净捕获」，不是模型不够强

第一个问题换捕获点就解决了；第二个问题换单用户模式 + 极小 trace 就解决了。两次都不是「模型太笨」，而是实验设计没收敛。作者的自我反省也指向同一件事：他以为简单所以没搭脚手架，结果白白烧掉一周多。

4. 「Mesa first」是给所有 agent 使用者的通用教训

两条路线的差别，本质是任务有没有可验证的收敛判据。为完整性做实验，判据是主观的、开放的，agent 会无限膨胀；为「让 Mesa 跑起来」做实验，判据是客观的、可跑的。CTS 的价值同理：它不是测试，它是把开放性目标变成封闭性目标的那把钥匙。

5. 上游化会是人类瓶颈，这一条短期内不会变

作者写道：「我们预期会被用比人类手写更高的标准要求」。技术验证可以自动化，但信任与责任无法自动化，只能靠测试、review 和时间累积。他们的结论很务实：等 M1/M2 驱动先上游，再排队。
