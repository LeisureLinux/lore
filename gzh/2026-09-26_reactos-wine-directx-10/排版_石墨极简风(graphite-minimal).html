ReactOS 把 Wine 10.0 的 DirectX 代码整体借入：新增 49.8 万行、删除 11.9 万行旧 hack，解锁上百款游戏。

—— Phoronix 对 ReactOS DirectX 栈更新的报道（2026-09-26）

ReactOS（致力于二进制兼容 Windows 应用/游戏/驱动的开源项目）合并了一次重大 DirectX 栈更新——把 Wine 10.0 状态的 DirectX 代码搬进来。代价是开发者 Justin Miller 累计 230+ 小时，结果：新增 49.8 万行、删除 11.9 万行，可借 Vulkan/OpenGL 翻译 DirectX，解锁上百款游戏，DX10/11/12 兼容在望。

01

WHAT

这次更新做了什么

来源：从 Wine 10.0 借来的 DirectX 实现，替换 ReactOS 原有、带大量 hack 的旧栈（PR：reactos/reactos#9352）。

规模

合并代码 49.8 万行新增、11.9 万行删除——一个量级惊人的重写式更新。

翻译路径

新栈让 ReactOS 能用 OpenGL 与 Vulkan 翻译 DirectX（Vulkan 当前需 custom branch 或 mesa 软件渲染器才能跑）。

副作用

清掉内部大量旧 DirectX hack，并改善该 DirectX 栈在 Windows 自身上的工作能力。

02

GAMES

游戏收益

Miller 在 PR 里说：这个 PR 配合其他待合并 PR，解锁的游戏数量在 100 量级（hundreds）。

ReactOS 开发者在 X 上表示，DX10 / 11 / 12 的游戏兼容即将在 ReactOS 上成为可能——目前标着「即将」，尚非已可用。

03

WHY

解读

1. 站在 Wine 肩上的典型胜利

ReactOS 自己重写一套 DirectX 没意义，直接吸收 Wine 已做好的、与上游同步的实现，是最省力的追赶路径。Wine 10.0 的 DX 栈被整体借入，等于一次性补齐多年差距。

2. Vulkan/OpenGL 翻译是关键转折

能用 Vulkan/OpenGL 做 DX 翻译，意味着不必原生实现每一代 DirectX——借宿主图形 API 当后端，与 Wine/DXVK/VKD3D 思路一致：用现代图形 API 当翻译层，而非逐代复刻。

3. 游戏兼容是 ReactOS 最被期待的能力

二进制兼容 Windows 的「圣杯」就是能跑 Windows 游戏。这次把目标从「能进桌面」推向「能跑 DX 游戏」，是项目吸引力的实质跃升。

边界：「解锁上百款游戏」是开发者在 PR 的预估，且依赖其他仍在 review 的 PR；DX10/11/12 是「即将」而非已可用。实际能跑哪些游戏，需等社区实测沉淀。
