01

VSOCK

VSOCK 是什么

VSOCK 已不算新东西—— Linux 4.8 起进入内核 ，前身是 VMware 的 VMCI。AF_VSOCK 是与 AF_INET、AF_UNIX 并列的套接字地址族，专为虚拟机（guest）与宿主机之间的通信设计，同一宿主机上的多个 guest 也能互通。此前这类通信走串口——Proxmox 的 qemu-guest-agent 就是典型。

用起来的观感是 Unix socket 的形态加 TCP/UDP 的特性：地址是 32 位的上下文标识符 CID，端口也是 32 位、1024 以下需要 root，同 CID 可靠不同端口跑多路通信，流式与数据报两种模式都有。Linux 5.6 起还有了 VMADDR_CID_LOCAL —— 不开 VM 也能本机测试 。AWS 的 Nitro Enclaves 就靠它做 enclave 与宿主的通信。


02

LIBZMQ

libzmq 里的 VSOCK：一次照抄式贡献

想用 VSOCK 时你手里往往只有最底层的绑定，poll、recv、send、bind 全要自己来。作者于是想到 ZeroMQ——它几乎在所有 socket 类型上封装了消息模式与安全特性。意外的是 libzmq 里有 VMCI 实现、 却没有 VSOCK ，于是他照着 VMCI 的代码「复制粘贴」级别地提交了 PR #4822。

能力 说明
语言全解锁 所有有 libzmq 绑定的语言都能用 AF_VSOCK
模式继承 req/rep、pub/sub 等 ZMQ 消息模式直接跑
安全继承 Curve 认证可用
嵌入式友好 libzmq 极稳、发版慢，易按 commit 静态编译

正式版尚需时日，作者先 fork 了 pyzmq 按最新 libzmq commit 构建：pyzmq-vsock，manylinux 轮子可以直接 pip 安装。

TUTORIAL

动手：loopback 上跑通 Hello World

ZMQ 里用 @ 直接绑定 vsock loopback。要模拟真实 guest/host 场景，QEMU 命令行加一个 vsock 设备：

. . . bash

export CID=100

qemu-system-x86_64 \

　　-device vhost-vsock-pci,guest-cid=$CID

　

sudo modprobe vsock_loopback　# loopback 测试前置

venv/bin/pip install <pyzmq-vsock 的 manylinux wheel>

服务端与客户端，相比 tcp 版本 只改了 URI ——vsock://@:5555：

. . . python · rep.py

import time, zmq

　

context = zmq.Context()

socket = context.socket(zmq.REP)

socket.bind("vsock://@:5555")

　

while True:

　　message = socket.recv()

　　print(f"Received request: {message}")

　　time.sleep(1)　# 模拟干活

　　socket.send(b"World")

. . . python · req.py

import zmq

　

context = zmq.Context()

socket = context.socket(zmq.REQ)

socket.connect("vsock://@:5555")

　

for request in range(5):

　　socket.send(b"Hello")

　　message = socket.recv()

　　print(f"Received reply {request} [ {message} ]")

. . . 运行输出

Sending request 0 …

Received request: b'Hello'

Received reply 0 [ b'World' ]　# 循环 5 次，全部成功

SECURITY

进阶：Curve 认证 + asyncio

生产形态大概率是 asyncio 加 Curve。作者把 pyzmq 官方的 asyncio-ironhouse 示例改到了 VSOCK 上：先 zmq.curve_keypair() 生成三组密钥；REP 侧用 AsyncioAuthenticator 只放行已知 client key，绑 vsock://@:9000。服务端关键行：

. . . python · REP 关键行

auth = AsyncioAuthenticator(ctx)

auth.start()

auth.certs["*"] = {keys["client"][0].encode(): True}

　

server.curve_publickey = zmq.utils.z85.decode(keys['server'][0])

server.curve_secretkey = zmq.utils.z85.decode(keys['server'][1])

server.curve_server = True　# 必须在 bind 之前

server.bind('vsock://@:9000')

认证通过与未授权密钥被拒的输出对比：

. . . 认证通过 vs 被拒

[DEBUG] ALLOWED (CURVE) domain=* client_key=b'HhdIwzo4=…'

[DEBUG] ZAP reply code=b'200' text=b'OK'

[INFO] Ironhouse test OK

　

[DEBUG] DENIED (CURVE) client_key=b'P4//#^+&*…'

[DEBUG] ZAP reply code=b'400' text=b'Unknown key'

踩坑点很集中：vsock_loopback 模块要手动 modprobe；curve_server 必须在 bind 之前设置；端口 1024 以下需要 root。

THE END

结语

VSOCK 的价值是通信面隔离：不经过网络栈、不占 IP 规划，guest 拿它扫不了 host 的网络。ZMQ 传输与语义解耦的设计此时显现红利——从 tcp:// 换到 vsock:// 只换一个 URI。对 KVM 系私有云与信创虚拟化平台，guest agent 通信从串口走向 VSOCK 加 ZMQ 是个值得参考的现代化模板。本文译自 Rémi Jouannet 博客。
