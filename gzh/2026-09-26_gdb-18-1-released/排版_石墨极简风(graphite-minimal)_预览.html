GDB 18.1：Windows 原生目标获 non-stop 模式、调度锁、TLS 与真彩；并移除 stabs/mdebug/CTF 等旧格式。

—— GDB 18.1 发布公告（Andrew Burgess，经 LWN 2026-09-26）

GDB 18.1 发布，面向 Ada/C/C++/Fortran/Go/Rust 等、可调试十几种架构。本期亮点：Windows 原生目标大幅增强（non-stop、调度锁、TLS、真彩/UTF-8）、新增 MicroBlaze 与 AArch64 MinGW 目标、Python API 大量扩充，并移除 stabs/mdebug/CTF 等旧调试格式。

01

WIN

Windows 原生目标重大改进

1. non-stop 模式与调度锁

支持 non-stop 模式（需 Windows 10+）；set scheduler-locking on 现在可用。

2. 原生 TLS 与真彩

支持原生线程局部存储（TLS）；Windows Terminal 下支持 24 位真彩色，代码页 65001 时支持 emoji 样式与 UTF-8（host charset 自动 UTF-8）。

3. 文件名统一正斜杠

文件名统一用正斜杠展示（如 C:/proj/src/main.c），影响所有解释器（CLI/TUI/MI/DAP）。

02

API

新目标、Python API 与协议

1. 新目标

GNU/Linux/MicroBlaze（gdbserver，microblazeel-*linux*）与 AArch64 MinGW（aarch64-*-mingw*）。

2. Python API 扩充

新增 gdb.Corefile 类（含 Inferior.corefile）、gdb.Style/gdb.StyleParameterSet 与 gdb.INTENSITY_* 常量；新增 selected_context/corefile_changed 事件；Symtab.source_lines、Block.ranges、Architecture.disassemble 的 styling 参数等。

3. DAP / 远端协议

DAP 未处理 Ada 异常可用 unhandled 过滤器；launch/attach 新增 adaSourceCharset、coreFile 参数。远端新增 qExecAndArgs 包与 single-inf-arg qSupported 特性。

其他：.gdb_index 现写入所有类型符号（旧索引应重建）；--no-escape-args；info locals 标注被遮蔽变量；AArch64 支持 FPMR；新增 essential 帮助命令类等。

03

BREAK

不兼容变更（破坏性）

1. 移除旧调试格式

移除 stabs / mdebug 与 dbx 二进制格式；移除 CTF：trace 只存 GDB 自己的 tfile 格式，target ctf 消失，--with-babeltrace 移除。

2. 其他移除

移除 version 7 前 .gdb_index、DWP v1、record save 旧格式；Guile 最低提至 2.2；移除 psymtab maint 命令；不再支持 AIX 7.1；s390 32 位被弃用（configure 报错，--enable-obsolete 可覆盖）。

注意：CTF 移除意味着老的 CTF trace 文件无法再读——有历史 trace 资产的团队要提前转存。

GDB 18.1 给 Windows 原生目标补齐了 non-stop 模式、调度锁、TLS 与真彩/UTF-8——这是从「能勉强用」到「接近第一梯队体验」的跨越；Python API 持续膨胀服务于自动化与 DAP/IDE 集成。代价是清理旧格式：stabs/mdebug/CTF/DWP-v1 等被移除，其中 CTF 移除意味着老 trace 文件无法再读，有历史资产的团队要提前转存。
