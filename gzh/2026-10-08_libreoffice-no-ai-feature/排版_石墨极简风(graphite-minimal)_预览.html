QUOTE

唯一能经受审计的保证，就是它没有离开这台机器。

—— LibreOffice 26.8 发布说明

LibreOffice 26.8 的发布说明里把「没有生成式 AI」列为一项功能。有用户在那条公告下评论问：「所以，没有 AI 现在也算一个功能了？」 第二天，The Document Foundation 用一篇博客回应了这个问题，并给出六条硬性验收标准。结论是：目前没有任何集成同时满足全部要求，所以默认安装里不会有任何形式的 AI。

SIX

六条验收标准

这是全文最实用的部分，也是我认为真正值得带走的产出物。TDF 把要求逐条列出：

·

用户控制执行位置：用户必须能自己选择推理在哪运行：本地、用户直接控制的基础设施、或用户独立选择的服务。默认设置静默重定向到单一供应商，那不叫选择。

·

未授权内容不得离开本机：文档内容是用户的资产，很多场景下还是受法律保护的材料：病历、案卷、招标文件、学生数据。传输必须是用户决策的结果，而不是应用在后台执行的行为。

·

零遥测：LibreOffice 不收集使用数据，这一点同样适用于 AI 功能。

·

不依赖单一供应商：一个只能配合某家公司 API 工作的集成，就是一种锁定机制，不管发行说明里怎么描述它。 接口应当开放，且能被多个后端实现。

·

不在格式上妥协：生成的内容必须是 ODF 格式，与任何其他内容一样，并且必须保留其结构、样式与语义。一个用专有格式生成文档的助手，只是在延续内容锁定。

·

完全可选：必须可安装、可移除、并且对不想使用它的人从界面上消失。包括那些因公司政策不允许使用、却要为数千台工作站部署软件的运维人员。

这六条的特征是「可检验」。它们不是「我们重视隐私」这类无法验证的表述，而是六道能否通过测试：推理端点是不是用户可选的？断网能不能用？有没有出站请求？换后端是否要改代码？输出是不是 ODF？能不能彻底卸载？

最强的一句：审计论证

LibreOffice 26.8 发布说明里的原话措辞相当有分量：

「**LibreOffice 26.8 不包含任何生成式 AI 功能。文档不会被传输到远程服务进行处理，套件中没有任何组件需要网络访问才能运行。**这是一个深思熟虑的立场。**任何处理机密、法律特权或个人数据的组织都需要知道数据去了哪里，而唯一能经受审计的保证，就是它没有离开这台机器。**」

为什么这句话比「我们不会滥用你的数据」强：

·

「我们不会滥用」是承诺，承诺依赖对方持续守约，而且验证成本极高（要审计它的日志、子处理商、留存策略）

·

「它根本没联网」是事实，而事实可以用断网测试来验证：把网线拔了看能不能用，这比读一百页隐私政策都快

这也解释了 TDF 列举的用户画像为什么是「学校、医院、公共机构、律所」：这些场景的共同点不是「在意隐私」这种软理由，而是有合规责任人——病历、案卷、招标文件、学生数据都有明确的法律保护要求，而且出事时要能向审计方交代。对这些人来说，「无法验证的承诺」不具备证据价值。

MISSED

媒体漏掉的那一节：为什么动机不同

媒体摘要到这里就结束了，只说了「不是原则性反对 AI，而是当前技术不满足隐私、用户控制和开放标准的要求」。但它漏掉了原文里最有洞察力的一节，标题是「Why our motivations are different」：

「我们的立场与主流套件不同的原因，**几乎和技术无关**。**对于一个卖订阅的公司来说，AI 助手既能支撑涨价，又能强化『把所有文档留在自己基础设施内』的理由。功能与商业模式互相强化，所以集成不仅是可取的，几乎成了必须做的。** **The Document Foundation 是一个非营利组织。没有需要保护的订阅档位，没有追加销售，没有数据可以变现。这并不能说明我们比别人更聪明，但它意味着我们可以花必要的时间来判断某件事是否真的对用户有用，因为我们不被季度业绩驱动。**」

这节为什么最重要，有两点：

1. 它把「反 AI」从一个价值判断换成了结构分析

TDF 没有说「AI 不好」或「做 AI 的厂商居心不良」。它说的是：当一个商业模式同时从「功能」和「锁定」两端获益时，这个功能被做进默认配置就是必然的。不是谁道德有问题，而是激励结构使然。

这种论证方式比道德批判更难反驳，因为它不指控任何人的动机，只描述结构。你可以在不同意其结论的情况下，承认这个结构分析是对的。

2. 它的结尾是克制的

「这并不能说明我们比别人更聪明」这句话值得留意。开源社区讲这类话题时很容易滑向自我表扬，而 TDF 明确划掉了这条线：它承认自己的优势是「可以慢」，而不是「判断力更好」。

真正被拒绝的不是 AI，是那种组合

如果只读标题，很容易理解成「LibreOffice 拒绝 AI」。但对照六条条件就会发现，它一条都没说「AI 本身不能要」：第 1 条允许在本地、自有基础设施或用户自选的服务上跑推理；第 4 条说接口应该开放、能被多个后端实现；第 5 条只要求输出仍是 ODF。

所以它拒绝的不是 AI，是「默认开启 + 无法关闭 + 通往单一云厂商」这一种组合。「没有 AI」是这个约束条件下的结果，不是目标。换句话说，这项「功能」的实质是：用户可以拒绝，而且拒绝得干净。

那些扩展真的都在本地吗？

TDF 说「想用 AI 的用户可以装扩展，大多数通过 Ollama、LM Studio 或其他 OpenAI 兼容端点连接本地模型，这意味着文档从不离开这台计算机」。这是一个可核实的说法，我查了 LibreOffice 扩展库里的实际状况：

·

localwriter —— Ollama（默认）、text-generation-webui；行内生成式编辑

·

LibreThinker —— Ollama / LM Studio，或自带 API key（OpenAI、Mistral、Groq 等）

·

WriterAgent —— Ollama / LM Studio、OpenRouter 等；还暴露本地 HTTP 服务给外部 AI 客户端

·

LibreAI —— Ollama + OpenAI/Claude/Grok/Gemini；C++/Qt6 的 UNO 组件，不依赖 Java

·

lo-ai-assistant —— Ollama / LM Studio

结论：TDF 的说法基本属实，默认端点普遍是 localhost:11434（Ollama）或 localhost:1234（LM Studio）。localwriter 作者的公开说明可作佐证：「事实上我从未用专有 API 测试过它。推荐的后端是 Ollama，它是免费且开源的；推荐的模型也是免费且开源的。你可以在完全不需要出网连接的情况下本地运行。」

但「默认无 AI」不等于「你的数据就安全了」

这一点必须说清楚，TDF 自己也提示了：

「这些是第三方扩展，处于不同的成熟阶段，**由各自的作者而非 The Document Foundation 开发和维护**。用户和运维人员应像评估任何第三方组件那样评估它们，**检查是否配置了云端端点，以及提供商如何处理它收到的数据。**」

换句话说：默认安装是干净的，但一旦用户自行安装扩展，责任就转移到了用户和运维身上。上面那张扩展表里也有反例：LibreAI、LibreThinker、WriterAgent 都支持云端 API。在受监管环境里，这恰恰是「默认无 AI」挡不住的风险。 给运维的实际含义：「LibreOffice 默认没有 AI」不能作为合规论据，你还得叠加扩展白名单/黑名单策略（比如通过 unopkg 的部署策略限制可安装的扩展）。

六条条件没有覆盖的三个问题

·

输出质量与可追责性：一份由 AI 生成的合同条款如果出错，责任归属和留痕如何？六条只说了「输出必须是 ODF 并保留结构」，没说内容的可靠性

·

生成内容的版权与来源：可能牵涉第三方版权或训练数据来源，这在文档场景下是实质风险。六条没提

·

「完全可选」的执行成本：对企业来说，「可卸载」是一条产品属性，但「确保 5000 台机器上真的没装」是一项运维工作。条件写起来容易，落到自动化部署上需要额外机制

这些不是对 TDF 的批评。它写的是集成政策，而不是AI 使用的完整治理框架。但如果有人把这份清单当成完整的 AI 合规方案，就会漏掉上面这些。

这不是永久决定，重估条件也很明确

「我们列出的标准**并不等于彻底拒绝**。AI 领域发展迅速；**本地推理在标准硬件上正变得可控；而开放模型的进步比我们大多数人预期的要快得多。** 如果出现满足全部条件的方法，**我们会非常仔细地评估它。**」

「本地推理变得可控」+「开放模型进步快」这两条，正好是六条条件里最实际的两个瓶颈（条件 1 和 4 的实现难度）。所以这更像是一个带明确触发条件的观察期，而不是立场宣示。

给 Linux 用户的建议

·

默认安装可以放心用：26.8 不需要网络访问即可运行，没有任何组件依赖联网，这在断网环境下是可验证的

·

想要 AI 的话，优先选本地后端：Ollama 或 LM Studio 的安装成本不高，而且能保住条件 1、2、3。注意选模型：小显存机器可以从 3B～8B 级别起步，本地推理的主要瓶颈是显存而不是 CPU

·

受监管环境务必加一层扩展管控：既然默认干净，那么「保持它干净」就是运维动作：用部署策略限制可安装扩展，比事后排查省力得多

·

顺手清理你在用的其他办公套件：值得花十分钟按那六条过一遍，特别是第 3 条（遥测）与第 4 条（供应商锁定）。这两条在日常使用中最不明显，但在审计时最要命
