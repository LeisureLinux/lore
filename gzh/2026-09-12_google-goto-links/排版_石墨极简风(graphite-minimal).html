Google 把搜索结果链接收进了 google.com/goto ，离线解码已经不可能。

—— Autom 2026-08-27

如果最近从 Google 搜索结果里抓过链接，会发现一个不显眼但很关键的变化：搜索结果的 href 不再是目标网页的 URL，而是 google.com/goto?url=... 这种重定向壳。点过去 Google 才把你转到真正的目的地。

搜索 API 提供商 Autom 把它叫做 Google 的反爬虫更新。意图很明确：让「光爬 SERP HTML 不再能拿到目的地 URL」这件事变得更贵、更慢、更可观测。下面看原文译文，再聊我的解读。

01

WHAT CHANGED

新格式到底长什么样

Google Search 现在把有机结果的链接改写成 google.com/goto?url=...，而不是在 HTML 里直接暴露目标 URL。点结果时，Google 才把你重定向到真实页面。

url 参数用的是一种 Google 自有的编码——不是普通 base64，离线解不出来，看起来像是 Google 索引记录里的某个不透明引用。到 2026 年 8 月下旬，这种格式在登出状态 / 隐私模式下已经稳定出现。

和老格式 google.com/url 的三点差异

1

结果的 href 是 /goto，不是目的地

2

离线解码不了 url= 那坨 blob

3

真实 URL 只在 /goto 的 Location 响应头里——必须 HEAD 读头，不要跟着重定向走到底

「Google 画 SERP 还需要目的地（域名、favicon、署名），所以页面 HTML 里仍有目的地副本。这跟读 Location 头是两件事，不能混。」


02

BIGGER PICTURE

反爬组合拳，不是单点

Google 的反爬升级已经形成「组合拳」。最显眼的三招：

1

撤掉 &num=100——一次拿 100 条结果的隐藏参数失效

2

收紧 BotGuard / SearchGuard——把自动化检测的信号做实

3

goto 重定向壳——把 URL 离线解码堵死

三招叠加的物理含义是：SERP 抓取从「纯 HTML 解析」必须升级到「对每个结果都打一次 Google」。对任何想拿搜索结果建索引的项目，单位成本至少上一个数量级。

这不是单一动作，是 Google 一个长期方向。理解「组合拳」比理解「单个招式」更重要。


∞

MY TAKE

给运维/工程师的 4 条建议

除了「看到反爬组合拳」这一层事实，有几条工程层面的具体动作可以立刻做：

SKILL 1 养成 HEAD 看 Location 的习惯

Location 头不只是给浏览器重定向用——很多中间环节（CDN、网关、反爬壳）都依赖它说明目的地而不强制跟随。先 HEAD 看 Location，需要时再 GET，能省掉无谓下载，也避开污染统计的 302/307 链尾。Go 的 http.Client.CheckRedirect、curl 的 --max-redirs 是验证过的成熟模式。

SKILL 2 别再用 num=100，文档里也删掉

早就失效的参数，写在新文档里只会误导新人。任何「从 SERP 建索引」的脚本都要准备好退路：google.com/goto 之外，Bing / DDG / Startpage 都是备选——多源融合是常态，单押 Google 不再现实。

SKILL 3 真要 Google，走 API 别爬 SERP

Programmable Search、Knowledge Graph、Google Trends 等官方通道都有，这次更新只是把门槛又抬高一截，下次只会更高。「不用付 API 费」的捷径会被持续抬高到不划算的水位。

SKILL 4 浏览器自动化/agent 注意 headless 误伤

很多自动化工具默认跟着重定向走完，很容易被 goto 误伤或被 Google 当成爬虫。Agent 类产品要明确设置合理的 max-redirs、并把 /goto 当成「说明」而非「目的地」。

一句话：Google 没打算封死所有人，但打算把所有「不用付 API 费」的捷径持续抬高到不划算的水位。这是商业策略，不是技术对抗。
