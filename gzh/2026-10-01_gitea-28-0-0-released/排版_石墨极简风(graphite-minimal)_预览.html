默认更安全了，但很多人的现有配置会在升级后失效或行为改变。

—— Gitea 28.0.0 的破坏性变更

Gitea 28.0.0 发布，最大标志是去掉了历史性的 `1.` 前缀（所以是 28.0.0 而不是 1.28.0）。但这个版本真正需要你升级前仔细读的，是一批安全默认值收紧的破坏性变更：Git 网络操作改走内部代理、出网策略必须显式声明、自注册默认关闭、Actions 运行历史默认 400 天过期。

01

EGRESS

最需要关注：Git 网络操作走内部代理

迁移（migrations）、镜像（mirrors）以及其他 Git 网络操作，现在统一走一个内部代理，该代理对直连也应用出网设置。

具体变化

·

`external` 预设被移除。想要默认拒绝的策略，需要设 `EGRESS_MODE = strict` 并显式列出允许的主机。`[migrations] EGRESS_MODE` 管迁移与镜像；`[security] EGRESS_MODE` 管 webhook 与 OAuth2

·

strict 模式下，不带端口的条目只允许 80 和 443 端口

·

默认的 `lax` 模式下，`[security] ALLOWED_HOST_LIST` 不再限制公开主机。想让它继续当排他性白名单，必须设 [security] EGRESS_MODE = strict。如果设置了白名单却没有显式声明 `EGRESS_MODE`，Gitea 会在启动时打警告

·

IP 地址条目不再支持通配符，且 *** 不再是合法条目**

·

非法的 `[migrations] BLOCKED_HOST_LIST` 条目现在会阻止 Gitea 启动

·

`ALLOWED_DOMAINS`、`BLOCKED_DOMAINS`、`ALLOW_LOCALNETWORKS` 已废弃，改用 ALLOWED_HOST_LIST 与 BLOCKED_HOST_LIST

域名条目遵循 curl 语法

·

example.com —— 匹配该域名及其所有子域

·

*.example.com —— 只匹配子域

·

example.* —— 无效

解读：这是把「默认宽松」翻成「默认收紧」。过去你的 ALLOWED_HOST_LIST 在 lax 模式下其实拦不住公开主机——很容易给人「我已经限制出网了」的错觉。新版本要求你明确表态。代价是升级后镜像、webhook、OAuth2 可能集体失灵——因为它现在真的按你写的规则执行了。

02

BREAKING

其余四项破坏性变更

⚠️ Actions 运行历史会过期了

已完成的 Actions 运行，默认在 400 天后被删除，连同它们的 jobs、日志和 artifacts。执行删除的是新的 `cleanup_action_runs` 定时任务，默认在午夜运行。

想保留全部运行记录，升级前设置：

注意语义变了：`0` 现在表示「永久保留」，适用于 RUN_RETENTION_DAYS、LOG_RETENTION_DAYS、ARTIFACT_RETENTION_DAYS。日志和 artifacts 始终随其运行一起删除。 [actions] 段下设 `RUN_RETENTION_DAYS = 0` 即可。

这是本次最容易被忽略、损失又最不可逆的一项——如果你的合规、审计或排障流程依赖一年以上的 Actions 历史，这次升级会静默删掉它们，而且删掉的 artifacts 是要不回来的。

⚠️ 要求 Git 2.25 或更新

Gitea 现在拒绝在低于 2.25.0 的 Git 版本上启动。 自行安装 Git 的，升级前先跑 git --version 确认。

⚠️ 自注册默认关闭，`[server] DOMAIN` 被忽略

·

除非显式设置 `[service] DISABLE_REGISTRATION = false`，否则自注册现在是禁用的

·

Gitea 不再读取 `[server] DOMAIN`。实例域名（含默认 SSH 域名）现在来自 `ROOT_URL`——如果你以前依赖 DOMAIN，请改设 `ROOT_URL`

自注册默认关闭是正确的安全默认，但如果你的部署依赖开放注册（如内部试用环境），升级后会突然没人能注册。域名来源改成 `ROOT_URL` 是更合理的收敛（单一真相来源），但迁移时容易漏，需检查 SSH 克隆地址是否仍正确。

⚠️ Actions 工作流求值更严格

·

Job 级 `if:` 现在在矩阵展开之前求值，且只能使用 `github`、`gitea`、`needs`、`vars`、`inputs` 这几个上下文。依赖 `matrix` 的条件要挪到 `strategy.matrix.include`/`exclude`，或挪到 step 级 `if:`

·

矩阵的 `fail-fast` 现在真正生效了，失败 job 可以取消剩余组合。想让全部跑完，设 strategy.fail-fast: false

·

公开仓库里的工作流不能再调用私有仓库的可复用工作流；嵌套工作流的权限也不能超过调用方

`fail-fast` 从「写了不生效」变成「真生效」，是静默的行为变更——原本指望矩阵全绿的流水线，可能提前中断。而公开仓库不能调私有仓库的可复用工作流，会直接打断那些用「公开仓库 + 私有 actions 仓」模式的组织。

CHECKLIST

升级检查清单

官方步骤：从下载页取包 → 读 breaking changes → 备份数据 → 替换二进制或 Docker 容器 → 重启。以下为补充检查项。

·

备份：数据库 + 仓库数据 + `custom/` 与配置文件。Actions 历史一旦被清理任务删除无法恢复

·

版本号：更新所有写死 `1.x` 的脚本、镜像标签、文档；注意下载文件名不再带 OS 版本后缀、32 位 x86 / gogit / armhf Snap 已取消

·

Git 版本：git --version 必须 ≥ 2.25

·

出网规则：审阅 [migrations] 与 [security] 的白/黑名单；想收紧就设 `EGRESS_MODE = strict`；检查 IP 条目里的通配符（已不支持）和 *** 条目（已非法，会阻止启动）；检查域名条目是否符合 curl 语法**

·

域名：`[server] DOMAIN` 已不生效 → 确认 `ROOT_URL` 正确，并检查 SSH 克隆地址

·

注册：如果依赖开放注册，显式设置 `[service] DISABLE_REGISTRATION = false`

·

反向代理：确认转发 WebSocket 升级头（否则通知与秒表退化为轮询）；多进程部署配置 `[websocket] PUBSUB_TYPE = redis` 及 Redis 连接

·

Actions：检查矩阵 `fail-fast` 的预期（现在真生效了）；确认没有依赖 job 级 `if:` 里的 `matrix` 上下文

·

升级后验证：迁移/镜像功能（最容易踩）、webhook 与 OAuth2、SSH 克隆、登录、Actions 跑一次、通知计数是否实时

顺带说说这次的新能力

·

审计日志（默认关闭，[audit] RECORD_OUTPUT = database，默认保留 30 天）

·

专用机器人账号（用令牌认证、不能交互登录、不收通知邮件）——过去自动化账号只能伪装成普通用户，职责边界模糊

·

管理员模拟用户（复现权限问题不用要密码，审计双记录）

·

仓库级 HTTPS 部署令牌、PR diff 搜索与扩展名过滤、合并前要求 CODEOWNER 审批、Actions 构建队列视图、浏览器预览构建产物

·

实时通知改用 WebSocket（/-/ws 取代 SSE）——反代没改的话会悄悄退化为轮询，这是不明显的升级陷阱

KEY FACTS

关键事实速查

KEY FACTS

项目 内容
版本号 去掉历史性的 1. 前缀（28.0.0 = 原 1.28.0）
出网 Git 网络操作走内部代理；strict 模式需显式白名单
终止支持 32 位 x86 / gogit 构建取消；Snap 不再构建 armhf
Actions 保留 默认 400 天过期；0 = 永久保留（语义变了）
Git 版本 要求 2.25 或更新
自注册 默认关闭，需显式 DISABLE_REGISTRATION = false
域名 [server] DOMAIN 被忽略，改用 ROOT_URL
安全修复 含修复，细节约一周后公布

Gitea 这次的核心主题是把默认值从宽松改成收紧：自注册默认关闭、出网默认受限、非法配置阻止启动。方向完全正确——自托管产品的历史包袱就是「默认配置不安全，而使用者以为它安全」。但代价也很直接：升级后一堆东西会突然不工作，其中一些（出网规则、fail-fast）是静默的行为变更，不会给你明显报错。对运维而言，升级前读 breaking changes 从「好习惯」变成了「必需动作」。
