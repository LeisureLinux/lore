02

READ

解读：一次「收窄边界」的版本

1. Mir 早已不是「Ubuntu 的下一代替换」

Mir 最初想给 Ubuntu 一套自己的显示服务器/合成器栈，和 X、Wayland 正面对撞。多年演化后的真实落点是一个可复用的 Wayland 合成器库——给想自建 shell 的人（嵌入式、消费电子、数字标牌、智能镜子）提供底座。它不去抢 Mutter/KWin 的桌面默认，而是更底层、更可裁剪。

2. Rust 从可选变必需 = OS 目标收窄的连带结果

因果链很清楚：Mir 主动把支持面收窄到 Ubuntu 26.04 LTS+，而该平台 Rust 本就必备，于是 Rust 从「最好有」变「一定有」，MIR_ENABLE_RUST 被删——不再为无 Rust 环境保留退路。这是 Ubuntu 生态 Rust 化的浪花：同期 Ubuntu 26.10 把 cp/mv/rm 全线切 Rust coreutils 完成 100% 迁移，Google 那个「难维护」的 Binder C 驱动也被 Rust 取代。在 Ubuntu 的地盘上，Rust 正从加分项变入场券。代价是构建门槛提高，但 Mir 本就不以无 Rust 平台为目标。

3. 新增 wl_fixes = 跟着 Wayland 上游走的成熟信号

wl_fixes 是 Wayland 体系里修补核心协议历史设计遗留的一套协议。Mir 跟进它，说明项目在主动对齐 Wayland 上游协议演进，而不是自成一套。对一个合成器库来说，协议兼容性就是可用度。

03

ROADMAP

首次公开路线图：最有信息量的事

一个项目愿意把「接下来做什么」摊开写进文档，通常意味着它进入了产品化/长期维护的节奏。逐条拆：

·

硬件 plane 做视频播放：视频帧直接进显示控制器 overlay plane、绕开合成器全屏重绘——嵌入式/媒体设备的省电省 CPU 手法

·

全 Rust 的 Mir 合成器：不只输入平台用 Rust，而是整个合成器搬进 Rust，和「Rust 硬依赖」是组合拳

·

稳定 mir-shell 扩展：从「能跑」到「第三方可依赖」——只有接口冻结，别人才敢把产品压上来

·

长期渲染管线设计：架构层面的债提前还，避免渲染路径反复推倒重来

·

Mir shell 的 systemd 集成：与 Ubuntu 引导/服务模型对齐，是「和平台长在一起」

·

安全改进：任何要跑在政企/消费终端上的显示栈几乎必选项

对自建 Wayland shell 的开发者：用 Mir 意味着接受「Rust 工具链是前提」，换来更明确的长期路线与更稳定的扩展面。

解读 边界收窄 = 走向长期主义的信号

Mir 2.30 不是一次功能大爆炸，而是一次边界收窄——把支持面押在 Ubuntu 26.04+、把构建押在 Rust、把未来押进一份公开路线图。对一个已经「退到幕后当库」的项目来说，这种收窄恰恰是走向长期主义的信号：先想清楚自己不做谁，再决定自己能做多久。
