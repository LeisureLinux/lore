本文对 Emaki 四条设计原则的归纳

Emaki 是一个由一个人做出来的、基于 Arch + niri 的完整桌面。而它最值得看的不是「又一个 tiling 桌面」，是它把「桌面环境」重新定义成了「一个你不需要理解的产品」。官网原话：装好即用，之后不再碰配置 —— 「而不是去读十二个 wiki」。实测数据：13 天发了 9 个版本（0.6.0 → 0.12.0），仓库只有 1 个贡献者、35 个 commit。作者是 Artur Yakymenko（Yakyman）。

01

WHAT IT IS

先把它是什么说清楚

README 第一句：「Emaki 是一个基于 Arch 的桌面，围绕 niri-emaki（niri 这个滚动平铺 Wayland 合成器的 fork）和它自己的 Quickshell shell 构建。」

·

底座：Arch Linux —— 不 fork、不扣留包、滚动发行版就明说滚动发行版

·

合成器：niri-emaki —— niri 26.04 + 14 个补丁的 fork

·

Shell：自有 Quickshell shell —— 面板、dock、启动器、通知、锁屏、登录屏

「Quickshell shell」是理解 Emaki 的关键 —— 这意味着它不是「niri + 某个现成桌面」，而是自己在 niri 上写了一整套 shell。

那 14 个补丁说明了什么

「活体壁纸、shell 的玻璃捕获、从登录屏的无缝衔接、动画概览背景、分数缩放下的清晰光标，以及在无法创建 GPU 渲染器时给出不同的退出状态；再加上锁定会话的捕获保护、静态模糊遮蔽计数、为映射的 shell 层保留键盘焦点，以及带合成器输入隔离和物理 Ctrl+Alt+Delete 证明动作的可信认证连接、会话期间其他程序无法更改的安全键绑定、被标记为 shell 自身的屏幕录制、位于可见面板下方的全屏窗口，以及窗口切换器图片的平铺窗口位置。」

这一串读下来能感觉到一件很具体的事：作者在做的事情，是把「niri 从一个极客工具变成一个普通用户能用的桌面」所缺的那一层补丁，全部补齐。比如「全屏窗口从可见面板下方开始」「分数缩放下清晰的光标」—— 这些都不是「更炫」的功能，是「不这么做就会烦」的细节。

02

THE FOUR RULES

⭐ 四条原则：Emaki 真正卖的是什么

⭐ ① 你的改动是你的 —— 配置分成两个文件

「我们的默认值是单独一个文件，属于软件包。你的改动放在你自己的文件里，它 include 了我们的，并在 niri 允许后设置胜出的地方覆盖它。我们从不写你的文件；你也永远不需要编辑我们的。因此更新不会与你的自定义冲突。」

这一条比任何花哨功能都重要，因为它解决的是「不敢升级」这个心理障碍 —— 而不敢升级是所有桌面发行版流失用户的头号原因。

⭐ ② 你的磁盘你做主 —— 文件系统不替你决定

「文件系统由你选。选 btrfs，Emaki 会为你配置快照工具：每次包变更前一个快照，以及从启动菜单回去的路。选 ext4，你得到 ext4。这里没有什么是强加给你的。」

ext4 的降级路径设计得很实在：「如果新内核是问题所在，在启动菜单里选 linux-lts 那一项。否则从缓存里用 sudo pacman -U 重装之前的包。如果桌面起不来，Ctrl Alt F3 打开文本控制台。」—— 最后那句「还有文本控制台兜底」，是那种只有真的想过「用户会搞砸系统」的人才会写进文档的话。

⭐ ③ 底下是 Arch —— 滚就明说

「Emaki 底下是 Arch。我们不 fork 它，我们不扣留包，我们不假装滚动发行版是别的东西。当 Arch 坏掉时，Arch 就是坏掉。其他一切都是 Arch，我们大声说出来。」

这一条在 2026 年的 Linux 发行版生态里几乎是一种宣言 —— 过去几年不少「用户友好」的 Arch 衍生版会冻结包、扣留包、改包，让滚动更新保证失效。Emaki 明确拒绝这么做。而代价是可见的：上游问题会直接砸到用户脸上。Emaki 的对策只有两个：更新前自动快照 + 启动菜单回滚（btrfs），以及两个内核并存（linux 与 linux-lts）。—— 这是它架构里最聪明的一处：它没有试图「修好 Arch」，它只是给了 Arch 一个安全网。

⭐ ④ 为阅读而生 —— 没有黑魔法

「一个设置只存在于一个地方。没有东西在你背后被重新生成。每一块状态都能从终端查询，每一个设置都能从终端更改。」

配套的杀手锏是 emaki 命令：「system map and state」，以及 niri 的窗口/工作区命令。一个宣称「每个状态都能从终端查询」的项目，给了一个「打印系统状态图」的命令 —— 这是最自然的落地方式。

03

PROGRAMS & UPDATES

Programs & Updates：把 Arch 的三套包源收进一个窗口

官网描述：「程序用一个按钮安装：找一个，按 Install。不用终端。更新在同一个窗口里，在 btrfs 上还有回到更新前系统的路。」

·

四个标签页：Browse、AUR、Installed、Updates，各有各的搜索

·

评分和评论：用 GNOME Software 和 KDE Discover 同一个开放评分服务，你也可以写自己的

·

目录在安装后立即可用，在第一次更新之前 —— 靠内置索引，不是联网抓取

·

「Undo this install」：安装的程序能一键收回，它加了什么就删什么，你的文件留着

⭐ 关于 AUR 那句警告，值得单独拎出来

「AUR，在 Programs & Updates 自己的标签页里。它只在一句明确的警告之后打开：任何人都可以在那里发布，没人检查它，Emaki 也不检查，Arch 也不检查。」

AUR 是 Arch 生态里最大的用户风险来源之一（包是任意用户写的构建脚本，运行时以你的身份执行）。大多数衍生发行版会悄悄提供 AUR 支持，或用一句模糊的免责声明带过。Emaki 把它单独放在一个标签页里，加一句明确的警告，还说明「密码提示会写明来源是 AUR」。在一个把 GUI 友好当核心价值的项目里，这句警告的分量比任何功能都重。

而 release notes 里也有一条很实在的修复记录：「Programs & Updates 在目录很大时不再卡死，重新打开时保留目录，并安静地刷新它。」—— 一个 GUI 包管理器在几千个包上卡死然后被修掉，这个过程本身就是这个功能难度的证明。

04

THE SUDO KEY

⭐ 那个专门给 AI agent 用的包

v0.6.0 release notes 原文：「sudo key，一个可选的包，给使用 AI agent 的人。不用为每条命令都输入密码，而是你给一个 agent 管理员权限，限时若干分钟、若干轮对话，或整个会话。面板指示器显示每一个活跃的 key，Super+Ctrl+Esc 一次性结束它们全部。」

·

粒度：传统 sudo 是每条命令一次密码；sudo key 是一次授权，覆盖 N 分钟 / N 轮 / 整个会话

·

撤销：命令结束即失效 → 面板指示器可见，Super+Ctrl+Esc 一次性全撤

·

可见性：只有输入密码时的提示框 → 面板上有常驻指示器

⭐ 为什么这件事重要？因为 AI agent 的工作模式和 sudo 的授权模型在结构上不兼容。一个 agent 跑 50 条命令，传统做法是 50 次密码输入 —— 这在自动化流程里根本没法用；而一次性给永久 root，又太宽松。Emaki 的答案是「限时 + 可视 + 一次撤销」—— 正好对应 agent 授权的三个真实需求：时间边界、状态可见、紧急刹车。

⭐ 同期还有一件相关的事：一个「你只能相信」的密码提示框

「一个你能信任的密码提示。当程序请求管理员权限时，Emaki 显示一个只有系统本身能绘制的提示。在它打开时按 Ctrl+Alt+Delete，会出现一个其他程序无法伪造的标记。」

「按 Ctrl+Alt+Delete 时出现一个无法伪造的标记」—— 这是物理证明动作（proof action）机制：截屏软件能伪造画面上的任何东西，但伪造不了「你在物理上按了某个键」这件事。这是 DRM 里用了二十年的老招数，被搬到了 Linux 提权提示上。

而同一个 release 里还有一条：「给 Claude Code 和 Codex 的一份规则模板，告诉它们 Emaki 是怎么布局的。」

—— 所以 Emaki 对 AI agent 的态度不是「排斥」，而是「专门做支持」。这对 2026 年的 Linux 桌面来说是个很新的方向。

SECURE BOOT

Secure Boot：一个「先开着再说」的少见选择

大多数 Linux 发行版在 ISO 里默认关掉 Secure Boot。Emaki 默认开着。

「1. U 盘显示『Verification failed: (0x1A) Security Violation』，选 OK。2. 蓝色『Shim UEFI key management』屏幕（MokManager）倒数 10 秒，按任意键。3. 选『Enroll key from disk』→ EMAKI → emaki.cer。4. 选『View key』，把 SHA-1 指纹和发布页上那个对比。然后『Continue』→『Yes』→『Reboot』。不需要密码。」

—— 「View key 然后对比指纹」这个步骤，很多发行版只说「去 MokManager 选 Enroll」，不会告诉你该对比什么。Emaki 给了指纹，还告诉你怎么比对。

⭐ 背后的根本判断

「Secure Boot 可以保持开启，如果固件信任微软的第三方 UEFI 证书（2011 或 2023）；如果两个都不信任，就在固件设置里打开那个选项。」

也就是说：Emaki 的 Secure Boot 方案建立在「微软第三方 UEFI CA」之上，而不是自己维护一条 shim 信任链。这和 Fedora、openSUSE 那套「自己签 shim、自己维护 CA」的路线不同 —— 代价小得多，但依赖微软的证书继续被固件信任。

GPG 签名也做了：官网给出 .sig 和签名公钥 .asc，让你 gpg --verify，并写明「期望看到 Good signature from Emaki Package Signing」。另外每个镜像旁边还有 SOURCES-ISO.txt，列出镜像里每一个 Emaki 包的源码出处 —— 这个做法比大多数发行版认真。

NIRI

niri 的工作方式：为什么「滚动平铺」值得单独一节

「大多数桌面把窗口挤进屏幕里。niri 不是。你的窗口并排坐在一条很长的带子上，屏幕只是这条带子的一段视图。新窗口开在当前窗口右边；其他什么都不变小。」

·

Super ← / → 沿带子移动，放不下的窗口在边缘露出一部分

·

Super ↑ / ↓ 在楼层（带子）之间移动；Super O 缩小并一次显示全部

·

Super R 在三分之一、一半和三分之二之间循环窗口宽度

这个模型对「屏幕小」的场景特别友好 —— 而这恰好是「旧硬件」和「笔记本」这两类最需要它的场景。而且因为窗口从不缩小、只横向排布，「你的布局」是一个有序的、有逻辑的位置序列，而不是一堆堆叠的矩形。在滚动平铺里，「我刚才把那个终端放哪了」这个问题基本不存在。

⭐ 相关的行业动态：Wayland 的远程显示协议

「瞬态输出协议可以被特权客户端用来创建独立的虚拟输出，当客户端销毁对象时这些输出会从合成器移除。该协议用于配合诸如 ext_output_image_capture_source_manager_v1 这样的输出捕获协议，以支持远程使用场景。本协议创建的 wl_output 全局不绑定到任何特定硬件设备。」

—— Wayland 开发者 Simon Ser 于 2026-10-25 提出（wayland-protocols MR 546）。在 Wayland 下做远程桌面（VNC/RDP 转发屏幕给远程客户端）一直很别扭 —— 合成器不提供「创建一个虚拟显示器让我抓」的正规途径。有了 ext-transient-output，VNC 服务器就能创建虚拟输出、用标准捕获协议抓它、销毁时自动消失。

而它的设计取舍很有意思 —— MR 描述里 Simon Ser 自己列了三个设计决定：「内置输出配置」（不依赖 wlr-output-management，因为「虚拟输出有硬件输出没有的怪癖」）、「缩放配置留给未来扩展」、以及「Commit ACK」—— 并直接自问「客户端没有一个事件表示 commit 已被处理，这合适吗？有什么用例？需要序列号做匹配吗？」—— 一个协议设计者把「我还没想清楚的地方」写进 MR 描述里，这种写法本身值得记一笔。

KNOWN ISSUES

⚠️ 作者自己列的那些已知问题

Emaki 的 README 有一整节叫「Known issues in 0.12.0」，这比任何宣传都更能说明成熟度。

·

休眠：在测试的 MacBook 上，休眠恢复后会话无响应。请不要用休眠。

·

与 Windows 并存：只要 Windows 没完全关机，Emaki 就不会改动系统包；Windows 睡眠时它会停下并告诉你怎么关

·

旧更新地址：迁移到 pkgs.emaki.sh 后会打印一次「emaki: missing required signature」，下次更新就正常

·

应用启动器在非英语下只能按英文名找到设置程序

·

已安装系统的启动菜单在任何语言下都保持英文

⭐ 官网最诚实的一句

「如果你在真实硬件上装了 Emaki？我们最需要来自我们没测过的电脑的报告：带 Secure Boot 的 NVIDIA 显卡，或者带 BitLocker 的 Windows 并存于 Emaki 旁边。告诉我们什么能用、什么不能用。」

—— 「我最需要的是坏消息」这种写法，比任何 changelog 都更能说明作者的心态。而「What we tested」一节也写得很克制：「Emaki 是后期 alpha。每个版本都在虚拟机里以多种屏幕尺寸、在两台真实电脑上安装和更新：一台 AMD 笔记本和一台 MacBook。还没测试：真实硬件上的 NVIDIA 显卡，以及与 Emaki 并存的带 BitLocker 的 Windows。」

PACE & VERDICT

⭐ 13 天 9 个版本，以及我的评价

⭐ v0.7.0 的 release notes —— 我见过的最诚实的一次自我批评

「我们在 0.6.0 和 0.7.0 上犯了错误。在 0.6.0 上，真实硬件测试发现安装器里一个 bug：它停在时区那一步。我们修了，但没有发布修好的镜像，打算把修复放进 0.7.0 一起发。在 0.7.0 上我们犯了更大的错：我们发布了它，并把它移到了 stable 频道，而没有在真实硬件上测试。每个版本在进 stable 之前都要经过那个测试，而这一版跳过了。我们不会事后测试 0.7.0，所以这一版也没有安装镜像：请安装 0.5.0 然后更新。这不会再发生。」

—— 「这不会再发生」，并把 0.7.0 的镜像撤掉。这是一个人做的项目，但我见过的团队发布纪律不如这个清楚。

⭐ 我的评价：它解决了什么

Linux 桌面有一个长期的结构性问题：「桌面环境」这个词在 2026 年仍然意味着「一堆需要你调的东西的集合」。每一个发行版都把这份工作推给了用户，而绝大多数用户不想做。Emaki 的回应是：把这份工作做完，然后交付一个成品。

⭐ 「我替你做决定，但我尊重你的所有权，并且我保证你能反悔。」

这比「可定制」更激进 —— 可定制说的是「你什么都能改」，Emaki 说的是「你什么都不用改，但如果你要改，也不会被更新冲掉」。

⚠️ 三个天花板

·

① 单一贡献者 + 极新 = 巴士因子。 实测只有 1 个贡献者、35 个 commit、4 stars、0 fork；作者本人在 PLANS.md 里用第一人称写「我是 Arthur」。而且它建立在 niri 和 Quickshell 两个上游之上

·

② 「不扣留包」的代价是真实的。 上游问题直接砸到用户脸上，而对冲手段只有快照（仅 btrfs）和双内核两个

·

③ 它解决的痛点可能不是最大众的痛点。 「十二个 wiki」最强烈地出现在「刚接触 Linux 又不想装 Arch」的人身上，而这部分人群的规模，Emaki 自己的数据给不出答案

⭐ 但有一件事值得单独说：Emaki 最值得借鉴的不是任何具体功能，而是它对「发布纪律」的态度 —— 撤镜像、公开认错、README 里一整节 Known issues、AUR 页上写「没人检查它」。在一个大部分发行版把 release notes 当营销素材的环境里，这种写法本身就是一种差异化。

⭐ 而且如果它是你的机器（NVIDIA + Secure Boot，或 Windows + BitLocker），官网的建议很明确：先从 U 盘试，备份，再装。

Emaki 解决的是一个所有人都见过、很少有人认真对待的问题：Linux 桌面至今仍然意味着「一堆需要你调的东西的集合」。Emaki 的回应是把这个工作做完，然后交付成品 —— 配置分成官方和你的两个文件、更新不与你的自定义冲突、btrfs 上每次包变更前自动快照、可以从 GRUB 菜单回滚、Secure Boot 保持开启、AUR 页面写明「没人检查它」。这背后是同一条主线：可定制说的是「你什么都能改」，而 Emaki 说的是「你什么都不用改，但如果要改，也不会被更新冲掉」。真正让我觉得值得写的不是它的功能清单，是它的发布纪律 —— 0.7.0 因为没做真实硬件测试而撤掉镜像并公开认错，README 里有一整节 Known issues 包括「请不要用休眠」，PLANS.md 里说「我测不了每一台电脑」。在一个大部分发行版把 release notes 当营销素材的环境里，这种写法本身就是差异化。而那个给 AI agent 用的 sudo key 尤其值得留意：限时、可视、一次撤销 —— 这三个词正好对应 agent 提权的三个真实需求，而传统 sudo 的模型在结构上就不适合 agent。当然，前提仍然是那句老话：alpha 阶段，别装在你要依赖的电脑上。
