01

WHAT

Waydroid 到底是什么：容器，不是模拟

要理解「原生感」从哪来，先纠正误解：Waydroid 不是 Android 模拟器。

模拟器 vs 容器

模拟器（AVD/QEMU）是跑一整套客户机系统，CPU/显卡靠软件或二进制翻译，开销大、延迟高。Waydroid 是容器/命名空间方案：在宿主机上启动一个 Android 用户空间（LineageOS，Android 13），与宿主共享同一个 Linux 内核。

原生感从哪来

Android 的 binder/IPC、图形栈通过 LXC 风格隔离 + 内核模块对接宿主。Android 应用以普通窗口出现在你的 Wayland 桌面——而不是「模拟手机窗口里再套一层」。这就是「feel native」的来源。

一句话：它把 Android 当成一个 Linux 上的「第二个用户态」来跑，不是一台虚拟机里的另一台机器。

02

PREREQ

落地前置：两道硬性门槛

门槛一：必须是 Wayland 会话

Waydroid 图形依赖 Wayland 合成器，Xorg 下不可用。已是 Wayland 桌面（GNOME/KDE/Sway/Hyprland/Budgie+Labwc）通常直接可用；若还在 Xorg，可用 Weston 或 Cage 嵌套出 Wayland 会话来跑（有额外一层合成开销）。

门槛二：内核必须带 binder 支持

Android 的 IPC 核心是 binder。最省心做法：装 Zen 内核（社区维护、默认开启 binder/Ashmem 等 Android 容器所需选项）；自编译则要打开 CONFIG_ANDROID_BINDER_IPC 等并加载模块。

安装（Arch 为例）

从 AUR 装 waydroid → 初始化（拉取 Android 13 / LineageOS 镜像）→ 启动容器服务 → Wayland 下 waydroid show-full-ui 进 Android 桌面或直接启动 app。Arch/AUR 打包与文档最成熟；Ubuntu 有官方 PPA、Fedora 有 COPR。

03

GPU

GPU 支持矩阵：最大的变量

Waydroid 的硬加速几乎只认 Intel / AMD，这决定「流畅还是卡死」：

·

Intel：支持最好，开箱即用，验证最充分。

·

AMD：大多正常；较新 GPU 可能需自建 Waydroid 镜像才能拿完整支持。

·

Nvidia：长期问题最多；有实验性专用版本承诺完整硬件支持但仍在开发，否则只能退回很慢的软件模拟。

结论：Intel 最轻松，AMD 多半能跑（新卡自建镜像），Nvidia 目前基本是「等实验版 / 忍软件模拟」。显卡品牌直接决定体验下限。

适合谁 / 局限

适合：需要 Android 独占应用或游戏、且已在 Intel/AMD + Wayland + binder 内核 上的人。不适合：Nvidia 用户、必须 Xorg 且不愿嵌套者、保守发行版默认内核（需先解决 binder）。默认镜像不含 GMS，依赖 Google 移动服务的场景需自行用 microG / 处理签名。
