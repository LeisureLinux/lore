# Fedora 45 Beta 发布：默认限制 ptrace、kmscon 换掉 fbcon、Anaconda 原生装 Stratis

> 原文：[Fedora 45 Beta now available](https://www.redhat.com/en/blog/fedora-45-beta-now-available)（Red Hat 博客，2026-09-15，作者 Jef Spaleta，Fedora 项目负责人）。本文由 LeisureLinux 翻译整理并加注解读；文内所有事实与版本号均来自原文，未作改动。

Fedora 45 Beta 已开放下载。按官方定位，Beta 是**代码冻结后的预览版**，与最终 GA 版本非常接近——换句话说，现在能测到什么，正式版大致就是什么。

这个周期的主线很清楚：**装机器的方式、控制台的样子、以及供应链与进程边界的收口**。

---

## 译文：Fedora 45 Beta 带来了什么

### 桌面、安装器与系统现代化

| 变更 | 内容 |
|---|---|
| **Anaconda 集成 Stratis** | 可以直接把 Fedora 装到 Stratis 管理的存储卷上。支持 Kickstart 自动安装，也支持基于 Cockpit Storage 的 Anaconda WebUI 手动配置——开箱即得精简置备、池化与快照能力 |
| **kmscon 取代 fbcon** | 用用户态虚拟终端 `kmscon` 替换内核里的传统 `fbcon` 控制台，换来更好的渲染、国际化支持、更顺的视觉衔接，以及更好的控制台安全性 |
| **oo7 作为默认密钥服务** | 桌面各变体改用 `oo7` 作为默认的 Secrets Service 实现，统一 GNOME、KDE 等桌面环境的凭据处理 |
| **Atomic 桌面统一镜像构建** | Silverblue、Kinoite 等 Fedora Atomic 桌面改用 `image-builder` 而非 `lorax` 构建磁盘镜像，构建流水线统一，并直接产出可用的 raw 与 qcow2 云/虚拟化镜像 |
| **bash-color-prompt 1.0** | 默认终端体验重写，基于 `PROMPT_COMMAND` 实现轻量、动态、易定制的命令提示符 |
| **RPM 仓库配置挪到 `/usr`** | 打包的 RPM 仓库配置文件从 `/etc/yum.repos.d/` 移到 `/usr`，把厂商默认值与管理员本地定制分开，更贴近标准的无状态系统布局 |

### 安全与包管理加固

| 变更 | 内容 |
|---|---|
| **默认限制 ptrace** | 为防御恶意软件检查或注入运行中的进程，非特权 `ptrace` 通过内核 sysctl 设置**系统级默认受限**。安装开发调试工具后会自动启用完整调试能力 |
| **强制 RPM 签名校验** | 向 RPM 上游默认值看齐，包安装与升级现在**开箱严格校验签名** |
| **DNF5 保护厂商仓库** | `allow_vendor_change=False` 成为默认，防止依赖解析或升级时自动跨冲突的第三方仓库切换包——除非用户显式命令 |
| **标准化 PURL 元数据** | 引入 Package URL（PURL）标准标识符，打通上游仓库与下游包管理的供应链追踪 |
| **可复现构建里程碑** | 在数个周期的基建工作之上，Fedora 45 的包构建**正式以 99% 可复现性为目标** |

### 语言运行时与开发者工具

- **GNU 工具链**：GCC 16.2、Glibc 2.44、Binutils 2.47、GDB 17.2
- **LLVM 23**：所有 LLVM 编译器工具与子项目全面更新
- **Python 3.15**、**Go 1.27**、**Perl 5.44**（年度刷新，含上游语言修复与 CPAN 兼容性更新）
- **Ruby on Rails 8.1**、**Podman 6**（下一代容器执行与 rootless 管理）
- **数据库**：MariaDB 12.3、MySQL 9.7 成为发行版默认

### 怎么参与测试

官方给了三条路径：按 Fedora 缺陷报告指南往 Bugzilla 提票；在 Matrix 的 `#quality:fedoraproject.org` 频道或测试邮件列表直接对接 QA 团队；以及先在 Ask Fedora 的「Common Issues」分类里查已知问题与规避方法。

因为这是预发布版本，可能遇到边缘 bug 或不完整的迁移。镜像在 getfedora.org 下载，升级前记得先完整更新系统。

## 解读：这份清单里真正值得工程师注意的四件事

**1. 默认限制 ptrace，对调试工作流的影响要提前想清楚。**

这条是本次最可能"咬人"的变更。非特权 ptrace 系统级受限之后，随便 `strace -p` 别人的进程、或者用 gdb attach 一个非自己启动的进程，都会失败——这对生产环境的排障习惯是实质性改变。

官方的缓解设计是：**装开发调试工具会自动开启完整调试能力**。所以对开发机基本无感，但对于那些"不装 debug 包的生产机 + 临时 scp 一个 strace 上去查问题"的做法，需要重新规划。这是典型的**用默认值提升基线安全、把便利性交给显式配置**的取舍，方向正确，但值得在升级前确认你的 runbook 是否依赖它。

**2. `kmscon` 替换 `fbcon` 是控制台层的一次架构迁移，不只是"换个终端"。**

把虚拟控制台从内核态移到用户态，影响面比看起来大：渲染质量、国际化（CJK 宽字符、组合字符在 fbcon 下长期是痛点）确实会改善，但**早启动阶段（early boot）、救援模式、以及无 GPU 驱动环境下的控制台行为**都会变化。这类底层替换的坑通常出现在最不方便的时刻——比如系统起不来、只能用控制台救的时候。

对运维的建议很朴素：**在虚拟机里先跑一遍"无法启动 → 控制台救援"的路径**，而不是只测日常使用。

**3. RPM 仓库配置搬到 `/usr`，是"无状态系统"路线的又一步。**

`/etc` 留给管理员、`/usr` 归厂商，这条分界线在 systemd 的 stateless 讨论里讲了很多年，现在落到了仓库配置这个具体位置上。短期影响是：**你写过的那些直接改 `/etc/yum.repos.d/` 的自动化脚本、配置管理模板、容器构建步骤，升级后会失效或行为不一致**。正确的新姿势是把本地定制放到 `/etc` 下的覆盖层（例如 drop-in），而不再去改那些文件本身。

顺带一提，DNF5 的 `allow_vendor_change=False` 和严格的签名校验，方向都是**让包管理默认更保守**——这在混合了第三方仓库（如 RPM Fusion、厂商仓库）的机器上，可能会让你发现某些"以前自动能装上"的包现在需要显式命令或显式授权。这是设计意图，不是 bug。

**4. 99% 可复现构建是个被低估的里程碑。**

可复现构建的价值不在"能验证"，而在于**它是供应链完整性的地基**：只有构建结果可复现，独立第三方重构建并比对哈希才成为有意义的验证手段，二进制与源码的对应关系才可证明。99% 这个数字也值得注意——它意味着**剩下 1% 是明确记录在案的例外**，而不是"我们没做到"。这种"把没做到的也说清楚"的工程诚实，比一个笼统的"支持可复现构建"有用得多。
