# 文件通知攻击：Linux / Windows / macOS 的文件监控子系统正在泄漏你的操作

> 原文：File Notification Attacks: Templating and Exploiting Side-Channel Leakage from the File-Notification Systems on Linux, Windows, and macOS（Graz University of Technology，Sudheendra Raghav Neela 等，CCS 2026，2026-09-18 预印本）。论文主页：[inoti.fyi](https://inoti.fyi/)。本文由 LeisureLinux 编译整理并加注解读。

现代操作系统（Linux、Windows、macOS）都内置了监控文件系统事件的子系统：**inotify、ReadDirectoryChangesW、FSEvents**。用户进程可以订阅这些通知——当被监控的文件或目录上发生访问、写入、打开、关闭等操作时，就会收到事件。但**这些通知系统打开的攻击面一直没有被充分理解**：此前的工作只表明「文件打开事件能在 Android 上泄漏应用启动」。

这篇论文提出了**首个针对 Linux、Windows、macOS 的通用「文件通知模板攻击（file-notification template attack）」**，可以窥探各类系统与用户活动。

## 译文：攻击怎么做的

攻击分两阶段：**模板化（templating）**与**攻击（attack）**。

**模板化阶段（攻击者控制的离线阶段）**：系统性地、半自动地扫描，通过「用户活动 ↔ 文件操作事件」之间的**因果分析**，发现可被利用的文件通知信息泄漏。论文模板化了一大类用户活动：运行终端命令、物理键盘与鼠标输入、浏览网页、Web 服务器活动、打印、运行虚拟机与容器、更改连通性设置（蓝牙、网络、VPN）、与 USB 设备交互。

关键点是效率：在**单次**用户活动过程中，监控整个系统文件系统上发生的**所有**文件操作事件。因此与前人模板攻击不同，模板化阶段的耗时**由用户活动本身决定，而不是由搜索空间决定**——因为攻击者不是「发起侧信道攻击」，而是**直接以操作系统为预言机（oracle）**获取信息。

- 在 **Linux** 上，`/dev` 和 `/usr` 尤其暴露大量侧信道泄漏——**仅用 `/dev` 中 2 个文件**就能做本地/远程击键时序，**用 `/usr` 中 1448 个文件**就能做网站指纹。
- 模板把系统、用户、应用活动映射到特定文件上的事件。

**攻击阶段**：用这些模板 + 文件通知子系统来窥探用户活动。子系统的开销**最高仅 0.21% CPU**，可实现 **0.2 ms 到 11.5 ms** 的时间分辨率。

## 译文：各平台上的攻击结果

**Linux**（本地与远程 SSH 击键时序攻击，F1 分数 **93.1%–100%**，7 名用户，66% 的按键在 1 ms 内；对 **KDE Plasma 6（Wayland）** 的实际认证 UI 覆写攻击；对**前 100 网站**的网站指纹，开放世界设定下 F1 **87.9%**）。

**Android**（基于 Linux）：用模板方法论超越前人工作，发现一个**新的非特权原语**，能揭示**应用无法访问的、受权限保护的文件是否存在**，从而推断用户活动（例如 WhatsApp 的使用）。

**Windows**（最严重）：任何**非特权用户都能泄漏所有文件的完整路径**，**即使对该目录没有读权限**（例如用户主目录）——直接泄漏用户与应用的**文件使用情况**，可被利用来可靠监控网站访问：**仅一次扫描**，对**前 1000 网站**的 F1 达 **97.8%**。

**macOS**：观测到**最少**的泄漏量，但仍足以监控特定应用启动与交互。

## 译文：核心成因——连「没有读权限」都能监控

论文的根基事实是：**非特权用户可以动用文件通知子系统**。更糟的是：

> 虽然 Windows 与 Linux 有完全独立实现，我们**在两者上都发现了「无需读权限即可获取文件事件」的方法**。也就是说，一个非特权攻击者可以监控**它自己根本读不了的文件的**事件**——例如 Windows 上其他用户的个人目录。

关键洞察是：**文件的存在与否、文件名本身，就已经能泄漏大量信息**。而这也是 Windows/Linux 上最强攻击（实时网站访问的直接泄漏、击键时序攻击）的基础。

**披露与厂商回应**：论文于 **2025 年 10 月**负责任披露给 Linux、Windows、macOS、KDE 的安全团队。所有厂商都承认了发现，**Linux 已部署部分补丁**。但——

> 我们向微软披露后，他们在回应中称，这种「损害隐私的、未文档化的行为」是 **by-design（设计如此）** 的。

微软的具体说法是：该行为「只揭示另一个用户 profile 目录内的**文件名与路径**，不暴露文件内容或敏感数据」。

## 解读：为什么这篇论文重要

**1. 「文件名 + 时序」被当成侧信道，是这次攻击最反直觉、也最致命的地方。**

传统侧信道攻击（缓存、功耗、时序）大多需要特殊硬件或精细的微架构知识。这篇论文的攻击**完全不需要特殊硬件**（hardware-agnostic），只用**操作系统公开提供的文件监控 API**——任何普通进程都有权调用。它利用的信息源是两类「看似无害」的元数据：**哪些文件被访问了、什么时候被访问**。而正是这两样，让攻击者能重建**你按了键、你在打字、你打开了哪个网站、你在跑什么容器**。

**2. Linux 上的具体泄漏点，暴露了「公开可读目录」这个被忽视的设计面。**

论文最有工程含义的细节之一是 **`/dev`**：一台测试机上 `/dev` 有 **278 个不可读文件**，却都能触发通知。因为**父目录 `/var/log`、`/dev` 等是公开可读的**，非特权用户即使读不了 `syslog` 本身，也能监控 `/var/log` 目录、收到**目录内所有文件**（包括 `syslog`）的通知——这就是「**不可读文件绕过（Unreadable File Bypass）**」。
   
- `/dev/input`：键盘/鼠标输入会触发对应 event 文件通知 → **击键时序攻击**（每次按键产生两个通知：key down、key up）；攻击者甚至能靠访问模式区分触摸板（密集突发）与键盘（零星访问）。
- `/dev/snd`、`/dev/bus/usb`、`/dev/tun`：分别泄漏音频设置交互、USB 插拔、VPN 是否激活。
- `/usr/share`：KDE 搜索菜单每次按键都在 `.../searchproviders/` 触发事件；Firefox 浏览不同网站会访问 `/usr/share/fonts/` 下**不同的字体文件** → **网站指纹**。

这提醒系统/发行版设计者：**「目录可读」不等于「目录内容安全」**，尤其当目录里混有敏感文件时。

**3. Windows 的 by-design 回应，是一个「结构性风险」而非「补丁遗漏」的典型样本。**

Windows 上「非特权用户可泄漏所有文件完整路径、即使无读权限」，微软回应是 **by-design**、且辩解「只暴露文件名路径、不暴露内容」。论文作者的隐含反驳是：**文件名与路径本身就是敏感信息**——它足以让攻击者对前 1000 名网站做 97.8% F1 的指纹识别。**当厂商把「元数据泄漏」定性为「设计如此」，就意味着这类漏洞不会有 CVE、不会有补丁、不会有升级提醒**——它从「可修复的 bug」变成「必须靠架构缓解的既成事实」。这正是安全工程里最棘手的一类问题：**它不是错误，而是特性。**

**4. 缓解方向：细粒度权限模型 + 更强的文件通知 API。**

论文结论明确：因为文件通知攻击是**横跨所有现代操作系统**（尽管它们各自独立开发）的通用安全问题，缓解措施——包括**改进细粒度用户权限模型**和**增强文件通知 API**——对保护用户隐私与系统安全至关重要。落实到实践：对高敏感环境，需要考虑「谁有权监控哪些目录的事件」这个此前几乎无人审视的权限面。

**5. 对普通用户的现实意义。**

- 在**多用户 Linux/Windows 主机**上（共享服务器、多用户工作站），一个低权限账户可能正在 passively 窥探你的键盘时序、网站访问、容器/VM 活动。
- 单用户桌面受影响较小（攻击需要「第二个本地用户代码执行」的威胁模型），但**一旦有低权限服务被攻陷**（论文提到 systemd 下服务常以非特权用户运行，可被攻陷，如 XZ Utils 事件），这条通道就成了后门式的情报来源。
- **Linux 已有部分补丁**，Windows 的 by-design 行为短期内不会变——对安全敏感的场景，值得把「文件通知监控」纳入威胁建模。

一句话收尾：这篇论文的价值，不是发现了一个「可被修掉的 bug」，而是揭示了一类**结构性侧信道**——操作系统把「文件事件」开放给任意非特权进程，而**文件名、路径与时序本身就构成足够强的信号**，足以从键盘一路还原到你访问的网站。当厂商把这类元数据泄漏称为「设计如此」时，能缓解它的就不是补丁，而是**权限模型和 API 设计**——也就是说，问题被从「运维层」提升到了「操作系统架构层」。
