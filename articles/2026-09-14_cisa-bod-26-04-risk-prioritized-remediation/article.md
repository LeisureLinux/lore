# CISA 发布 BOD 26-04：扔掉 CVSS，漏洞修复改看「四个变量」

2026 年 6 月 10 日，美国 CISA 发布 **Binding Operational Directive 26-04（BOD 26-04）《基于风险优先级的漏洞修复》**。一句话概括它的颠覆性：**联邦民口机构（FCEB）从此不再把 CVSS 严重性评分当作漏洞优先级排序的主要依据，而是改用四个风险变量的组合，给每一条漏洞算出一条「动态修复时钟」——最快三天，且必须做取证分类。**

这份指令同时**取代并废止**了沿用多年的 BOD 19-02（2019，面向互联网可达系统的漏洞修复）和 BOD 22-01（2021，KEV 已知被利用漏洞目录）。它把七年的联邦漏洞修复政策，压进了一个统一的、按风险加权的框架。

## 一、它为什么出现：AI 把攻防窗口压扁了

CISA 在背景陈述里讲得很直白：网络威胁行为者利用**未修补漏洞**发动攻击，而他们用上 AI 之后，「从补丁发布到可能被利用之间，防御者能反应的时间窗口」进一步收窄。旧的玩法——所有漏洞一刀切按严重性排期——已经不够看。

指令的核心理念是：**把修补精力集中到风险最高的地方，而不是对所有漏洞和系统一视同仁**。KEV（已知被利用漏洞）目录只是其中一块拼图，它要的是「威胁行为者能力 × 资产在网络中的位置 × 利用路径的难易 × 利用后的后果」四者合起来给出一张完整的风险图。

指令还回应了各机构和利益相关方的反馈——把优先级排序聚焦到 KEV 目录上；并配合《促进先进人工智能创新与安全》行政令，加速联邦政府信息系统的网络防御。

## 二、四个风险变量：机制的心脏

修复紧迫度（指令表 1 的「修复时间线」）由以下四个变量共同决定：

- **资产暴露（Asset Exposure）**：存在漏洞的资产是否**公网暴露**？即是否能被未经认证 / 不受信任的实体通过公共网络（如互联网）访问，无论其物理或逻辑位置。
- **KEV 状态（KEV Status）**：该漏洞（以 CVE ID 标识）是否在 CISA 的**已知被利用漏洞（KEV）目录**中？
- **利用可自动化（Exploit Automation）**：威胁行为者能否**自动化**利用该漏洞所需的全部步骤？
- **技术影响（Technical Impact）**：利用之后，威胁行为者获得的是对脆弱资产的**部分控制**还是**完全控制**？

其中后三个（KEV 状态、利用可自动化、技术影响），CISA 通过 **Vulnrichment（漏洞数据富化）计划**为每一个 CVE ID 给出答案，直接打进标准 CVE 数据流的 ADP 容器里，机构「免费拿、政府背书」；**只有「资产暴露」这一项，必须由机构自己用资产清单 + CISA 的《互联网暴露削减指南》去判定**。

> 关键定义：**完全控制** = 利用使敌手对软件行为获得完全控制，包括可靠地泄露登录凭据（所以 Heartbleed、Citrixbleed 这类凭据泄露型漏洞，技术影响判为「完全」）。**部分控制** = 只拿到有限控制或有限信息暴露，或仅有「低概率随机获得完全控制」的机会（DoS 属于对行为的有限控制）。

## 三、16 格修复时间表（指令表 1）

四个变量各有「是 / 否」两种取值，共 **16 种组合**，逐一映射到修复时限。下表是完整决策树（「日历日」为限，时间从「CISA 将 CVE 加入 KEV 目录」与「机构在 CDM 仪表盘上于自身资产发现该漏洞」二者中**较早者**起算）：

| 公网暴露 | 在 KEV 中 | 可自动化 | 技术影响 | 修复时限 |
|---|---|---|---|---|
| 是 | 是 | 是 | 完全控制 | **3 天 + 取证分类** |
| 是 | 是 | 是 | 部分控制 | 3 天 |
| 是 | 是 | 否 | 完全控制 | **3 天 + 取证分类** |
| 是 | 是 | 否 | 部分控制 | 14 天 |
| 是 | 否 | 是 | 完全控制 | 3 天 |
| 是 | 否 | 是 | 部分控制 | 14 天 |
| 是 | 否 | 否 | 完全控制 | 14 天 |
| 是 | 否 | 否 | 部分控制 | 60 天 |
| 否 | 是 | 是 | 完全控制 | **3 天 + 取证分类** |
| 否 | 是 | 是 | 部分控制 | 14 天 |
| 否 | 是 | 否 | 完全控制 | 14 天 |
| 否 | 是 | 否 | 部分控制 | 14 天 |
| 否 | 否 | 是 | 完全控制 | 60 天 |
| 否 | 否 | 是 | 部分控制 | 60 天 |
| 否 | 否 | 否 | 完全控制 | **下个系统升级时修** |
| 否 | 否 | 否 | 部分控制 | **下个系统升级时修** |

几条规律值得记住：

1. **取证分类的触发条件很窄但很稳**：只要「在 KEV 中 = 是」且「技术影响 = 完全控制」，无论暴露与否、能否自动化，都进 3 天 + 取证分类这一格（共 4 行）。这是因为 KEV 里能拿到完全控制的漏洞，默认你大概率已经被摸过了。
2. **真正的「头号火情」是四全齐备**（暴露 + KEV + 可自动化 + 完全控制），3 天 + 取证分类。
3. **最低风险组合**（不暴露、不在 KEV、不可自动化）直接「下个系统大版本升级或重建时再修」——这是指令第一次给联邦机构一个名正言顺的「可以拖」的档位。

> ⚠️ 注意：这不是「数有几个勾就排多急」的记分牌，而是**决策树**——组合决定档位，不是数量。同一个 KEV + 完全控制的漏洞，放在暴露资产上是 3 天 + 取证分类，放在非暴露资产上就降到 14 天。这也是为什么「把系统从公网摘下来」是受认可的缓解手段：它不修 bug，但改了时钟。

## 四、分阶段落地要求

指令把落地拆成三个阶段，给机构留了缓冲：

- **Phase I（立即生效）**：修订漏洞管理政策以对齐本指令；持续监控 KEV 目录并按其时限积极消项；通过 CDM 仪表盘**自动上报** KEV 漏洞状态（未完全自动化的机构**每两周手动报一次**）；继续 Cyber Hygiene 扫描；**每季度**对公网暴露的 IP 与域名做 attestation（申报）。
- **Phase II（60 天内）**：把漏洞管理流程升级到能基于「完整 CVE 数据库 + KEV 目录」做修复排序。
- **Phase III（180 天内）**：逐条按表 1 时限修复；**持续给所有互联网可达资产打标签**（组织、环境、暴露面、资产类型）；若未通过 CDM 完全自动化，则**每 7 天**向 CISA 上报一次漏洞状态。

## 五、取证分类（Forensic Triage）：补丁不等于清除

这是 BOD 26-04 比前两代多出的一层。最高档（3 天 + 取证分类）不仅要打补丁，**还要在同样的三天内，对受影响系统做取证分类，判断在打补丁前是不是已经被攻陷**——因为「打补丁通常并不能把威胁行为者赶出去」。

实现指南给了六步法（均为**推荐最佳实践**，指令本身只要求「做了充分的取证分类」，不强制下列精确时限）：

1. **范围界定（KEV 加入后 2 小时内）**：识别是否三日内需修复、是否触发取证；建立**带外通信通道**（不依赖可能已被攻陷的基础设施）。
2. **保全与采集证据（2–24 小时内）**：优先采集易失性数据（内存、缓存、RAM、注册表）；先采证再动系统；建采集日志。
3. **关键补丁与稳定化（2–24 小时内）**：采证完毕后再打关键可用补丁；与内部团队协作稳定关键业务系统。
4. **遏制与控制（6–24 小时内）**：在不惊动威胁行为者（避免其察觉后隐藏/固守访问）的前提下隔离受影响系统；遏制动作须与采证、打补丁协调，过早遏制会毁掉关键证据。
5. **分类分析（24–48 小时内）**：分析证据判断是否已发生入侵。
6. **升级决策**：决定是否上报/升级响应。

## 六、几个容易被忽略的「默认值」与动态性

1. **暴露判定「疑罪从有」**：只要任一手段（CISA Cyber Hygiene、CDM、第三方工具）发现资产可达公网，暴露就判为「是」、走更快时钟。**机构若无法证明某资产「不」暴露，CISA 默认按暴露处理**—— ignorance 会被罚最快时钟。
2. **数据缺失默认 60 天**：当 Vulnrichment 尚未给出某 CVE 的 KEV/可自动化/技术影响时，时限默认落到 60 天档（而非无限期拖）。
3. **时间线是动态的**：事实变了，时钟就变。把系统摘出公网 → 时限放宽；漏洞新进 KEV → 时限收紧。指令明确要求机构持续更新资产可达性标签。
4. **可以更快，不能更慢**：表 1 的时限是「容忍未修复风险的最长上限」。风险容忍度更低的机构可自行设更短时限。
5. **适用范围**：仅限 FCEB（联邦民口行政分支）机构；**不适用于**法定「国家安全系统」、战争部（Department of War）与情报界相关系统。承包商除非合同另有约定，默认不受约束，但 FCEB 机构须审查合同以落实要求。FedRAMP 认证的云通过 FedRAMP PMO 落实；非认证云由机构直连 CSP 落实并文档化偏差。
6. **CVSS 去强制化**：废止 BOD 19-02 的直接后果，就是 FCEB **不再被强制用 CVSS 做优先级排序**。指令仍与 FIRST CVSS SIG 的消费者实施指南对齐——成熟做法是用 CVSS 消费者指南里的技术/威胁/环境信息去辅助决策，但 CVSS 不再是那个「一票决定排期」的分数。

## 七、解读：这事儿对我们有什么启示

**1. 这是 SSVC 第一次被写进联邦强制令，而且是「可操作版」。** 四个变量本质上就是 **Stakeholder-Specific Vulnerability Categorization（SSVC）** 的方法论落地：不靠一个静态分数，而靠「暴露 × 被利用证据 × 自动化成熟度 × 控制后果」的组合决策。过去十年安全圈喊「别迷信 CVSS」喊了很久，CISA 这次是真把它从建议变成了合规。对国内做漏洞管理的人，这是一次明确的风向标：**打分时代正在让位于「能不能被打、打到了能怎样」的实战视角**。

**2. 它骨子里是一条「资产管理令」，只是外面套了补丁的壳。** 四问里三问 CISA 免费喂数据，唯一要机构自己答的「资产暴露」，本质是资产清单的功力。指令反复强调持续给互联网可达资产打标签、每季度申报暴露面——说白了，连不上资产台账，这套 16 格决策树你连第一格都填不动。对信创 / 关基运营方同理：**暴露面测绘（互联网可达性）才是风险优先级的地基**，没有它，再漂亮的风险模型都是空中楼阁。

**3. 给「可拖」一个合法名分，是对 patch fatigue 的诚实回应。** 旧指令所有 KEV 一视同仁当火灾，结果是工程人力被卷进「三网段深处、气隙后面、CVSS 全是 critical」的无底洞，和真正的互联网预认证 RCE 抢同一拨人。BOD 26-04 第一次承认：真低风险的，可以等到下个大版本升级再修。这个「可以拖」的档位，反而让「必须三天」的档位更有说服力。国内关基的漏洞考核如果还停留在「发现即计时、清零才算完」，不妨参考这种分级——把稀缺的人力压到真正可达、可自动化、能拿完全控制的那一格。

**4. AI 压缩攻防窗口，是这份指令真正的导火索。** CISA 把「威胁行为者用 AI 缩短武器化时间」写进了背景，所以才要把最高档压到 3 天还附带取证。对做安全运营的人，这意味着 SoC/漏洞响应要开始默认「小时级」节奏，而不是「周级」排期。顺便一提背景里那组数据：据 2026 Verizon DBIR，2025 年 KEV 漏洞**完全修复率仅 26%**（前一年还 38%）——修复率在掉，窗口在缩，这纸指令就是冲着这个剪刀差去的。

一句话收尾：BOD 26-04 把「按分数排期」的旧世界正式关了灯，打开灯后你会发现——**真正该先修的漏洞，从来不是分数最高的那个，而是最能被摸到、最能自动化、最能一击拿权的那一个。**
