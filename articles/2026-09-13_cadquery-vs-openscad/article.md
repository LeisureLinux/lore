# CadQuery vs OpenSCAD：让 AI 生成功能零件，谁更能打？

ModelRift 平台一直用 OpenSCAD 做代码优先 CAD。为了验证这个选择是否还站得住，他们做了一次受控对比：让 **6 个 AI agent、用同一款模型（Claude Opus 5，1M 上下文，走 Claude Code）**，分别用 CadQuery（Python + OpenCascade B-rep 内核）和 OpenSCAD 建模 3 个可打印零件，然后**独立解析每一个 STL 网格**——不信工具自己报的状态。

问题问得很窄：**在没人盯着的情况下，哪个工具能被 AI agent 开到「正确、可打印、功能性」的零件？** 手写爽不爽不在考察范围。

结果：6 个零件全部可打印，两边都交了卷。**能力是最无聊的部分——真正的分野在于它们怎么失败。**

## 一、测试设置

- 每格一个独立 subagent，同模型无串扰；版本 CadQuery 2.8.0（Python 3.14）、OpenSCAD 2026.06.12，都在 M 系 Mac 上
- OpenSCAD 侧用他们自家的 openscad-skill（文件/版本命名、render-inspect-fix QA 环、CLI 预览相机预设、剖面调试、Customizer 语法）
- CadQuery 侧逐操作移植同一个 skill；因 CadQuery 无 CLI 渲染器，补写了一个离屏渲染器，用 B-rep 有效性指标替代 CSG 状态行
- 两边拿同一套 3D 打印设计规则（壁厚、间隙、悬垂），skill 体量 12.4 KB vs 13.1 KB
- 每个 agent 最多 12 个版本、不许假装成功、失败必须原样报错文本，全程无人值守
- **最终 STL 全部过独立解析器**：三角形数、包围盒、体积、水密性、非流形边、翻转面、连通分量

## 二、三个任务

- **T1（简单）**：壁挂 L 形托架——两块 90° 板、4 个三角筋、两个沉头孔、两个普通孔、外角 R3、内角 R4 圆角，免支撑打印
- **T2（中等）**：50×26 PCB 的两件式卡扣外壳——壁厚 2、单边间隙 0.4、四个 M2 柱、USB-C 开口 9.5×3.5、带 0.2 间隙外唇的盖子、可用的卡扣、五个散热槽，**两件必须真能装配**
- **T3（最难）**：M24×2 螺纹软管倒刺转接头——30 对边六方法兰、12 长真螺旋螺纹、25 长倒刺段（三个倒刺，配 12 内径软管）、8 通孔。**规范明确禁止叠环冒充螺纹，必须是真螺旋几何**

## 三、逐任务战报

### T1：简单托架

OpenSCAD **首次编译即正确**，2 个版本搞定。CadQuery 在一个错误上耗了约三分之一的时间：`.fillet(3.0)` 报 `BRep_API: command not done`——**既不说是哪条边也不说是哪个半径**。agent 只能手二分排查，最后发现是算术问题：**两个 R3 圆角塞不进 4mm 墙**。

这暴露了一个深层差异：OpenSCAD 圆的是 2D 轮廓再拉伸，不关心实体怎么拼的；CadQuery 得**先给四条边命名**——而命名是最难的部分（`edges("|Z")` + BoxSelector 一长串）。

### T2：两件必须装配

这是 CadQuery **参数链**的高光时刻：改一个唇深，沿口、板、槽、沟槽、倒刺全部联动，因为每个尺寸是派生的而不是敲两遍。OpenSCAD 这边 8 个版本 vs CadQuery 5 个，且 8 个里有 3 个花在布尔卫生上（清理相切/共面甩出来的碎屑）。

更有意思的是**装配校验方式**：OpenSCAD 打印数字等人来读（`echo`），CadQuery 直接断言、断言失败构建就停（`assert box.intersect(lid).Volume() < 1e-6`）。**对无人值守生成来说，这个差距就是全部故事。**

### T3：真螺旋螺纹（最大冷门）

OpenSCAD **一个版本、首次编译正确、43 毫秒、零库依赖**。因为没有 sweep 操作，agent 直接写了裸顶点/面算术：ISO 四点齿形轮廓、每圈 96 段、单个 `polyhedron` 输出——**没有任何护栏，绕序错了工具一声不吭**。它还提前预判了经典螺纹陷阱（ISO 齿形恰好跨一个螺距，相邻根平面共面导致 union 变质），把扫掠轮廓沉到小径以下让螺旋穿过芯柱而非相切。

CadQuery 同样的几何只有 6 行可读代码，这部分一次过。但**最后一行 `union()` 静默丢掉了芯柱**——因为螺纹根恰好落在芯柱半径上，沿螺旋线的**精确相切让 OCCT 无声地丢了一个实体**。从外面看零件完美，agent 读了 4 张渲染图都没发现。**抓住它的是体积测量：7065 mm³，预期 10323。**

更糟：坏零件自报 `valid=True`、`solids=1`；把布尔容差放宽到 1e-3，得到一个**负体积**的实体，照样 `valid=True`。

OpenSCAD 也不干净：T2 里它的 Manifold 后端对一个带 **4 条非流形边 + 60 个零面积三角形**的 STL 报了 `Status: NoError`。**两个工具的自我报告都不能当最终裁决**——所以他们才自己解析每个网格。

## 四、核心发现

1. **渲染图什么都没抓到。** 视觉反馈适合「大形、比例、柱子放错位置」；对壁厚、间隙、布尔悄悄删了你半个零件这种事，视觉是错的工具——**那需要数字，而且必须逼 agent 去看**。
2. **OpenSCAD 渲染没有「零件边」的概念。** CSG 之后只剩三角形汤，`--view=edges` 画的是三角剖分不是轮廓；CadQuery 的 B-rep 知道两面在哪相交。这是 agent 反馈通道上的真实不对称（他们后来从 STL 重建特征边轮廓来修）。
3. **可验证性 > 表达力。** 能问内核「我刚建了什么」并对答案断言，在 agent 循环里比任何顺手的语法都值钱。这是 CadQuery 领先的维度，且差距比语法差异更大。
4. **任务形状比工具更决定成败。** 简单棱柱活归 OpenSCAD；必须配对的两件归 CadQuery；看起来为 B-rep 内核量身定做的螺旋螺纹，**被 OpenSCAD 干净利落地拿下了**。

## 五、ModelRift 的决定

**留在 OpenSCAD。** 理由没变：LLM 能直接写的紧凑文本格式、安全沙箱（WASM）、16ms 渲染。CadQuery 的优势真实存在但**主要在验证环节——而验证可以加在 OpenSCAD 外面**；它的劣势对 ModelRift 是结构性的：每会话一个 Python 运行时而不是 WASM 沙箱、两秒级重建而不是 16ms、没有干净的多对象多色导出。

两个改动已经回流到公开的 OpenSCAD skill：**特征边渲染器**（预览带真实零件轮廓而非三角剖分）+ **数字检查关卡**（agent 必须跑完壁厚/间隙/干涉体积/网格审计才能宣布模型完成——不问工具自己干得好不好）。

## 我的解读

这篇的实验设计值得所有做「AI 生成 + 物理输出」管线的人抄作业。

**第一，独立验证器是整篇文章的主角。** 六个 agent、两套工具、十几个版本迭代里，真正抓到致命 bug 的从来不是渲染图，也不是工具自报状态，而是那个「谁都不信」的 STL 解析器——三角形数、体积、水密性、非流形边。`valid=True` 配上 7065 vs 10323 mm³ 的体积差，这就是全部证据。**教训通用：任何「生成→验证」管线，验证器必须与生成器异构**——同源验证等于没验证。CAD 如此，代码生成（编译通过 ≠ 逻辑对）如此，SQL 生成（执行成功 ≠ 查的是对的表）也如此。

**第二，精确相切是 B-rep 内核的暗礁。** 「螺纹根恰好落在芯柱半径上 → union() 静默丢实体」这个 bug 模式，所有用 OCCT 的工具（FreeCAD、CadQuery、pythonocc）用户都可能撞上。规避手法值得记：**让扫掠几何穿过基体而非相切**（沉到小径以下），把「数学上恰好接触」变成「明确重叠」。这条对任何做布尔运算的人都是保命知识。

**第三，「数字断言 > 截图评审」这个结论超出了 CAD 范围。** Agent 工作流里最常见的反模式就是让 agent 自己看自己的输出说「看起来没问题」。ModelRift 的数据点是：4 张渲染图全没发现半个零件没了，一个 `assert volume == expected` 立刻爆炸。**给 agent 的反馈通道，能量化的必须量化**——壁厚、间隙、干涉体积、悬垂角、体积、连通分量数。凡是能写 assert 的，别让 agent 靠眼睛。

**第四，「任务形状决定工具」比「工具排名」有用。** 榜单思维会让人记住「X 赢了」；但这篇的真正贡献是那张失败模式对照：简单棱柱（OpenSCAD 快）vs 参数联动（CadQuery 派生链）vs 螺旋（OpenSCAD 裸算术反而赢）。**选型时先问「我的失败面在哪」，再选对应工具**——这比看任何 benchmark 总分都靠谱。

一句话收尾：**表达力决定上限，可验证性决定下限——而 agent 管线里活下来的从来是下限高的那个。**
