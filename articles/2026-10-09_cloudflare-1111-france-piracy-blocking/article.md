> 原文：[Cloudflare Keeps 1.1.1.1 Out of Piracy Blocking, Escapes Penalties in France](https://torrentfreak.com/cloudflare-keeps-1-1-1-1-out-of-piracy-blocking-escapes-penalties-in-france/)（TorrentFreak，2026-10-08，作者 Ernesto Van der Sar）
> 判决书原文：[F1 案（RG 26/08243）](https://torrentfreak.com/images/tribunal-judiciaire_n%C2%B02608243_17_09_2026.pdf)、[MotoGP 案（RG 26/08228）](https://torrentfreak.com/images/tribunal-judiciaire_n%C2%B02608228_17_09_2026.pdf)
> 本文为**译文 + 解读**。第四节的时间线与法国行政法院判决是笔者补充的背景，已标注为本文补充。

## 一句话结论

Canal+ 要求巴黎法院对 Cloudflare 处以**每个站点每天 5 万欧元**的罚款，理由是它只通过 CDN 封禁、**根本没动 1.1.1.1 公共 DNS**。九月十七日，三名法官组成的合议庭**驳回了罚款请求**，理由是四月那份封禁令本来就**「不指定手段、只要求有效」**，而 Cloudflare 通过 CDN 封禁构成了「合理措施」。**但这个判决比它看起来窄得多**：它确认的是「你有权选择用什么手段」，而不是「DNS 解析器可以豁免封禁义务」。同一个月、同一个法庭、同一套法律框架下，**没有任何 CDN 可退守的 Quad9 正面临最高每天 58 万欧元的罚款，并表示可能直接退出法国**。

## 一、案件：一份不指定手段的封禁令

背景不复杂。过去两年，法国法院把封禁义务的对象从 ISP 一路扩展下去：**常规 ISP 之外，现在还包括公共 DNS 解析器、VPN 服务、搜索引擎和 CDN 提供商**。理由都一样，这些都是能帮用户绕过既有封锁的环节。

Cloudflare 收到了几份这样的命令。**2026 年 4 月，巴黎司法法院命令它封锁 21 个与盗版 F1 直播相关的域名和 16 个 MotoGP 相关域名。**

关键细节在这里：

> **命令覆盖了 Cloudflare 的 DNS 解析器和它的 CDN。但命令没有规定该怎么封锁，只要求「以防止从法国访问」。**

原文对措辞的表述是「by any effective means」（以任何有效手段）。

申请封锁的法国付费电视提供商 **Canal+ 认为 Cloudflare 做得不够**。于是它回到法院，**在五月要求追加每日罚款**：每个仍然可访问的站点每天 **5 万欧元**，媒体监管机构 ARCOM 每上报一个新的站点，同样金额。

Canal+ 的主张是 Cloudflare **故意不遵守**封禁令。按判决书的概述（译自法文）：

> Cloudflare 被指「通过仅在其 CDN 服务上实施该判决来规避措施，这意味着法院列出的 21 个域名中只有三个被封锁」。

MotoGP 案的情况类似，Canal+ 统计的是**16 个里封了 3 个**。两个案子它还都补了一句：**被封的三个站点里有两个一周后重新上线，一个换了 CDN，另一个用了镜像站。**

## 二、法院为什么判 Cloudflare 赢

九月十七日，三名法官组成的合议庭对两份罚款请求一并作出裁定。Cloudflare 的答辩有两条：

1. **技术约束**使得它只能通过 CDN 履行；
2. **法院明确让它自行选择使用哪些服务**，只要它对打击体育盗版有实质性贡献。

法院先确认了实施方式这个事实，没有争议：

> Cloudflare 仅在站点使用其 CDN 服务时，通过该服务实施所命令的措施，这一点没有争议。

然后关键的一步来了。Cloudflare 告诉法院，**CDN 封禁比 DNS 封禁有效得多**，并补充说**其公共 DNS 解析器的架构不允许进行封锁，因此这类措施是不合理的**。

法院接受了这个立场。而这里有一个反直觉的转折：

> **Canal+ 曾主张 Cloudflare 只封锁了法院要求它封锁的域名中的 72.6%。但法院把这个数字视为「有诚意协助制止侵权」的证据。**

**判决书没有解释这个百分比与 Canal+ 先前所说的「21 个里只封了 3 个」之间是什么关系。** 这个不一致值得单独拿出来说，见下一节。

法院还划了一条责任边界：**站点换成另一个 CDN、或者设置跳转到镜像站，不能归咎于 Cloudflare。**

> 当相关站点的所有者切换到另一个 CDN 或设置重定向到镜像站点时，Cloudflare 不能被追究责任。

**那该谁负责？** 法院说，该由 **Canal+ 去要求新的中间商封锁这些站点，并把镜像站上报给 ARCOM**。

最后是 Canal+ 援引的欧盟法院先例。它主张按 **UPC Telekabel Wien** 判决，中间商必须**有效**封锁。巴黎法院不同意这个读法：**在它看来，同一份判决只要求中间商采取「合理措施」（reasonable measures），而 Cloudflare 通过 CDN 封禁做到了这一点。**

**结果：罚款请求被驳回，理由是「既不必要也不相称」。Canal+ 另外要求的 2 万欧元诉讼费用也被驳回。**

## 三、那个没被解释的 72.6%

这是判决里最值得追问的地方，我想单独讲，因为它决定了这个先例的适用范围。

**同一份判决里同时出现了两个关于「封了多少」的数字**：

| 数字 | 来源 | 含义 |
|---|---|---|
| **21 个里封了 3 个**（MotoGP 是 16 个里 3 个） | Canal+ 的指控 | 法院列出的域名里，实际生效的比例极低 |
| **72.6%** | Canal+ 自己的统计 | Cloudflare 封锁了它被要求封锁的域名的 72.6% |

**这两个数字差了二十多倍，而判决书没有说明它们如何共存。** 原文直接点出了这一点（「判决没有解释这个百分比与 Canal+ 先前所述 21 个域中 3 个被封锁之间有何关联」）。

**最可能的解释**（这一句是本文的推断，判决书未给出）是两者统计的分母不同：**72.6% 的分母可能是 Cloudflare 实际提供 CDN 服务的域名集合，而 3/21 指的是那 21 个域名里通过 CDN 路径仍然能从法国访问的数量。** 如果这个推断成立，那么「72.6%」实际上说的是「在我们能封的范围内，我们做了七成以上」，而「3/21」说的是「法院那张清单的整体拦截效果很差」。

**为什么这件事重要**：如果法院是在「Cloudflare 已经尽力」这个前提下判它免罚的，那么**这个前提本身建立在一个未经解释的数字上**。而这个数字恰好是 Canal+ 自己提供的。TorrentFreak 用的措辞很谨慎：「有趣的是，法院的结论依赖于 Canal+ 自己提供的统计数据。」

## 四、真正的不对称：Quad9 没有 CDN 可以退

这才是这个判决最该被读出来的部分。原文在结尾把对比摆了出来：

> 非营利 DNS 解析器 **Quad9** 面临来自 **beIN Sports** 的类似、且可能致其破产的罚款请求，理由是它没有在自己的 DNS 解析器上封锁盗版内容。**巴黎法院会如何看待这件事，本月晚些时候就会清楚。**

**把两个案子并排放：**

| | Cloudflare（1.1.1.1） | Quad9 |
|---|---|---|
| 是否封锁其 DNS 解析器 | **没有** | **没有** |
| 是否有其他可封锁的服务 | **有，CDN** | **没有** |
| 法院结论 | **驳回罚款请求** | **结果待定（本月）** |
| 罚款规模 | 请求 5 万欧元/站点/天 | 最高 **58 万欧元/天** |
| 态度 | 通过 CDN 履行 | **公开拒绝，并表示可能退出法国** |

**同一套法律框架、同一个法庭、同一个核心事实（都没封自己的 DNS 解析器），但结果可能完全不同。差别只在于一方恰好还经营着一项更容易封锁的业务。**

**这就是这个先例的真实边界**：它不是「DNS 解析器不必封禁」，而是「**如果你有一个更有效的替代手段，法院可以接受你用那个替代手段**」。对没有第二项业务的纯解析器来说，这个判决提供不了任何保护。

**顺带说一下这套封禁体系在法国是怎么一步步铺开的**（以下为本文补充，来源为 Canal+ 官方新闻稿、TorrentFreak 与法国行政法院判决）：

| 时间 | 进展 |
|---|---|
| 2022 | 巴黎法院首次判令 **ISP** 封锁盗版流媒体站点 |
| 2024 | 扩展到**替代 DNS 解析器**（Quad9、Vercara 等） |
| 2025 年 5 月 | 判令 **5 家 VPN** 封锁 203 个域名，被称为司法先例 |
| 2026 年 3 月 27 日 | **巴黎上诉法院**驳回 Google Public DNS、Cloudflare、Cisco OpenDNS 的上诉（一次五案），**首次在法国上诉层面确认 DNS 封锁**，依据是《体育法典》第 L.333-10 条 |
| 2026 年 4 月 | 巴黎司法法院判令 Cloudflare 封锁 F1 与 MotoGP 域名 |
| 2026 年 7 月 15 日 | **法国行政法院（Conseil d'État）** 判决（第 509579 号）：ARCOM 有权强制 **Cloudflare** 封锁基于欧盟制裁的俄罗斯媒体地址，驳回了 Cloudflare 的撤销请求，并**拒绝将 DSA 第 9 条的解释问题提交欧盟法院**，理由是「不存在严重的解释困难」 |
| 2026 年 9 月 17 日 | 本篇判决：驳回 Canal+ 对 Cloudflare 的罚款请求 |
| 2026 年 10 月（待定） | **Quad9 案结果** |
| 已在进行 | Canal+ 称正在逐步部署包括 **IP 封锁**在内的更多措施 |

**3 月那次上诉法院判决里，法院驳回的几个论证方式也值得记下来，因为它们以后还会被反复引用**：

- Cloudflare 和 Cisco 主张自己的服务是「中立且被动的」功能，像一本把域名翻译成 IP 的通讯录。**法院认为这个中立性根本不是重点：重要的是「技术上有能力封锁」，而不是服务的性质。**
- Google 换了个角度，主张 DNS 封锁无效，因为一个 VPN 就能绕过。**法院驳回的理由是：任何过滤系统都能被绕过，但这不代表它没用。**
- Cisco 提出实施成本是 64 人周。**这也未能说服法官。**

**这三条驳回理由与 9 月判决并不矛盾**，因为 9 月裁的是「要不要罚款」，而不是「要不要封」。**义务本身没被推翻，被推翻的只是「你必须用 DNS 这个特定手段」这个隐含要求。**

## 五、Cloudflare 提的替代方案，恰好和欧洲监管的方向一致

Cloudflare 在给欧盟委员会「假冒与盗版观察名单」（Counterfeit and Piracy Watch List）磋商的意见书里说明了它的立场：**全球公共 DNS 解析器不应被用来封锁或限制访问**。

同时它提出了自己认为更好的做法：**一个实时的盗版流媒体中断机制**。经审核的权利人可以标记流经其网络的盗版流，这些流会**「在数秒内」被中断，而不需要任何 DNS 或 IP 地址封锁**。它的原话是：

> 对于直播内容，速度至关重要，Cloudflare 已经建立了实时缓解机制，允许经过审核的权利人合作伙伴标记侵权的流。当这些流经过我们的网络时，我们会在数秒内对其采取行动。

**这个思路与 DNS 封锁有本质区别，值得单独指出：**

| | DNS/域名封锁 | 实时流中断 |
|---|---|---|
| 作用对象 | **名字**（域名、IP） | **内容流** |
| 生效方式 | 静态清单，提前配置 | 实时检测，秒级 |
| 误伤面 | 可能连带封掉共享 IP 或整个 CDN 边缘 | 针对具体流 |
| 绕过成本 | 换域名、换 CDN、镜像 | 需换传输路径 |
| 跨域效果 | 只在封禁国生效（但 DNS 封锁常外溢） | 在流经的网络内生效 |

**有意思的是欧盟自己的研究也指向同一个方向**：一项受欧盟委托的研究指出反盗版「不够有效」，**目标应该是「30 分钟内实时封锁」**。也就是说，监管方和平台方对「更快、更精准」的方向判断是一致的，分歧在于**该不该把 DNS 解析器当成执行点**。

## 六、对从业者意味着什么

**如果你运营 DNS 解析器或任何基础设施服务**，这个判决给出的最实际的信息是**业务形态决定了你的法律风险敞口**：

- **只有一项业务的服务最脆弱**。Quad9 的处境说明，一个纯粹的非营利解析器，在同样的事实基础上可能面临致其破产的罚款，而拥有 CDN 的对手可以主张「我用别的手段更有效」并因此免罚。**这不是法律原则的差别，是架构的差别**；
- **「不指定手段」的措辞是你的朋友**。Cloudflare 能赢的关键前提是四月那份命令让它自行选择服务。如果命令明确指定「通过你的解析器封锁」，这个先例就不适用；
- **注意行政法院和司法法院是两条线，结论可能相反**。七月那份行政法院判决里，Cloudflare 是**输**的：ARCOM 有权强制它封锁，且法院同样提到「Cloudflare 保留对如何实施的裁量权」，但结论是**必须履行**。同一家公司，两条轨道，两种结果，**不要用这一份判决推断另一条轨道的走向**。

**如果你关心 DNS 隐私与加密 DNS 的争论**，这里有一条很具体的观察：Cloudflare 的透明度报告是一个难得的窗口，能看出**封锁实际发生在哪一层**：

| 期间 | CDN 层面在法国地理封锁的域名数 | 依据的命令数 |
|---|---|---|
| 2025 上半年 | **662** 个 | **7** 份命令 |
| 2025 下半年 | **1,238** 个 | **1** 份命令 |

**封锁量集中在一份大规模命令上**，而不是分散在很多小案子。同时，Cloudflare 在报告里反复声明：

> 截至目前，Cloudflare 尚未通过 1.1.1.1 公共 DNS 解析器封锁任何内容。

**这句话本身就是这个案子里最有争议的事实**：法院判了它封锁 DNS 解析器（命令覆盖了解析器），但公共解析器至今未封，而且这次没被罚款。

**如果你在关注这类监管的长期走向**，值得留意的还有两点：一是 **Canal+ 明确表示可以上诉**，所以这不是终局；二是这套体系正在**继续向下一层扩展**，Canal+ 的官方说法是「包括 IP 封锁在内的额外措施正在逐步部署」，并提到已在罗兰·加洛斯期间做了首次试验。**从 ISP 到 DNS 到 VPN 到 CDN 再到 IP，这是一条把可执行点逐层填满的路径。**

## 七、我的判断

**第一，「Cloudflare 赢了」这个框架有误导性。** 它赢的是一份不指定手段的命令，而不是「DNS 解析器免于封禁义务」这个原则。判决书里甚至明确承认「命令覆盖了解析器和 CDN」，只是没规定用哪个。**同样的法院、同样的事实，如果命令换一种写法，结果可能反过来。**

**第二，也是我认为最值得警惕的一点：这个案子的结果取决于被告有没有第二项业务。** Cloudflare 因为拥有 CDN 而可以主张「我用更有效的方式履行了」，Quad9 因为没有 CDN 而只能拒绝或者离开。**用一个与合规义务无关的商业事实，去决定一个法律义务的履行方式和后果，这在制度设计上是有问题的。** 原文把这个对比留在了结尾，但它其实是全篇分量最重的一段。

**第三，那个 72.6% 值得被追问。** 法院用「Canal+ 自己提供的统计」证明了 Cloudflare 有诚意，而这个统计与 Canal+ 自己另一处「21 个里封了 3 个」的指控之间，判决书没有给出任何调和。**一份判定的关键前提建立在一个未经解释的数字上，这是可以上诉的实质理由。**

**第四，从更长的时间尺度看，DNS 封锁这条路正在被技术现实和市场结构同时消解。** 一方面它效果有限（换域名、换 CDN、镜像站都能绕过，法院自己也承认任何过滤都能被绕过）；另一方面**加密 DNS、DoH/DoT 的普及**让解析器层面的干预越来越难以在终端生效。**Cloudflare 提出的「秒级中断盗版流」之所以更可能成为长期方案，不是因为它对平台更有利，而是因为它同时满足了「更快」和「更精准」这两个监管方自己提出的目标。** 而这，恰好是那个「30 分钟内实时封锁」的欧盟研究结论所指向的方向。

| ⚠️ 未解释之处 | Canal+ 称 21 个里只封了 3 个，另一处又给出 **72.6%** 的封锁率，判决书未说明两者关系 |
| 1.1.1.1 现状 | **仍未封锁任何内容**；Cloudflare 透明度报告明确声明这一点 |
| CDN 封锁量 | 2025 上半年 662 个域名（7 份命令）；下半年 **1,238 个域名（1 份命令）** |
| ⚠️ Quad9 对比 | 同样未封 DNS，但**没有 CDN 可退守**；面临最高 **58 万欧元/天**罚款，**结果待定（本月）** |
| Cloudflare 的替代方案 | 实时流中断：经审核权利人标记盗版流，**数秒内**中断，不做 DNS/IP 封锁 |
| 后续 | Canal+ 可上诉；IP 封锁已在罗兰·加洛斯期间做过首次试验 |
